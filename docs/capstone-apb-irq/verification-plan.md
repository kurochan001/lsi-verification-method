# APB＋割り込みの検証計画：記入済み例

対象仕様は[r1のAPB＋割り込み](../../examples/local-apb-irq/README.md)と、[r1／r2の変更要求](../../examples/local-spec-change/spec.md)です。以下のCAP IDはこの演習用の対応表で、元の要求カタログのIDを変更するものではありません。

| 要求 | 刺激・成立条件 | 期待値と観測 | 実行例・判定 |
| --- | --- | --- | --- |
| CAP01：リセット | 状態・IRQを保持中に同期リセットを取り込む | CONFIG・PENDING=0、IRQ解除、解除後に再動作 | APBの全サイクル比較、`APB_RESET_RESPONSE`、SVAの次状態と`cp_reset` |
| CAP02：マスクと保持 | クリアなしで各要因をマスク中に発生させ、後で許可する | マスク中もPENDING=1、許可後IRQ=1 | `APB_IRQ_PENDING`・`APB_IRQ_OUTPUT`、クロスとnative cover |
| CAP03：通常更新 | イベントだけ、W1Cだけ、両方なしを各ビットで作る | セット、クリア、保持。W1Cは正常完了時だけ有効 | bitごとの独立モデル、SVAの次状態、TRACE |
| CAP04：競合優先 | 各ビットでPENDING=1、マスク0／1、同時イベント＋W1C | r1は1、r2は0。受理後の状態とIRQを確認 | `TI-R1`／`TI-R2`、各waitの8目標、古い期待値・SVAの診断 |
| CAP05：IRQ | 複数要因を保持し、一部・最後の要因をクリアする | IRQはPENDINGとCONFIG下位4ビットのANDのOR | `APB_IRQ_OUTPUT`・`APB_IRQ_RELEASE`、`ap_irq` |
| CAP06：応答・副作用 | 未割当・禁止書込み、SETUP・wait・完了を作る | 規定のready／error。拒否されたアクセスの副作用を起こさず、独立したイベントの更新は継続する | `APB_READY`・`APB_ERROR_RESPONSE`・`APB_ERROR_SIDE_EFFECT` |
| CAP07：読出し時点 | 読出しとイベント・クリアの前後を作る | 完了エッジの更新前のレジスタ値を返す | `APB_READ_DATA`と全サイクルの独立モデル |
| CAP08：時間関係 | 正常W1Cに対してイベントを−1／0／＋1へ配置する | 同じ時間窓の状態・IRQを最後まで比較する | クロス例の要因別・構成別temporal目標、TRACEと確認済み行 |

## 構成・目標・完了条件

- 機能比較：wait=0／1／3、4要因、マスク0／1。境界、固定seedのランダム、既存の異常系・変異検出を保持する。
- r1クロス：既存44／45目標に加え、pairwise 96、priority 32、temporal 48を各waitで要求する。full4 64は診断の扱いを維持する。
- 変更要求の機械照合：r1／r2それぞれに、4要因×マスク2水準の8競合目標を、全3waitで要求する。異なる構成や失敗したケースの到達を持ち寄らない。
- ネイティブSVA：wait=1で両版の次状態・IRQを検査し、7 coverをDBとaction件数で照合する。無効化を検出する。
- 行カバレッジ：各版のwait=1・レジスタRTLだけを計測し、分母・ヒット・未達を保存する。追加時smokeは各7／7カウンターだが、他の指標・構成・ラッパーの網羅を意味しない。
- 完了：予定結果とJUnit、source／planの版、比較件数、必須到達、診断の検出を確認する。未実行、未達、仕様課題を残したまま合格へ変更しない。

## r2への変更の影響

CAP04の期待値、CAP03の競合時の次状態、CAP05でIRQが解除される条件、CAP08の時間窓の結果を再評価します。受理エッジ、マスク、リセット、エラーの契約自体を変更していなくても、操作列の到達や変異の期待結果が変わる可能性があります。

`local-spec-change`は変更要求を再検証します。元のクロスモデルと全カタログをr2へ展開する判断は演習の残課題です。元のr1を前提とした期待値のまま、r2の達成率を合格扱いにはしません。
