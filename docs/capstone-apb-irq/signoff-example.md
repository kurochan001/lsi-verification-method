# APB＋割り込み：サインオフ記入例

これは[汎用の雛形](../templates/signoff-record.md)を教材へ適用した記入例です。実際の実行記録は[追加時の確認](../../PROVENANCE.md#workflow-capstone-and-composition-20261101)を参照してください。人が承認した製品サインオフではありません。

## 対象と採用する証跡

- 対象：教材APB＋割り込み、4要因、単一クロック・同期リセット、wait=0／1／3。
- 仕様：r1セット優先。変更演習のr2はクリア優先。出典は実行例のREADME・`spec.md`、要求と構成は[検証計画](verification-plan.md)。
- ソースの版：各`manifest.json`のSHA-256。実際の入力・比較・ログ・波形・DBも保持する。
- 実行ID：個別例と統合実行の出力先。採用先と全試行は`regression_report.py`のJSON・HTMLから照合する。
- 判定方法：ランナー・独立モデル・SVA・カバレッジ・診断の自動確認と、AIによるレビュー。人の承認欄は未承認。

| 確認項目 | r1での記入 | r2での記入 |
| --- | --- | --- |
| 受理・応答・状態・IRQ | 成功。元の全構成・境界・ランダム・変異を確認済み。 | 成功。同じ保存入力で更新した期待値と全3waitを比較済み。 |
| 機能クロス | 成功。元の必須目標と実観測による追加選択を確認済み。 | 保留。全カタログ・クロスモデルの改訂判断が残る。 |
| 変更要求 | 成功。8競合目標×全3waitを機械照合済み。 | 成功。別IDで同じ目標と、古い期待値の検出を確認済み。 |
| SVA | 成功。wait=1、次状態・IRQと7 coverを確認済み。 | 成功。改訂した真理値表と7 coverを確認済み。 |
| 行カバレッジ | wait=1のレジスタRTLは7／7カウンター到達、未達0。 | 別ビルド・別DBで7／7カウンター到達、未達0。 |
| 初回失敗・再実行 | 採用結果と入力SHA-256を照合済み。元の失敗も保持。 | 同じ方針。r1の成功をr2へ流用していない。 |
| 自動確認後の判断 | 計画した教材の限定範囲は確認済み。人の承認は未承認。 | 変更要求は確認済み。全体サインオフは保留。 |
| 人の承認 | 承認者・承認日：未承認 | 承認者・承認日：未承認 |

## 残る確認と判断

行カバレッジはレジスタRTLのwait=1だけです。IRQラッパー全体、全waitのコード網羅、4値のX伝搬、CDC/RDC、電源、物理タイミング、製品の権限・安全要件は、この演習の完了範囲へ含めません。製品に適用するときは[適用範囲](../templates/verification-scope.md)で必要性を判断して追加します。

**r2の全体サインオフは保留**とします。変更要求2項目の機械照合が成功しても、元の全カタログ・クロスモデルの改訂、期待結果・変異の再評価、人の承認が残っているためです。残課題を適用外へ移して完了率を上げません。

演習では、残課題の担当者・期限・再実行する項目を記入し、証跡がそろった後に判断を更新してください。
