- 2026-10-24の再検討（保留継続）: 解消案（自動ビンの網羅率の分母は、19.5.3 で作成された自動ビンの数 N とする（値を持たないビンは B008 により除外）。MIN(auto_bin_max, 2**M) は enum 以外の整数 coverpoint についての N を表す式と読み、enum の coverpoint では列挙値の個数を分母とする。列挙値の個数が auto_bin_max を超える場合の扱いはこの判断に含めない。）を検討しましたが、検証で根拠が決定的でないとされたため保留を続けます。理由: 中核の推論は正しい。19.8 B012 によれば、coverpoint に対する get_inst_coverage の第2引数は「定義されたビン数」で、そのまま分母になる。19.5.3 B003 は enum のビン数 N を列挙値の個数としている。したがって 19.11.1 B006 の MIN(auto_bin_max, 2**M) は、enum 以外についての N を表す式と読める。差し戻すのは書き直しが判断の範囲を越えているためである。adopted_interpretation は「列挙値の個数が auto_bin_max を超える場合（19.5.3 B003 と表19-1 B012 の緊張）はこの判断に含めない」と明記している。ところが behavior と review_note は、enum の分母を無条件に列挙値の個数と書いている。たとえば列挙値が100個で auto_bin_max が既定の64のとき、behavior は total=100 を要求することになり、未決とした点を黙って決めてしまう。直すには、behavior と review_note を「19.5.3 で実際に作成された自動ビンの数」に留めるか、列挙値の個数が auto_bin_max 以下の場合に限定する。あるいは、上限を超える場合を別に根拠つきで決める。受入基準（3値の enum で total=3、2値だけをサンプルすると 2/3）はそのままでよい。
