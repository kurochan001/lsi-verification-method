# メモリの検証

RAMとその周りの回路の検証を、ポートと衝突、Byte enable、ECCとスクラブ、MBIST、キャッシュ、DRAM、FIFOへ分けて整理します。入口は[RAMのポート構成の例](../../examples/local-ram-ports/README.md)と、[RAMを使う4つの発展教材](../../examples/local-memory-common/README.md)です。

メモリの検証には、目的の違う2つがあります。この資料の全体で、この2つを分けて扱います。

| | 機能検証 | 製造故障の検査 |
| --- | --- | --- |
| 問い | 設計が仕様どおりか | 作った1個1個のチップのメモリセルが壊れていないか |
| 対象 | メモリを使う論理、制御、インターフェース | メモリセル、デコーダー、読み書きの回路の物理的な欠陥 |
| 誤りのモデル | 設計の誤り（番地の計算、同時アクセスの扱い、初期化） | 故障モデル（縮退、遷移、結合、アドレスデコーダーの故障） |
| 手段 | シミュレーション、フォーマル、参照モデルとの比較 | MBIST、マーチ試験、修復、ECCによる運用中の訂正 |
| 指標 | 要求とカバレッジの到達 | 故障モデルに対する検出率 |
| このリポジトリの例 | RAMのポート、ECCの回路、キャッシュ、FIFO | [MBIST](../../examples/local-mbist/README.md)（MBISTの制御回路の機能検証と、デジタルな故障の注入） |

MBISTの回路そのものは論理回路なので、機能検証の対象です。MBISTが「メモリの故障を検出できるか」は、故障モデルを注入して確かめます。この2つを同じ合格数にまとめません。

## 1. 最初に対象境界を決める

| 対象 | 主な確認事項 | このリポジトリの入口 |
| --- | --- | --- |
| RAMのポート | 単一ポート、1R1W、真のデュアルポート。同じ番地への同時アクセス | [RAMのポート構成](../../examples/local-ram-ports/README.md) |
| 番地の単位 | WordアドレスとByteアドレスの変換、ベース番地 | 同上 |
| 部分書込み | Byte enable、ECCつきでのRead-Modify-Write | [ECC付き部分書込み](../../examples/local-ecc-rmw/README.md) |
| 整列していないアクセス | 分割、エンディアン | [非整列アクセス](../../examples/local-unaligned-memory/README.md) |
| 誤りの訂正 | 符号化、1ビットの訂正、2ビットの検出、スクラブ | [ECC](../../examples/local-ecc/README.md)、[ECCメモリ](../../examples/local-ecc-memory/README.md) |
| 自己試験 | マーチ試験の順序、故障の検出、結果の報告 | [MBIST](../../examples/local-mbist/README.md) |
| キャッシュ | ヒットとミス、書戻し、無効化、一貫性 | [キャッシュとDMA](../../examples/local-cache-dma/README.md)、[キャッシュコヒーレンシ](../../examples/local-cache-coherence/README.md) |
| DRAMの制御 | コマンドの間隔、行の管理、リフレッシュ | [DRAMコマンド制御](../../examples/local-dram/README.md) |
| FIFO | 満杯と空、同時の読み書き、非同期、同期読出しRAMの遅れ | [FIFO](../../examples/local-fifo/README.md)、[非同期FIFO](../../examples/local-async-fifo/README.md)、[同期RAM型非同期FIFO](../../examples/local-sync-ram-fifo/README.md) |
| 複数の利用者 | 同じ番地への複数マスターのアクセスの順序 | [同一番地の競合](../../examples/local-memory-order/README.md) |

RAMのマクロを使う設計では、最初にマクロの契約を表にします：読出しの遅れ（同期・非同期）、同じ番地の同時読み書きの結果（古い値・新しい値・不定）、2つのポートが同じ番地へ書いたときの結果、Byte enableの有無、初期値、クロックの関係。RTLの動作モデルとマクロの契約が違えば、RTLの検証の結果は実装へ引き継げません。

## 2. 要求へ分解する

| 要求の領域 | 要求の例 | 確認方法 |
| --- | --- | --- |
| 読み書き | 書いた値が読める。書いていない番地は変わらない | 参照モデル（辞書）との比較。全番地の最終状態の照合 |
| 番地の境界 | 先頭と末尾、深さが2のべき乗でないときの範囲外 | 境界の番地の固定の試験 |
| 同じ番地の同時読み書き | 決めた方針（古い値・新しい値・不定として使わない）どおり | 方針ごとの構成と、同じサイクルの読み書き |
| 2つのポートの同時書込み | 拒否する、優先を決める、または起こさないことを保証する | 衝突の試験と、上位の回路が起こさないことのアサーション |
| Byte enable | 有効なバイトだけが変わる。全0は何も書かない | バイトごとのパターン |
| 読出しの遅れ | 同期読出しのデータは次のサイクル。その間の番地の変化の扱い | 連続した読出し、読出し中の書込み |
| 初期化 | 読む前に書く、または初期化の完了を待つ | 未初期化の読出しのXの検査 |
| ECC | 1ビットは訂正して通知。2ビットは検出して訂正しない。検査ビットの誤りも同じ | 全位置の1ビット、選んだ2ビットの組 |
| スクラブ | 訂正した値を書き戻す。機能のアクセスと競合しない | スクラブ中の読み書き、訂正後の再読出し |
| MBIST | 決めた順序で全番地を読み書きする。故障を検出して位置を報告する。終了後に通常動作へ戻す | 順序の観測、故障の注入、終了後のアクセス |
| キャッシュ | 読んだ値は、その時点の最新の値。書戻しで古い値を上書きしない | 見える値の参照モデル、追出しと無効化の組合せ |
| FIFO | 欠落・重複・順序。満杯で書かない、空で読まない | スコアボード、フォーマル |

## 3. 重点にするクロス

| クロス | 見つかる誤り |
| --- | --- |
| ポートAの操作 × ポートBの操作 × 番地の一致 | 同時アクセスの扱いの誤り |
| 読出しの直後 × 同じ番地への書込み | 同期読出しの遅れの間の値の取り違え |
| Byte enableのパターン × ECC | 部分書込みでの検査ビットの更新漏れ |
| ECCの誤りの位置（データ・検査ビット）× 読出しの経路（機能・スクラブ） | 片方の経路だけの訂正 |
| 訂正 × 同時の書込み | 訂正した古い値による新しい値の上書き |
| MBISTの実行 × 機能のアクセス × リセット | 試験中のアクセス、試験の中断後の状態 |
| FIFOの満杯・空 × 同時の読み書き | 境界での1件の欠落・重複 |
| 番地の単位（Word・Byte）× ベース番地 | 単位の取り違え、ずれた番地 |

## 4. 独立した期待値を用意する

- **番地から値への辞書**：RTLの配列の添字や遅れの段数を写さず、「最後に書いた値」を辞書で持ちます。読出しの遅れは、読出しを要求した時刻の辞書の値を取っておき、応答の時刻に比べます。
- **同時アクセスの方針**：方針を表で持ち、構成ごとに期待値を切り替えます。「不定」の方針では、値を比べず、上位がその値を使っていないことを検査します。
- **ECC**：符号の定義（検査行列）から符号語を作る実装と、RTLとは別に、全1ビット誤り・全2ビット誤りを全数で確かめる実装を使います。
- **マーチ試験**：アルゴリズムの記法（各要素の番地の向きと操作）から、期待するアクセス列を生成し、RTLのアクセス列と比べます。
- **キャッシュ**：キャッシュを持たない参照モデル（常に最新の値を返す）と比べます。ただし、仕様として古い値が見える場面（無効化の前のDMAの書込みなど）は、その仕様を期待値に入れます。

メモリの中身は、最後に全番地を読んで照合します。途中の読出しだけでは、読まなかった番地への誤った書込みが見つかりません。

## 5. 検出力を確かめる

機能検証の変異と、製造故障のモデルを分けます。

| 種類 | 例 | 検出する検査 |
| --- | --- | --- |
| 設計の変異 | 番地を1ビットずらす、Byte enableを無視する、同時読み書きの方針を変える | 参照モデルとの比較、最終状態の照合 |
| 設計の変異 | ECCの検査ビットを更新しない、訂正した値を書き戻さない | 部分書込みの後の読出し、スクラブ後の再読出し |
| 故障モデル（MBISTの検出力） | セルの縮退、遷移できないセル、隣のセルとの結合、番地の取り違え | MBISTの不合格の報告と位置 |
| 故障モデル（ECCの検出力） | 1ビット・2ビットの反転、同じ語への複数回の反転 | 訂正と検出の通知、3ビット以上は保証外として診断に分ける |

故障モデルに対する検出率は、対象の故障の集合と分母を書きます。「March C−で全故障を検出」とは書かず、「注入したN種類の故障モデルのうちM種類」と書きます。

## 7. 製品で追加する確認

| 追加する確認 | 内容 |
| --- | --- |
| マクロのモデルとの整合 | メモリコンパイラーが出すシミュレーションモデルでの実行。RTLの動作モデルとの契約の差 |
| MBISTの挿入後 | 挿入したMBISTと機能の経路の等価性、試験モードの切替え、実速度の試験 |
| 故障の検出率 | 対象の故障モデルとアルゴリズムの対応。修復の割当ての検証 |
| ソフトエラー | 故障率、スクラブの周期、複数ビットの反転、インターリーブ |
| タイミングと電源 | マクロのセットアップ・ホールド、電源の投入順、保持モード |
| 性能 | 帯域、遅れ、キャッシュのヒット率（実際の負荷で） |
| DRAMのインターフェース | PHY、トレーニング、信号の品質、規格（JEDEC）への適合 |
