# DFTの検証：スキャン・ATPG・MBIST・LBIST・JTAG

DFT（Design for Test）は、製造後や運用中に回路の故障を検査しやすくする設計です。通常機能の検証に加え、テスト回路が正しい操作で開始・実行・観測・終了できるか、故障を検出できるか、機能動作へ復帰できるかを検証します。

本リポジトリには、内部スキャン＋ATPG、遷移故障、メモリのMBISTと修復、ロジックのLBIST、JTAGのデジタル教材があります。製品のDFT挿入・物理実装・量産テストを実施した結果とは範囲を分けます。

## 1. 題材を選ぶ

| 題材 | 既存の実行例 | 主に確認すること |
| --- | --- | --- |
| 内部スキャン・ATPG | [4ビットチェーンとパターン生成](../../examples/local-scan-atpg/README.md) | ロード・キャプチャ・アンロード、シリアル順序、指定14故障の分類と検出可能な13故障 |
| 遷移故障 | [実速度の捕捉](../../examples/local-transition-fault/README.md) | launch-on-captureの2パターン、SDFを使った実速度と低速の比較 |
| MBIST | [March C−](../../examples/local-mbist/README.md) | メモリの読書き順序・方向、10N操作、固着・遷移等の限定モデル、最初の失敗位置 |
| メモリの修復 | [予備の行・列とヒューズ](../../examples/local-memory-repair/README.md) | 修復可能性の判定、再起動後の番地の振替、修復後の再試験 |
| LBIST | [PRPG・MISR・エイリアシング](../../examples/local-lbist/README.md) | seed・試験長・署名、8個の出力縮退故障、圧縮による見逃し、開始・完了・中断・通常出力の隔離 |
| JTAG・境界走査 | [TAP・IR/DR・PRELOAD・EXTEST](../../examples/local-jtag-tap/README.md) | TAP遷移、命令とデータ、Capture/Shift/Update、出力保持と端子の制御・観測 |

例えば、スキャンは内部状態への制御・観測経路、ATPGは故障を検出する入力を作る処理です。LBISTは回路内の刺激生成と応答圧縮を使い、MBISTはメモリ向けの操作列を実行します。JTAGはアクセス経路であり、それだけで内部故障を網羅するものではありません。[OpenROADのDFT資料](https://openroad.readthedocs.io/en/latest/main/src/dft/README.html)は、スキャンセル・チェーンと挿入フローの参照先です。本教材でOpenROADを実行したとは扱いません。

## 2. テストモードの契約を要求にする

| 時点 | 計画する条件 | 判定と証跡 |
| --- | --- | --- |
| テストへ入る前 | 機能要求の停止・排出、クロック・リセット・電源、隔離、アクセス権 | 実行前提の成立、未完了の扱い、端子・出力が安全な状態 |
| 設定・開始 | seed・パターン数・期待署名、スキャン構成、メモリ範囲、再開始 | 入力の保持、禁止設定の拒否、busy・受理件数 |
| シフト・実行 | scan_enable、シフト数、capture、クロック条件、メモリready | 実際のデータ・順序・操作数・応答、途中の待ち・リセット |
| 完了・失敗 | 規定回数の完了、署名比較、最初の故障位置、タイムアウト | doneと合否の分離、最終応答を含む比較、未完了を成功へ数えない |
| 終了・復帰 | モード解除、状態の保持／破棄、リセットと再初期化 | 通常出力・機能転送の復帰、古い試験結果・応答の混入なし |

製品では、試験が機能状態を破壊する場合があります。[TIのLBIST資料](https://software-dl.ti.com/mcu-plus-sdk/esd/AM243X/10_01_00_32/exports/docs/api_guide_am243x/SDL_LBIST_PAGE.html)も、対象IPの準備、完了後の署名確認、テストモードからの復帰を説明しています。製品固有の手順は、そのIPの仕様に合わせて確認します。

## 3. 故障モデルと検出率を分ける

故障リストには、故障の種類、対象ノード・端子・分岐・セル、極性、単一／複数、実行モードと制約を固定します。単一縮退故障、遷移故障、ブリッジ故障、メモリの結合故障などは別の集合です。

- **検出済み**：故障を活性化し、許された観測点で無故障応答との相違を実際に判定できた。
- **検出不能を示した故障**：固定したモデル・制約の下で、どの入力でも観測差が出ないことを示した。小規模な全数調査や証明の対象範囲を残す。
- **未検出・未解決**：選んだパターンや資源上限では検出できなかった。ATPGの中断・時間切れを、冗長故障へ分類しない。
- **未実行・対象外**：実行していないもの、または仕様・モデルの対象から外したもの。根拠と担当を記録する。

全故障数を分母にする率と、検出可能と判定した故障数を分母にする率を区別します。スキャン例は全14故障中13故障を検出し、検出可能な13故障はすべて検出します。LBIST例は指定8出力故障に対する限定した結果です。これらを製品全体の故障検出率や機能安全の診断網羅率へ流用しません。

## 4. 署名圧縮とエイリアシング

PRPGのseed、多項式・ビット順、パターン数、応答の取り込み位置、MISRの初期値・更新規則を固定します。署名だけでなく、実応答と完了件数を比較し、違う設定や途中終了が同じ「PASS」へまとめられないようにします。

異なる応答列が同じ署名へ圧縮されることを、エイリアシングと呼びます。[LBIST例の診断](../../examples/local-lbist/README.md#3-故障とエイリアシング)では、2回の応答反転が打ち消し合い、署名比較が合格する状況をRTLで示します。これは見逃しの存在を確認する診断で、通常機能のカバレッジを埋める観測にはしません。検出力は、対象故障に対する故障シミュレーションと観測結果で評価します。

実回路のXがMISRへ入る場合も、無条件に0へ置換して合格にしません。X源、マスクの条件・範囲、マスクで失う観測性を記録します。このリポジトリのLBIST例にはXマスキングを実装していません。

## 5. 実装と製造テストへつなぐ項目

| 領域 | 教材に加えて必要な確認 |
| --- | --- |
| スキャン挿入 | 機能モードの等価性、全チェーンの接続・長さ、除外セル、クロック・リセットの制御性 |
| テストクロック | シフトとcaptureの切替、OCC、captureパルス数、at-speedの実タイミング、複数クロックとlockupの要否 |
| 圧縮・観測 | チェーンの再順序、圧縮器、MISR、Xマスク、パターン変換後の故障検出性 |
| 電力・低電力 | シフト／captureの切替活動、同時試験、クロック停止・電源領域・隔離・保持との競合 |
| ATE・実機 | 端子割当、波形・比較時点、電気条件、変換後パターンの照合、実デバイスの結果 |
| 運用・保護 | テストへのアクセス権、製造／出荷後モード、破壊する状態、通常動作への復帰手順 |

これらは必要な追加検証の項目であり、本教材で実行済みの範囲ではありません。[適用範囲](../templates/verification-scope.md)、[完了記録](../templates/signoff-record.md)、[製品開発上のDFT項目](spec-to-verification-method.md#145-dft量産テスト)へ、要求・担当・実行段階・証跡・未解決を対応付けます。
