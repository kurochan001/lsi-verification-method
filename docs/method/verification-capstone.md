# 仕様から検証完了の判断までを通して学ぶ

[APB＋割り込みの総合演習](../capstone-apb-irq/README.md)で、個別の手法を一つの開発の流れへつなぎます。仕様の曖昧さを解消し、検証項目と合格条件を定め、失敗・未達を見直し、仕様変更後にどこまで再検証するかを判断します。

| 段階 | 作るもの・確認すること | 演習の資料 |
| --- | --- | --- |
| 仕様を読む | 受理時点、優先順位、リセット、エラー時の副作用を確定する | [対象と仕様課題](../capstone-apb-irq/README.md#1-対象と仕様課題) |
| 計画を作る | 要求、刺激、期待値、観測、構成、完了条件を対応付ける | [記入済み検証計画](../capstone-apb-irq/verification-plan.md) |
| 実行する | 正常比較、クロス、変異検出、SVA、行カバレッジを読む | [実行する手順](../capstone-apb-irq/README.md#2-固定計画で実行する) |
| 変更に追従する | 同じ入力でr1／r2を比較し、古い期待値・SVA・証跡を検出する | [仕様変更の実行例](../../examples/local-spec-change/README.md) |
| 完了を判断する | 採用する結果、未確認、残リスク、人の承認を記入する | [サインオフ記入例](../capstone-apb-irq/signoff-example.md) |

要求表が埋まったこと、試験が正常終了したこと、カバレッジの率が高いことは、それぞれ別の情報です。対応する判定と版をそろえ、計画した適用範囲が満たされたかを判断します。仕様変更で必要な再検証が残った場合の保留判断も演習へ含めています。

初めて項目表を作る場合は[短い仕様からの展開](spec-to-test-items-walkthrough.md)、条件が多い場合は[クロス条件の選定](cross-test-selection-walkthrough.md)を先に参照できます。
