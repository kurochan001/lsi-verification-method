# 低電力設計の検証

電源を切る領域、クロックを止める領域を持つ回路の検証を、電源状態の表、領域の境界（隔離・保持・レベルシフター）、起動と停止の順序、クロックゲーティング、wake-upへ分けて整理します。入口は[低電力制御の例](../../examples/local-power/README.md)と[クロック停止・リセットの例](../../examples/local-clock-reset/README.md)です。

この資料とリポジトリの例は、RTLで書いた動作モデルの範囲を扱います。電源の意図を記述するUPF（IEEE 1801）を読み込むパワーアウェアなシミュレーションは、このリポジトリのオープンソースのツールでは実行できません。[実行できない範囲](#2-rtlの動作モデルとパワーアウェアなシミュレーションの違い)を先に確認してください。

## 低電力の検証が別の分野になる理由

電源を切った領域の信号は、0でも1でもない不定の値になります。通常のRTLシミュレーションは電源を扱わないので、領域を切っても中のレジスタは値を持ち続け、出力も正しい値のままです。次のような誤りは、電源の振る舞いを足さないと見えません。

| 誤り | 通常のRTLシミュレーションで起きること |
| --- | --- |
| 隔離の抜け | OFFの領域の出力が、切る前の値のまま常時動作側へ届く。誤りが見えない |
| 隔離の順序 | 隔離より先に電源を切っても、値が残るので合格する |
| 保持の抜け | 保持しないはずのレジスタが値を持ち続け、復帰後の初期化漏れが見えない |
| 復帰後の初期化漏れ | リセットを忘れても、切る前の値で動いてしまう |
| OFF中の領域への依存 | 常時動作側がOFFの領域の信号を使って判断しても、値があるので動く |

## 1. 最初に対象境界を決める

| 対象 | 主な確認事項 | このリポジトリの入口 |
| --- | --- | --- |
| 電源状態と遷移 | 合法な状態の組、遷移の順序、遷移中の要求 | [低電力制御](../../examples/local-power/README.md) |
| 領域の境界 | 隔離の値と時刻、保持と復元、レベルシフターの有無 | 同上（隔離値0、保持の有無） |
| クロックの停止 | 停止前の排出、停止中の保持、再開後の最初のエッジ | [クロック停止とリセット](../../examples/local-clock-reset/README.md) |
| クロックの供給源 | PLLのロック待ち、停止の検出、切替え | [PLLの復帰](../../examples/local-pll-recovery/README.md) |
| wake-up | 要因の保持、停止との競合、非同期の要因 | [CDCハンドシェイク](../../examples/local-cdc-handshake/README.md)（同期化の部分） |
| 電源の立上り | パワーオンリセット、電圧の検出 | [RC回路とSPICE](../../examples/local-spice-cosim/README.md)（電圧応答の部分） |

最初に、電源領域の一覧を作ります。各領域について、常時動作か切れるか、電圧、保持するレジスタ、境界の信号と隔離値、制御する回路の所在（必ず常時動作側）を表にします。この表が、UPFを書くときにも、動作モデルを作るときにも元になります。

## 2. RTLの動作モデルとパワーアウェアなシミュレーションの違い

| 観点 | RTLの動作モデル（このリポジトリ） | パワーアウェアなシミュレーション |
| --- | --- | --- |
| 電源の意図の書き方 | RTLやテストベンチの中に、電源の状態と不定値の注入を書く | UPFに領域・電源網・スイッチ・隔離・保持・レベルシフターを書く |
| OFFの表現 | モデルが選んだレジスタへXを入れる | 領域内の全レジスタと出力をシミュレーターが破壊する |
| 隔離・保持セル | 論理として手で書く | UPFの方針から挿入され、制御信号と電源が検査される |
| 電源網とスイッチ | 1本の`power_good`などの信号 | 電源網ごとの電圧と、スイッチの応答 |
| 見つかる誤り | 制御の順序、隔離値、保持の方針、復帰後の初期化（モデルに入れた範囲） | 上に加えて、UPFと回路の不整合、隔離・レベルシフターの抜け、電源の供給元の誤り |
| 見つからない誤り | モデルに書かなかったレジスタと経路。UPFの記述の誤り | 実際の電圧降下、突入電流、スイッチの段階的な投入の電気的な影響 |

動作モデルで合格しても、UPFが正しいことは分かりません。逆に、UPFを使うシミュレーションでも、制御の順序の仕様が曖昧なら誤りは見つかりません。動作モデルの段階では、次の3つを固めます。

- 電源状態の表と、合法な遷移。
- 各境界の信号の隔離値と、隔離・電源・リセット・保持の順序。
- 保持するレジスタと、復帰後に初期化するレジスタの一覧。

### このリポジトリで実行できない範囲

- UPFの読込み、UPFから隔離セル・保持セル・レベルシフター・電源スイッチを挿入した状態でのシミュレーション。
- UPFと回路の静的な検査（隔離やレベルシフターの抜け、電源の供給元の誤り）。
- 電源網の電圧、突入電流、IRドロップ、スイッチの投入順による電気的な影響。
- 低電力要素を挿入した後のネットリストと、RTL＋UPFの等価性検証。
- 消費電力の見積りと実測。

これらは、UPFに対応した商用のシミュレーター・静的検査ツール・等価性検証ツール、または実機の評価で確認します。このリポジトリは商用ツールを実行しないので、結果も載せていません。

## 3. 要求へ分解する

| 要求の領域 | 要求の例 | 確認方法 |
| --- | --- | --- |
| 電源状態の表 | 合法な状態の組だけが現れる。表にない組へ入らない | 状態のアサーションと、全状態・全遷移の到達 |
| 停止の順序 | 受付の停止→排出→保存→隔離→リセットまたはクロック停止→電源断 | 各段の完了を待つこと。順序を入れ替えた変異 |
| 起動の順序 | 電源投入→安定の待ち→リセット→復元→隔離の解除→受付の再開 | 安定の前に隔離を解かない。復元の前に使わない |
| 隔離 | OFF中、境界の信号が決めた値（0／1／直前の値）である | 常時動作側の入力でのXの検査と値の検査 |
| 保持 | 保持するレジスタは復帰後に同じ値。しないレジスタはリセット値 | 停止前と復帰後の比較。保持の対象を1つ外す変異 |
| 復帰後の初期化 | 保持しないレジスタを、使う前に必ず初期化する | OFF中にXを入れ、復帰後の出力にXが出ないこと |
| クロックゲーティング | イネーブルの変化で短いパルスが出ない。止めている間に状態が変わらない | ゲートの出力のパルス幅の検査、停止中の状態の比較 |
| wake-up | 要因を取りこぼさない。停止の途中に来た要因で戻る。要因が消えても記録が残る | 要因の時刻を停止の各段へずらす |
| 遷移中の要求 | 停止の途中の新規要求、起動の途中の停止要求 | 受け付けない・待たせる・取り消すのどれかを仕様で決めて検査 |
| ソフトウェアとの取り決め | 停止前に保存するもの、復帰後に再設定するもの | ドライバーの手順とレジスタの値の照合 |

## 4. 重点にするクロス

| クロス | 見つかる誤り |
| --- | --- |
| 停止要求 × 処理の各段（待機、受付直後、完了直前） | 未完了の処理の喪失、二重の完了 |
| 停止の各段 × wake-up要因の到着 | 要因の取りこぼし、途中で止まる状態機械 |
| 停止の各段 × リセット | 隔離や保持の制御が残ったままの再起動 |
| 保持の有無 × 復帰後の最初の操作 | 初期化前の値の使用 |
| 領域Aの状態 × 領域Bの状態 × 境界をまたぐ転送 | OFFの領域への要求、OFFの領域からの応答の待ち続け |
| 電源の投入順 × 領域間の依存 | 供給元より先に立ち上がる領域 |
| クロックの停止 × 非同期の入力 | 止まったクロックで同期化できない要因 |

## 5. 独立した期待値を用意する

制御回路の状態機械を期待値へ写すと、順序の誤りを一緒に写します。期待値は次のように作ります。

- **電源状態の表から**：各時刻の「あるべき電源状態」を、要求（sleep、wake）と完了の事実から求めます。RTLの状態の符号化は使いません。
- **保存値の台帳から**：停止を受け付けた時点の値を台帳に取り、復帰後の値と比べます。
- **不定値の伝搬で**：OFFの領域の全レジスタへXを入れ、常時動作側の観測点にXが現れないことを見ます。隔離値を知らなくても、抜けは検出できます。
- **電源意図の表からの生成**：領域・保持・隔離値を表（JSONなど）に書き、Xを入れるラッパーと隔離のチェッカーを表から生成します。モデルに書き忘れたレジスタが残らないようにするためです。

4値のシミュレーションが必要です。2値のシミュレーター（Verilatorの既定）では、Xの流出を観測できません。

## 6. 検出力を確かめる

| 変異 | 検出する検査 |
| --- | --- |
| 排出を待たずに止める | 受付数と完了数の照合 |
| 隔離より先に電源を切る、隔離を早く解く | 境界のXの検査 |
| 隔離値が違う（0のはずが1） | 境界の値の検査。Xの検査だけでは見えない |
| 保持の対象を1つ外す | 復帰後の値の比較 |
| 保持しないレジスタの初期化を忘れる | 復帰後の出力のXの検査 |
| 停止の途中のwake-upを落とす | 要因の件数と復帰の件数の照合、時間切れ |
| クロックゲートをANDだけで作る | ゲートの出力の最小パルス幅の検査 |

Xの検査は、Xを入れた箇所からしか始まりません。変異「Xを入れるレジスタの一覧から1つ外す」を用意し、チェッカーの元になる一覧そのものも確かめます。

## 8. 製品で追加する確認

| 追加する確認 | 内容 |
| --- | --- |
| UPFの静的な検査 | 隔離・レベルシフター・保持の抜けと余分、制御信号の電源領域、供給元 |
| パワーアウェアなシミュレーション | 主要な電源シナリオ（起動、各低電力モードへの出入り、wake-up、遷移中のリセット）をRTL＋UPFで実行 |
| 電源状態のカバレッジ | 電源状態の表の全状態と全遷移、遷移中の要求との組合せ |
| 低電力要素の挿入後 | ネットリスト＋UPFでの等価性検証と、ゲートレベルのシミュレーション |
| クロックとリセット | 停止・再開・切替えのグリッチ、電源領域をまたぐCDC・RDC（[非同期検証](asynchronous-verification.md)） |
| ソフトウェアとの結合 | 実際のドライバー・ファームウェアによる保存と復元、時間の制約 |
| 電気的な確認 | 突入電流、IRドロップ、スイッチの投入順、保持電圧、復帰時間、消費電力の実測 |
