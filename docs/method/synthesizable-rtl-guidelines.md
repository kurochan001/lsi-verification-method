# 合成向けRTLを書くときのルール

合成対象のRTLは、シミュレーションで動くだけでなく、意図したレジスタ・組合せ回路・メモリへ変換されるように書きます。対象のASIC／FPGA、合成ツールと言語対応、セル・メモリ、クロック・リセットと制約を先に決めます。仕様の準備は[LSI仕様書の書き方](lsi-specification-writing.md)、静的検査の運用は[lintと警告管理](lint-and-waivers.md)を参照してください。

以下は新規RTLと変更レビューに使う基本ルールです。FPGA固有の初期値やメモリ等は採用フローで確認する項目として分けます。本リポジトリの既存RTLすべてが、この記述様式へ統一済みという意味ではありません。

## 1. 書く前に合成の対象を固定する

| 決めるもの | 記録する内容 |
| --- | --- |
| 合成範囲 | トップ、ファイル一覧、include、define、パラメーター、使用する言語範囲 |
| 対象技術 | ASICのセル・メモリ、FPGAのデバイス・RAM/DSP等、使用IPと版 |
| 動作条件 | クロック・生成クロック、周波数、入出力・タイミング例外、リセット・電源・テストモード |
| 構成 | 幅1、最小・最大、深さ1、非2べき乗、オプション有無を含む合法集合と禁止条件 |
| 検査 | lint、シミュレーション、合成ログと推論結果、等価性、STA、CDC/RDCの担当と入口 |

ライブラリーがない汎用合成の成功を、実セルへのマッピング・タイミング収束・電力の合格として扱いません。ASICとFPGAで成立条件が変わる記述は、実装依存として隔離して根拠を残します。

## 2. 組合せ回路は全経路で値を決める

- SystemVerilogでは組合せ処理に`always_comb`、単純な式に`assign`を使えます。既存の`always @*`を使う場合も、感度と代入の完全性を確認します。
- 組合せ処理内の計算はブロッキング代入`=`を基本にし、参照する一時値を先に計算します。出力と一時変数を全分岐で定義します。
- デフォルト値を先に置くか、if/caseの全経路で代入し、意図しないラッチを作りません。ラッチが必要なら意図・保持条件・タイミング・採用セルを明示します。
- 自分自身や他の組合せ出力を循環して参照するループを作りません。合成ログと構造検査でも確認します。

次の記述は区別します。

```text
logic flag = expression;    // 変数の初期化。入力変化に追従する組合せ代入ではない。
assign flag = expression;   // 入力変化に追従する連続代入。
```

`always_comb`と書くだけで、ラッチや幅・優先順位の問題が自動的に解決するわけではありません。実際の推論結果を確認します。

## 3. 状態はクロック・リセット・更新条件を明示する

状態更新にはノンブロッキング代入`<=`を基本にします。同じエッジの各レジスタが更新前の値を使う動作として設計し、書いた順番への依存を避けます。計算用の一時変数に`=`を使う場合は、状態とは区別し、順序と読み手をレビューします。

一つのレジスタを複数のalways、initial、連続代入等から駆動しません。リセットと通常更新も同じ順序処理へまとめます。`always_ff`は意図を示す助けになりますが、採用ツールの検査範囲も確認します。

以下は、Low有効の同期リセットとclock enableを持つカウンターです。WIDTHは本例では1〜32を対象にし、最大値の次は0へwrapする仕様です。飽和が必要な回路へ、そのまま流用しません。

```systemverilog
module counter_ce #(parameter integer WIDTH = 8) (
    input  logic clk,
    input  logic rst_n,
    input  logic enable,
    output logic [WIDTH-1:0] count
);
    always_ff @(posedge clk) begin
        if (!rst_n)
            count <= '0;
        else if (enable)
            count <= count + WIDTH'(1);
    end
endmodule
```

クロック付きの処理で、更新しない分岐がレジスタの保持になることと、組合せ処理の代入漏れによるラッチは別です。不要な自己代入で、この違いを隠さないようにします。

## 4. 幅・符号・切捨てを式に表す

| 観点 | ルール・レビュー内容 |
| --- | --- |
| 定数と演算幅 | サイズなし定数やintegerとの混在で、意図しない32ビット化・符号拡張を起こさない。幅・型を明示する |
| 加減算 | carry・borrowやオーバーフローが必要なら、演算前に幅を広げる。狭い結果を後から拡張しても失った桁は戻らない |
| 符号 | signed/unsigned、連結・部分選択・三項演算子での型を確認する。`$signed`で値の幅まで増えると考えない |
| シフト | `>>`と`>>>`、左辺の符号と演算幅、シフト量0・幅以上を確認する |
| 縮小・丸め | 切り捨てるビット、丸め、飽和／wrapを仕様と対応付け、明示した範囲を選ぶ |
| 演算回路の規模 | 乗算・除算・可変シフト・大きなループが、必要な面積・遅延・DSP資源へ収まるか確認する |

次は、加算で1ビット広げた結果からcarryと下位ビットを分け、別操作としてANDを選ぶ例です。op=2／3はinvalid=1・出力0とする例示仕様です。

```systemverilog
module decode_and_add #(parameter integer WIDTH = 8) (
    input  logic [WIDTH-1:0] a, b,
    input  logic [1:0] op,
    output logic [WIDTH-1:0] result,
    output logic carry, invalid
);
    logic [WIDTH:0] sum_ext;
    always_comb begin
        sum_ext = {1'b0, a} + {1'b0, b};
        result = '0;
        carry = 1'b0;
        invalid = 1'b0;
        case (op)
            2'b00: begin
                result = sum_ext[WIDTH-1:0];
                carry = sum_ext[WIDTH];
            end
            2'b01: result = a & b;
            default: invalid = 1'b1;
        endcase
    end
endmodule
```

比較では境界の「以上／超過」を区別し、アドレス＋長さを必要な幅で計算します。幅警告を消すためだけのキャストで、比較対象の上位ビットや符号を捨てません。

## 5. 優先順位・FSM・Xの扱いを意図どおりにする

- if/elseの順番は優先順位になります。並列に成立し得る要求、同時更新、リセットとの関係を仕様の表へ対応付けます。
- caseの未指定値、予約値、複数ビットが立った条件を決めます。`casex`で未知値まで無視すると不具合を隠すため、基本のデコードには使いません。`casez`のワイルドカードも適用するビットと根拠を限定します。
- `unique`や`priority`、full_case等の指示で、合法な条件を暗黙に除かないようにします。シミュレーションの警告と合成時の最適化の意味を確認します。
- FSMの状態符号は、対象フローで再符号化される場合があります。不正状態からの復帰を保証する必要があれば、RTLのdefaultだけに頼らず、採用する合成設定・故障モデル・合成後の結果も確認します。
- 合成対象の`'x`を、実回路が未知値を出す仕様として使いません。don't-careを許す条件を明示し、合成と検証の前提をそろえます。X/Zの検出やcase equalityを使うチェッカーは、原則として検証側へ置きます。

機能動作で値を要求する期間と、valid=0等で値を使わない期間を分けます。無効時に値を使っていないことも検証し、未初期化やXの流出を隠すための一律0置換は行いません。

## 6. クロック・リセット・非同期入力を通常のデータと分ける

通常の保持には、例のようにclock enableを使います。`clk & enable`のような組合せ論理で、根拠のないゲートクロックを作りません。ゲーティングが必要なら、ASICのICGセルやFPGAの対応資源・IPなど、採用フローの安全な方式を使い、クロック定義・テスト・停止復帰を確認します。

リセットの同期／非同期、極性、優先順位、必要な初期値を仕様とセル・IPへ合わせます。非同期リセットの解除は各ドメインの条件へ対応付け、recovery/removalやRDCを別途確認します。クロック停止中の初期化、部分リセット、解除後の最初の受理も対象にします。

非同期入力へ同期器を置くだけで、短パルス・ワード整合性・再収束まで解決したとは扱いません。転送方式、最短間隔、データ保持、同期器の構造・属性・配置・物理制約を、[非同期検証の手順](asynchronous-verification.md)と対応付けます。

## 7. メモリ・初期値・ループは対象技術で確認する

| 記述・機能 | 気を付けること |
| --- | --- |
| メモリ配列 | 同期／非同期読出し、ポート数、書込みマスク、出力レジスタが、意図したRAM・マクロへ対応するか確認する |
| 全セルへのリセット | ループで全配列をクリアすると、RAMへ推論されず多数のFFになる場合がある。初期化シーケンスやvalid管理等の方式を検討する |
| 読書きの衝突 | 同一アドレスのread-during-write、複数ポートの同時書込みを定義する。RTLの実行順から実メモリの動作を決め付けない |
| 宣言時初期値・initial・readmem | 一部FPGAで設定時の初期内容へ対応する場合がある。一般的なASICの電源投入状態や、運用中のリセットを代替するとは考えない |
| for/generate | ハードウェアとして展開・実現できる有限の範囲を決める。大きな反復が、時間をかけて実行されると考えない |
| データ依存の反復 | while等の終了条件と実現方式を確認する。必要なら、カウンターとFSMで複数サイクルの処理へする |
| パラメーター | 深さ1での`$clog2`、幅0、負の範囲、非2べき乗の周回、定数シフトの桁あふれを確認する。禁止構成はビルド時に拒否する |

例えば、アドレス幅を`DEPTH <= 1 ? 1 : $clog2(DEPTH)`とするだけでは、任意の深さに対応したFIFOにはなりません。許すDEPTHの集合、ポインターの周回、空・満杯の判定を一緒に設計します。

[Yosysのメモリ処理資料](https://yosyshq.readthedocs.io/projects/yosys/en/stable/using_yosys/synthesis/memory.html)と[AMD UG901のコーディングガイド](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/Coding-Guidelines)には、対象資源と推論条件の説明があります。特定のFPGAで推奨されるリセット・初期値の記述を、ASICへ共通の規則として流用しません。

## 8. 検証専用の記述と合成RTLを分ける

`#`遅延やイベント待ちによる刺激、force/release、ファイルI/O、乱数、クラス・動的な検証用データ構造等を、汎用の合成RTLへ混ぜません。シミュレーションで受け付けても、合成で無視・拒否・別解釈される場合があります。FPGAのメモリ初期化等の例外は、対象と用途を明示して個別に確認します。

アサーション、bind、`translate_off/on`、`ifdef SYNTHESIS`等は、採用ツールの対応に従って検証コードを分けるために使います。条件付きコンパイルで、機能経路やリセットの意味がシミュレーションと合成で変わらないようにします。実際に合成したファイル・define・パラメーターを保存します。

内部tri-stateやセル属性も実装依存です。内部バスを一般的なロジックで実現する場合はMUX等へ明示し、端子の三態制御やopen-drainは、対象のI/Oセル・制約・電気条件を別途確認します。

## 9. lintの後に、合成結果まで確認する

1. 全必須構成をエラボレーションし、未接続・未駆動・暗黙ネット・多重駆動、幅・符号、組合せループ、ラッチを確認する。
2. リセット・enable・データの基本動作と境界をシミュレーションし、必要なSVA・フォーマルで性質を確認する。
3. 合成ログで無視された記述、ブラックボックス、不要な定数化・削除、ラッチ・RAM/DSP・FFの推論と増減を確認する。
4. 仕様に必要な機能を合成後も保持するか、対象に応じて等価性や合成後シミュレーション等で照合する。使う初期状態・モード・Xの前提をそろえる。
5. 実セル・デバイスへの実装、SDC等の制約、未制約パス、STA、CDC/RDCをそれぞれ確認する。lintの警告0や汎用合成の成功だけで完了にしない。

本リポジトリの[共通lint](../../examples/local-lint/README.md)は、既知指摘からの差分を管理します。既存の警告が残った「差分なし」と、警告0件は別です。[Verilatorの警告説明](https://verilator.org/guide/latest/warnings.html)で規則の意味を確認し、警告の一括抑止で期待する回路構造の確認を置き換えません。

本資料の2つのコード例は、幅1・8・16・32の計8組で、Icarus Verilog 14.0開発版のシミュレーション、Verilator 5.052のlint、YoWASP Yosys 0.70の汎用合成とラッチなしの確認が合格しました。これは小さな記述例の論理・推論の確認であり、特定のASIC／FPGAに対する面積・周波数・電力や、文書全項目の検証済み状態を示すものではありません。
