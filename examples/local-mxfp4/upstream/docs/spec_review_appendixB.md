## B-1. B.10「e_rel ≤ −10 は 0 へ丸める」は境界が 1 binade ずれている

### 該当箇所

> 相対指数 e_rel = elem_exp − X_biased の扱いは、e_rel ∈ [−6, 8] が正規域、
> [−9, −7] が subnormal 域(LSB 重み 2^−9 相対)、**e_rel ≤ −10 は 0 へ丸める(半 LSB 未満)**。

### 問題

E4M3 の最小非ゼロ値 (subnormal LSB) は 2^−9、その半分は 2^−10 です。
`e_rel = −10` の binade は **[2^−10, 2^−9)** であり、**半 LSB 点 2^−10 をちょうど下端に含みます**。
つまりこの binade は「半 LSB 未満」ではなく、**半 LSB 点そのものから始まり、その上側は
最小 subnormal へ丸まる**領域です。

「e_rel ≤ −10 は 0」とすると、0 へ潰してはいけない値まで潰れます。

### 具体例

v = 1.5 × 2^−10 (X = 1 のときの scaled 値。e_rel = −10)

| 丸め先の候補 | 距離 |
|---|---|
| 0 | 1.5 × 2^−10 |
| 2^−9 (最小 subnormal、M=1) | 0.5 × 2^−10 |

最近傍は 2^−9 です。RNE でも当然 2^−9 になります。付録B の規則では 0 になり、**誤差が 3 倍**に
なります。

なお本文 7.2 節の確定表は、E2M1 について同じ境界を正しく扱っています。

> [0, 0.25] 000 / (0.25, 0.75) 001

E2M1 の LSB は 0.5、半 LSB は 0.25 で、**0.25 を含む閉区間が 0、それより上は 0.5** です
(タイ点はちょうど 0.25 のときだけで、RNE の偶数丸めで 0 側)。付録B の E4M3 版はこの
「タイ点だけが 0」という構造が落ちています。

### 修正案

```diff
-相対指数 e_rel = elem_exp − X_biased の扱いは、e_rel ∈ [−6, 8] が正規域、
-[−9, −7] が subnormal 域(LSB 重み 2^−9 相対)、e_rel ≤ −10 は 0 へ丸める(半 LSB 未満)。
+相対指数 e_rel = elem_exp − X_biased の扱いは、e_rel ∈ [−6, 8] が正規域、
+[−9, −7] が subnormal 域(LSB 重み 2^−9 相対)。e_rel ≤ −11 は半 LSB (2^−10) 未満なので
+0 へ丸める。e_rel = −10 の binade [2^−10, 2^−9) は半 LSB 点を跨ぐため、
+ちょうど 2^−10 のときだけ RNE のタイとして 0(偶数側)へ、それより大きい値は最小
+subnormal (M = 1) へ丸める。E2M1 の確定表 [0, 0.25] → 000、(0.25, 0.75) → 001 と
+同じ構造である。
```

あわせて B.10 末尾の covergroup の記述も届きません。

```diff
-covergroup は cp_e_rel(E4M3 用に −10..8)と cp_mode を追加する。
+covergroup は cp_e_rel(E4M3 用に −11 以下の flush 域、−10 のタイ点、
+subnormal 域 −9..−7、正規域 −6..8 を分けた bins)と cp_mode を追加する。
```

### 検証での裏付け

E4M3 の代表点を独立に列挙し、v = 1.5 × 2^−10 の最近傍を求めました。

```text
[FAIL] B.10 「e_rel <= -10 は 0 へ丸める」 :
       v=1.5*2^-10 は 0 より LSB(2^-9) に近い (|v-0|=1.465e-03 > |v-LSB|=4.883e-04)。
       0 でなく最小 subnormal へ丸まる
[ ok ] B.10 e_rel <= -11 なら確かに半 LSB 未満 (0 へ丸まる)
```

## B-2. B.10 の RNE 骨格が subnormal 域 (e_rel ∈ [−9, −7]) を扱っていない

### 該当箇所

> RNE は 3bit 仮数の一般式 rm3 = m3 + up(up はガード / スティッキーから決定)で行い、
> rm3 の桁上げで指数を 1 繰り上げ、e_rel = 8 での桁上げは 448 へクランプする。

```systemverilog
logic [2:0] m3; logic g, s_or; logic up; logic [3:0] rm3;
up  = g & (s_or | m3[0]);          // RNE
rm3 = {1'b0, m3} + {3'b0, up};
```

### 問題

この一般式は「どの binade にも 3bit ぶん (8 点) の代表点がある」ことを前提にしています。
正規域 (e_rel ∈ [−6, 8]) ではそのとおりですが、**subnormal 域では 1 binade あたりの
代表点が 8 点未満**です。暗黙の 1 が無いため、binade が下がるごとに半減します。

| e_rel | 区間 | 表現可能な点 | 3bit 仮数が前提とする点数 |
|---:|---|---:|---:|
| −9 | [2^−9, 2^−8) | **1** (M=1) | 8 |
| −8 | [2^−8, 2^−7) | **2** (M=2,3) | 8 |
| −7 | [2^−7, 2^−6) | **4** (M=4..7) | 8 |
| −6 | [2^−6, 2^−5) | 8 (M=8..15) | 8 |

そのため subnormal 域では、上の一般式が**表現できない値を出力します**。

本文 7.2 節は E2M1 について同じ論点を明示しています。

> e_rel = −1 の binade だけは代表点が 0.5 のみで x.5 の枠組みが使えず、m1 単独判定となる。

E4M3 ではこれが 3 binade 分に広がる、というのが違いです。

### 具体例

X = 1 のときの scaled 値に対し、「binade 内で 3bit 仮数を RNE する」素朴な実装と
正しい最近傍を比べます。

| 入力 v | e_rel | 正しい最近傍 | 素朴な 3bit RNE |
|---|---:|---|---|
| 1.75 × 2^−9 | −9 | M=2 (2.00 × 2^−9) | 1.75 × 2^−9 — **表現不能** |
| 1.25 × 2^−9 | −9 | M=1 (1.00 × 2^−9) | 1.25 × 2^−9 — **表現不能** |
| 2.75 × 2^−9 | −8 | M=3 (3.00 × 2^−9) | 2.75 × 2^−9 — **表現不能** |
| 3.60 × 2^−9 | −8 | M=4 (4.00 × 2^−9) | 3.50 × 2^−9 — **表現不能** |
| 5.60 × 2^−9 | −7 | M=6 (6.00 × 2^−9) | 5.50 × 2^−9 — **表現不能** |
| 9.30 × 2^−9 | −6 | M=9 (9.00 × 2^−9) | 9.00 × 2^−9 — 一致 (正規域の対照) |

最後の行が対照です。正規域では素朴な実装で正しく、subnormal 域だけが壊れます。

### 修正案

B.10 に subnormal 経路を明記してください。

```diff
 RNE は 3bit 仮数の一般式 rm3 = m3 + up(up はガード / スティッキーから決定)で行い、
 rm3 の桁上げで指数を 1 繰り上げ、e_rel = 8 での桁上げは 448 へクランプする。
+ただしこの一般式が使えるのは正規域 (e_rel ∈ [−6, 8]) だけである。subnormal 域
+(e_rel ∈ [−9, −7]) は暗黙の 1 を持たず、1 binade あたりの代表点が 4 / 2 / 1 点しか
+ないため、仮数を (−6 − e_rel) bit だけ右シフトして LSB 重み 2^−9 の位置で丸める。
+実装としては「まず値を LSB 重み 2^−9 の固定小数点へ揃え、その位置で 1 回だけ RNE する」
+形にすると、正規域と subnormal 域を分岐なく扱える(E2M1 で e_rel = −1 を単独判定に
+した 7.2 節の対応物)。
 E2M1 のときに全タイ点を列挙して確定させたのと同様、各 binade × m3 × 直下ビットの表を
 作って丸め先を固定すること。
```

**表を作るときは正規域だけでなく subnormal 域の 4 / 2 / 1 点も含めてください。**
E2M1 で確定表を置いたことが実装の助けになったので、E4M3 でも同じ価値があります。

### 検証での裏付け

上の表は E4M3 の代表点 (M × 2^−9、M = 0..15) を列挙して最近傍を求めたものです。
binade ごとの代表点数も実測しました (1 / 2 / 4 / 8)。

## B-3. B.9 の SVA が `$past` の第 1 引数に式を渡している

### 該当箇所

```systemverilog
// (2) MXFP8: 同一ブロックの 2 拍で scale が一致
a_fp8_scale_pair: assert property (@(posedge clk) disable iff (!rst_n)
  (mode == MODE_FP8 && in_valid && in_ready && beat_odd) |->
    (a_block[135:128] == $past(a_block[135:128]) &&
     b_block[135:128] == $past(b_block[135:128])) );
```

### 問題

本文 10 章の運用ノート第四点が、これを避けるよう明記しています。

> 第四に、SVA の $past に渡す第 1 引数は式ではなく中間信号にする。
> $past(in_valid && last, LAT) のように式を直接渡すと、処理系によっては 1 tick 余分に
> 遅れた値が返る事例がある。(中略) assign で単一信号に落としてから渡せば移植性が保てる
> (9.5 節の p_ovalid_cause を参照)。

`a_block[135:128]` は部分選択の式なので、この注意にそのまま該当します。本文 9.5 節は
正しい形を実例で示しています。

```systemverilog
logic accept_last;
assign accept_last = in_valid && last;
...
  out_valid |-> $past(accept_last, LAT);
```

付録B の骨格だけが本文の運用ノートに反している状態です。

なお、この注意の根拠になった処理系側の不具合 (Issue #1164) は **2026-08-22 時点で
修正済み**です (procedural / property 内とも実測 PASS)。したがって現時点で
「そのまま書くと誤発火する」わけではありません。それでも中間信号へ落とす形を
維持したいのは、(a) 本文 10 章の運用ノートが規約として残っており、骨格だけが
それに反しているのは読み手を迷わせる、(b) 同じ書き方で 1 度踏んだ以上、
他処理系での移植性を担保する意味がある、の 2 点によります。

### 修正案

```diff
+// scale フィールドは中間信号に落としてから $past へ渡す(10 章 運用ノート第四点)
+logic [7:0] a_scale, b_scale;
+assign a_scale = a_block[135:128];
+assign b_scale = b_block[135:128];
+
 a_fp8_scale_pair: assert property (@(posedge clk) disable iff (!rst_n)
   (mode == MODE_FP8 && in_valid && in_ready && beat_odd) |->
-    (a_block[135:128] == $past(a_block[135:128]) &&
-     b_block[135:128] == $past(b_block[135:128])) );
+    (a_scale == $past(a_scale) && b_scale == $past(b_scale)) );
```

### 検証での裏付け

本文 9.5 節の `p_ovalid_cause` はこの形で書かれており、実装 (`tb/mxfp4_bdp_sva.sv`) でも
同じ運用にしています。処理系側の状態は `repro/past_expr_minimal.sv` で実測しました
(2026-08-20 ビルド)。

```text
PART A (procedural)  : n_mismatch = 0 (expected 0)
PART B (assertion)   : n_sva_mid  = 0 (expected 0)
PART B (assertion)   : n_sva_fail = 0 (expected 0)
*** PASS ***
```

つまり **いま誤発火はしません**。本指摘は「規約と骨格の不整合を直す」ためのものです。

## B-4 (軽微). B.7 の `pack_fp32` が本文 5 章と同名で引数の意味が違う

### 該当箇所

```systemverilog
  p  = Ma * Mb;                                   // 22bit、丸めなし
  ex = (((ea == 0) ? 1 : ea) - 15) + (((eb == 0) ? 1 : eb) - 15) - 20;
  return pack_fp32(sa ^ sb, p, ex);               // 先頭1へ正規化して詰めるだけ(exact)
```

### 問題

本文 5 章 (と実装 `rtl/mxfp4_bdp.sv`) の `pack_fp32` は

```systemverilog
function automatic logic [31:0] pack_fp32(
    input logic sign, input logic signed [IEXP_W-1:0] iexp, input logic [SIGNIF_W-1:0] sig);
```

で、**第 2 引数が内部指数、第 3 引数が暗黙 1 込みの 24bit 正規化仮数**です。
付録B の呼び出しは第 2 引数に 22bit の非正規化仮数、第 3 引数に LSB 重みの指数を
渡しており、引数の順序も意味も違います。

同名のまま両方が同じスコープに入ると、**引数の順序を取り違えても型が通ってしまう**
形です。本プロジェクトは「定数の取り違えが 1.0 + 1.0 = 3.0 型のバグに直結する」
(付録B B.6 の表現) 種類の事故を繰り返しているので、名前で分けておく価値があります。

### 修正案

```diff
-  return pack_fp32(sa ^ sb, p, ex);               // 先頭1へ正規化して詰めるだけ(exact)
+  return pack_fp32_from_lsb(sa ^ sb, p, ex);      // 先頭1へ正規化して詰めるだけ(exact)
```

とし、B.7 に `pack_fp32_from_lsb(sign, mag, lsb_exp)` の規約 (mag は非正規化、
lsb_exp は mag の LSB の重み) を 1 行添えてください。

## 補足 (指摘ではありません)

### E1. B.6 の「1 項の最大 2^35.81」は保守的 (実際は 2^35.61)

> | 1 項の固定小数点値 | ±(Ma·Mb) << s、最大 2^35.81 | s37 に収まる |

225 × 2^28 = 2^35.81 という計算だと思いますが、**|Ma·Mb| = 225 (M=15 同士) と
s = 28 (E=8 同士) は同時に成立しません**。M=15 は m = 7 を要し、E = 8 は e = 15 を
要するので、両立する符号 S.1111.111 は NaN だからです。実際に到達できる最大は
M=14 (448)、E=8 の組で 196 × 2^28 = 2^35.61 でした。

**s37 / s42 という結論は変わりません** (2^35.61 も 2^35.81 も符号込み 37bit に収まり、
必要ビット数は同じです)。修正は不要で、上界が少し緩いというだけの補足です。

### E2. B.3 の MXFP8 の要素インデックスは「拍内」であることを明記した方がよい

> | MXFP8 | scale(E8M0) | E4M3 × 16(半ブロック) | 要素 i = [8*i +: 8] |

B.6 に「拍 0 で要素 0..15、拍 1 で要素 16..31」とあるので、B.3 の `i` は
**拍内インデックス (0..15)** で、拍 0 と拍 1 では同じビット位置に別の論理要素が
載ることになります。B.3 の表にその 1 行があると、パッキングの実装で迷いません。

### E3. B.11 の X0 に R2f が含まれているが、R2f は mode を持たない

> | X0 | 後方互換 | mode = MXFP4 で既存 R2a / R2f / D4 を再実行 | 既存 RTL とビット一致 100% |

R2f は `mxfp4_fp32_add_core` 単体を任意の FP32 で叩くシナリオ (9.3 節) で、
mode 端子を持ちません。後段共有の方針 (B.4) では加算器コアは全モード共通なので、
R2f は「mode によらず不変であること」の確認として置くのが正確だと思います。

## まとめ

| # | 節 | 内容 | 重み |
|---|---|---|---|
| B-1 | B.10 | 「e_rel ≤ −10 は 0 へ丸める」の境界が 1 binade ずれている。e_rel = −10 はタイ点のみ 0 | 高 |
| B-2 | B.10 | RNE の 3bit 一般式が subnormal 域 (代表点 4 / 2 / 1 点) を扱えない | 高 |
| B-3 | B.9 | `$past` の第 1 引数が部分選択の式。本文 10 章 運用ノート第四点に反する (処理系側は修正済みで実害は無く、規約との整合の問題) | 中 |
| B-4 | B.7 | `pack_fp32` が本文 5 章と同名で引数の意味が違う | 低 |
| B-5 | B.9 | SVA が未定義の識別子 (`last_seen_done` / `beat_odd`) を参照 | 低 |

B-1 と B-2 はどちらも E4M3 の subnormal 域で、**本文 7.2 節が E2M1 について
明示的に処理している論点の対応物が抜けている**という同じ形です。E2M1 のときに
確定表を置いたのと同様、E4M3 でも **subnormal 域を含む確定表**を用意していただけると、
実装側は迷わず写経できます。

方針そのもの (案A の採用、後段共有、s42 固定小数点、FP16 の exact 積) には異論ありません。
とくに B.6 の s42 設計と B.7 の exact 積は、リファレンスモデルをそのまま正解にできる
(方針3 が使える) 形になっており、検証計画 B.11 の Q2 / H1 が素直に書けます。
