## 3. 実装側で追従が必要な差分

Rev.1.2 が C8 に応えて観測ポートを正式に定義したため、現行実装との間に次の差分があります。
**仕様書側の問題ではなく、実装を追従させるべき項目**です。

| モジュール | ポート | 現行実装 |
|---|---|---|
| `mxfp4_bdp` | `sop_valid_dbg` / `exp_valid_dbg` | 未実装。TB が `dut.valid_q[2]` / `[3]` を階層参照 |
| `quant_encoder` | `tie_hit_dbg` / `quant_valid_dbg` | 未実装。TB が `enc.valid_q[]` を階層参照し、タイ判定も TB 側で計算 |
| `mxfp4_fp32_add_core` | `r_carry_ovf` | 未実装 (BDP から未使用のため省略していた) |

ポート化すると TB から RTL 内部名への依存が消えるため、実装を仕様書に合わせます。
あわせて `tie_hit_dbg` の生成ロジックを RTL 側へ移します
(タイ判定は 7.2 節の中点条件そのものなので、RTL に置く方が仕様との対応が明確です)。

なお 8.2 節の `KBLK ≥ 2` 制約について、現行実装は
`KB_W = (KBLK > 1) ? $clog2(KBLK) : 1` としており **`KBLK = 1` でも動作します**
(D4 で BDP 単体の KBLK=1/2/3 を検証済み)。仕様書の要求を満たしたうえで
より広い範囲に対応している形なので、実装はこのまま維持します。

## 図10 の内容確認

図10 (`fig10_handshake.png`) のタイミングを実装と照合しました。

| 信号 | 図10 | 実装 |
|---|---|---|
| `in_valid` / `a/b_block` | cycle 1〜3 に B0 / B1 / B2 | 一致 |
| `first` | cycle 1 | 一致 |
| `last` | cycle 3 | 一致 |
| `out_valid` / `result` | cycle 9 (last から 6 = LAT) | 一致 |
| `in_ready` | 常時 1 | 一致 (3.3 節の初期実装方針どおり) |

`last` から `out_valid` までが 6 サイクルである点は 8.4 節の図9 (last = cycle 5、
ovalid = cycle 11) とも整合しています。このタイミングは実装側で D4 (KBLK = 1/2/3 の
累積列) が毎回検証しており、`run_series` は `out_valid` が LAT より 1 サイクルでも
早い / 遅い場合に FAIL します。

Rev.1.0 のテキストアートは clk が 6 サイクル分しか描かれていないのに「last から LAT = 6
サイクル後」の `out_valid` を示しており、サイクル数を数えると合わない概念図でした。
図10 への置換で cycle 番号が明示され、実装との照合が機械的にできるようになっています。
