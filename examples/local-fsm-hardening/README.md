# 状態機械とカウンターを、ビットの反転から守る符号化を確かめる

権限を与える状態機械では、状態レジスタの1ビットが反転しただけで、鍵を確かめずに権限のある状態へ移ってしまう符号化があります。この例は、状態の符号を互いに3ビット以上離し、失敗回数のカウンターに補数の写しを持たせた鍵付きのロックを題材に、「どの状態のどの1ビットが、どのクロックエッジで反転しても、権限を与えず、次のエッジでエラー状態へ入る」ことを、シミュレーションの全数とフォーマルの証明で確かめる教材です。

同じロックを2進の符号で作ると、1ビットの反転で権限のある状態へ移る反例が出ます。2ビット以上の反転は保証の外として、どこまで守れて、どこから守れないかを分けて示します。

防御側の検証の教材です。故障を起こす方法は扱いません。反転は、検証用の入力`fault_xor`で、更新後のレジスタへ排他的論理和として入れます。実デバイスの放射線や電圧の揺らぎを再現したものではなく、ISO 26262などの規格への適合や、診断の網羅率の主張でもありません。冗長な符号化の考え方は、[OpenTitanのセキュアなハードウェア設計の指針](https://opentitan.org/book/doc/security/implementation_guidelines/hardware/index.html)を参考にしました。指針の本文は写していません。

近い例として、[ライフサイクル](../local-secure-lifecycle/README.md)は状態の符号を1ビット変えた故障注入、[TMRレジスタ](../local-tmr/README.md)は多数決による訂正、[リセット後の値の確定](../local-reset-x-formal/README.md)は2つの複製の比較による証明を扱います。この例は、検出して止めることを題材にします。

## 仕様

[`hardened_lock.sv`](rtl/hardened_lock.sv)は、次の4つの働く状態と、エラー状態を持つロックです。

| 状態 | 出力 | 次の状態 |
| --- | --- | --- |
| LOCKED | なし | `start`でCHECK。`key_ok`だけ、`relock`だけでは動かない |
| CHECK | `busy` | `key_ok`ならOPENで失敗回数を0に。違えば失敗回数を1増やし、`MAX_TRIES`回に達したらLOCKOUT、そうでなければLOCKED |
| OPEN | `grant` | `relock`でLOCKED。`start`は無視 |
| LOCKOUT | `lockout` | どの要求でも抜けない |
| ERROR | `alarm` | どの要求でも抜けない。リセットだけがLOCKEDへ戻す |

`grant`を出すのはOPENだけです。失敗回数は`fails`（2ビット）に出します。リセット（同期、Lowで有効）はどの状態からもLOCKEDと0回へ戻し、`fault_xor`より優先します。`MAX_TRIES`は1〜3です。

### 符号と検出の規則

`HARDENED=1`では、状態を6ビットの符号で持ちます。

| 状態 | 符号 | OPENとの距離 |
| --- | --- | --- |
| LOCKED | `001011` | 4 |
| CHECK | `010101` | 4 |
| OPEN | `111000` | － |
| LOCKOUT | `100110` | 4 |
| ERROR | `011110` | 3 |

4つの働く状態は互いに4ビット、ERRORはそれぞれから3ビット離れています。全0と全1は、どの状態の符号でもありません。距離3の組がすべてERRORを含むように割り当てたので、3ビット以下の反転で働く状態から別の働く状態へは移れません。

失敗回数は、2ビットの値と、その補数の写し（2ビット）の両方で持ちます。毎クロック、次の2つを確かめます。

- 状態の語が5つの符号のどれでもなければ、次のエッジでERRORへ入る。
- 失敗回数と写しが補数の関係になければ、次のエッジでERRORへ入る。

この2つの検査は、どの状態の遷移よりも優先します。権限は「OPENの符号と一致する」ときだけ与え、「ほかのどの状態でもない」という否定では判定しません。

`HARDENED=0`は、同じ動作を3ビットの2進の符号（LOCKED `000`、CHECK `001`、OPEN `010`、LOCKOUT `011`、ERROR `100`）と1つのカウンターで作った比較用の構成です。符号に当たらない語はERRORへ送りますが、LOCKEDとOPENが1ビットしか離れていません。

### 反転の入れ方

`fault_xor`（10ビット）は、上位から状態の符号6ビット、失敗回数2ビット、その写し2ビットの順に、通常の更新の後でレジスタへ排他的論理和として入ります。検証用の入力で、設計では0に固定します。`f_regs`は`FORMAL`のときだけある出力で、フォーマル用のハーネスが証明の補助に使います。

## 期待値と判定

期待値は、[`model.py`](model.py)の`Lock`が作ります。名前つきの4状態と整数の失敗回数だけで書いた「故障のないロック」で、符号もERRORも知りません。テストベンチも符号を知らず、出力だけを見ます。

各行には、入力、そのエッジで反転させるビット、エッジの後の出力の調べ方、故障のないロックの出力を書きます。

| 行の種類 | 調べること |
| --- | --- |
| 通常 | 出力が故障のないロックと完全に一致する。違えばその場で不合格 |
| 最初の反転 | リセット後の最初の反転。故障のないロックが与えない`grant`を出さない |
| 反転の後 | 次のリセットまで。最初の行で`alarm`が1になり、以後1のまま。`grant`は故障のないロックが与えるときだけ |
| 2回目の反転 | ERRORの中でのもう1回の反転。`grant`を出さない |

反転ごとの結果は、それを閉じるリセットまで集め、最後にまとめて判定します。権限の昇格（故障のないロックが与えない`grant`）、検出の失敗（ERRORへ入らない）、ERRORからの離脱の順に重く扱い、1つでもあればその名前で不合格にします。計画のすべての反転を数えたうえで判定するためで、途中で止めると後ろの反転の結果が分からなくなるからです。

符号そのものの性質は、`model.py`が別に数えます（セルフテストで確かめています）。

| 符号 | 反転のビット数 | 結果 |
| --- | --- | --- |
| 6ビット | 1、2 | 5状態のどの語でも、どの反転でも符号に当たらない（1ビット30通り、2ビット75通り） |
| 6ビット | 3 | 働く状態からは20通り中1通りだけERRORに当たり、ほかの状態には当たらない。ERRORからはOPENに1通り、ほかの働く状態に3通り当たる |
| 2進 | 1 | 15通り中2通りがOPENへ移る（LOCKEDから、LOCKOUTから）。7通りが別の働く状態へ気付かれずに移る |
| 失敗回数＋写し | 1 | 4通りとも写しと食い違う |
| 失敗回数＋写し | 2 | 6通り中2通り（値と写しの同じ位置）は食い違わない |

## 構成と計画

構成は`tries3`（`MAX_TRIES=3`）と`tries2`（`MAX_TRIES=2`）の2つです。

| ケース | 内容 | 種類 |
| --- | --- | --- |
| `scenarios` | 故障なしで、各状態での要求、無視される要求、失敗回数の上限ちょうどと1回手前、上限の後の要求、成功で0に戻ること、各状態からのリセット（36行／32行） | 通常 |
| `single-flips` | 働く状態と失敗回数のすべての組（`tries3`で8組、`tries2`で6組）で、状態を保つエッジと抜けるエッジの両方に、10ビットのそれぞれを1回ずつ反転する（160回／120回）。各反転の後、ERRORへ入るべきエッジ、`start`、`key_ok`、`relock`、3つ同時の要求を与えてからリセットする。OPENとLOCKED（0回）を保つ反転では、ERRORの中で同じビットをもう1回反転する（20回） | 通常 |
| `random-seed*` | ランダムな要求の中で、ときどきランダムなビットをランダムなエッジで反転し、数行のランダムな要求と、ときどきERRORの中での2回目の反転の後にリセットする | 通常 |
| `double-state-flips` | 保証の外：4つの働く状態で、状態の符号の2ビットの全15通りを同時に反転する（60回） | 診断（合格で終わる） |
| `double-counter-flip` | 保証の外：失敗回数とその写しの同じ位置を同時に反転する | 診断（`FSM_ESCALATE`で不合格になる） |
| `detect-mutation1`〜`8` | 変異を入れた回路に、`scenarios`と`single-flips`をつないだ計画を当てる | 変異 |

`double-counter-flip`では、上限の1回手前で失敗回数の値と写しの同じ位置が反転し、2つは食い違いません。故障のないロックは次の失敗でLOCKOUTへ入りますが、回路は1回少なく数えてLOCKEDへ戻り、続く正しい鍵でOPENになります。2ビットの反転で、上限を越えて鍵を試せるようになるということです。

## 要求と目標

[`requirements.json`](requirements.json)の7要求・23目標です。どの目標も、2構成とも固定の計画（`scenarios`と`single-flips`）だけで届きます。

| 要求 | 目標 |
| --- | --- |
| FSM-AUTH | LOCKEDからCHECK、`start`なしの鍵、正しい鍵でOPEN、`relock` |
| FSM-LIMIT | 失敗の後の再試行、成功で0回、上限ちょうどでLOCKOUT、LOCKOUTが要求で抜けない |
| FSM-RESET | OPENとLOCKOUTからのリセット |
| FLT-DETECT | 4つの働く状態それぞれでの状態のビットの反転、失敗回数とその写しの反転、10ビット×4状態とERRORの全組 |
| FLT-TIME | 状態が変わるエッジ、失敗回数が変わるエッジでの反転 |
| FLT-SAFE | OPENでの反転で権限を失う、ERRORが要求で抜けない、ERRORでの2回目の反転 |
| FLT-RECOVER | 反転の後、リセットで戻って再びOPENになる |

## 意図的な誤実装

| 変異 | 誤り | シミュレーション | フォーマル |
| --- | --- | --- | --- |
| 1 | LOCKEDの符号をOPENから1ビットの語にする（符号の距離を縮める） | `FSM_ESCALATE` | `ap_no_escalation` |
| 2 | 失敗回数と写しを比べない（検査を外す） | `FSM_ESCALATE` | `ap_detect` |
| 3 | ERRORを`relock`で抜けられる | `FSM_ESCAPE` | `ap_detect` |
| 4 | 符号に当たらない語を、黙ってLOCKEDへ戻す | `FSM_ESCALATE` | `ap_detect` |
| 5 | 上限の比較を1つずらす（`>`） | `FSM_STATE` | `ap_match` |
| 6 | 失敗回数と写しを、CHECKのときだけ比べる | `FSM_UNDETECTED` | `ap_detect` |
| 7 | 成功で失敗回数を0に戻さない | `FSM_FAILS` | `ap_match` |
| 8 | 権限を「ほかのどの状態でもない」で判定する | `FSM_ESCALATE` | `ap_no_escalation` |

2構成の16件を、すべて予定のラベルで検出します。いくつかの変異は、見た目の誤りより重い結果になります。

- 変異2：写しを比べないと、失敗回数の1ビットの反転で上限を越えて鍵を試せ、OPENへ届きます。検出の失敗にとどまりません。
- 変異4：LOCKOUTでの反転で語が符号から外れると黙ってLOCKEDへ戻り、続く正しい鍵でOPENへ届きます。
- 変異6：比べる状態を限ると、CHECK以外での反転を見逃します。

フォーマルでは、最も短い反例が先に見つかるので、変異2・4は昇格より前の`ap_detect`で落ちます。

## フォーマル検証

[`formal.py`](formal.py)は、[`fsm_hardening_formal.sv`](fsm_hardening_formal.sv)を共通のSBYランナーで検査します。反転のマスクは自由な入力なので、1つの証明が、すべての保持ビット、すべての状態、すべてのエッジを覆います。反転は、リセットの外ならどのエッジで何回起きてもよく、1エッジあたりのビット数だけを`FAULT_BITS`で制限します。参照は、状態を番号で書いた故障のないロックで、回路と符号の表を共有しません。

| 性質 | 内容 |
| --- | --- |
| `ap_match` | リセット後の最初の反転までは、出力が故障のないロックと一致する |
| `ap_no_escalation` | 反転があってもなくても、`grant`は故障のないロックが与えるときだけ |
| `ap_detect` | 最初の反転から2つ目のエッジ以降、リセットまで`alarm`が1。直前のエッジでさらに反転した場合を除く |

| タスク | 内容 | 結果 |
| --- | --- | --- |
| `single-flip-proof` | 1エッジあたり1ビットまで、10ビットのどれでも、何回でも | k帰納法（深さ3）で証明 |
| `scenario-cover` | 反転の後のリセットからのOPEN、LOCKOUT、OPENでの反転で権限を失う、失敗回数だけの反転の検出、ERRORでの2回目の反転 | 5目標に到達 |
| `double-state-flip-proof` | 保証の外：状態の符号だけに、1エッジあたり2ビットまで | 証明。符号が3ビット離れているため |
| `double-counter-flip-escalates` | 保証の外：どこにでも2ビットまで | 反例（`ap_no_escalation`。SBYの表示で`tries3`はステップ10、`tries2`はステップ8） |
| `triple-state-flip-escalates` | 保証の外：状態の符号だけに3ビットまで | 反例（`ap_no_escalation`、ステップ4）。最初の反転でERRORへ入り、次の3ビットの反転でERRORからOPENへ移る |
| `binary-code-escalates` | 2進の符号（`HARDENED=0`）に1ビット | 反例（`ap_no_escalation`、ステップ3） |
| `detect-mutation1`〜`8` | 上の表の変異に1ビット | 反例（上の表の性質） |

2構成×14タスクで28件です。`double-counter-flip-escalates`は、`ap_detect`を外して（`ESCALATION_ONLY=1`）権限の昇格まで反例を伸ばしています。外したままだと、最も短い反例は「検出されない」ほうになるからです。

証明には、補助の不変条件4つ（`ai_age`、`ai_clean`、`ai_first`、`ai_after`）を一緒に入れています。仮定ではなくアサーションで、ほかの性質と同じく証明されます。最初の反転の前は保持ビットが故障のないロックの符号と一致すること、最初の反転の直後はその差が`FAULT_BITS`ビット以内であること、その次からは状態がERROR（直前に反転したならERRORから`FAULT_BITS`ビット以内）であることを述べます。補助の不変条件は符号の表を名前で持つので、その表は回路・ハーネス・`model.py`の3か所にあり、セルフテストが一致を確かめます。補助なしでは、深さ3の帰納法は`ap_detect`で成立せず（UNKNOWN）、深さ8なら成立することを、手で1回確かめました。

## 確認範囲と残る制限

- 故障のモデルは、保持している10ビットの一時的な反転だけです。持続する縮退故障、組み合わせ回路（次の状態の計算、出力の判定）の故障、クロックやリセットの故障、入力の誤りは扱いません。検査の回路そのものが壊れる場合（例：比較器の縮退）も扱いません。
- 反転は「通常の更新の後に排他的論理和で入る」ものとして、リセットのエッジでは起きないとしています。
- 1ビットの保証は、状態とカウンターについてで、`key_ok`を作る鍵の比較の回路は対象外です。鍵の比較は外からの入力にしています。
- 2ビット以上の反転は保証の外です。状態の符号だけの2ビットは証明できましたが、カウンターを含む2ビットと、状態の符号の3ビットには反例があります。
- ERRORに入った後の振る舞いは「リセットまで止まる」です。エラーの記録、通知の回数、復帰の手順は扱いません。
- 単一クロック・同期リセット・2値の検査です。符号の割当ては教材のもので、合成ツールが状態機械を再符号化しないことは確かめていません（合成は扱いません）。
- シミュレーションでは、2進の符号の構成を動かしていません。2進の符号の反例は、フォーマルと`model.py`の表で示しています。
- 規格・指針の節番号とは照合していません。

2026-11-21に、macOS arm64、Python 3.13.15（フォーマルは3.14.7）、Icarus Verilog 14.0開発版（`ca6b8d3`）、YoWASP版Yosys 0.70とSBY、Z3 4.15.3で、次を実行しました。

- `formal.py`：2構成・28タスクが予定どおり（証明4、到達2、反例22）。証明は1タスク4〜11秒でした（ほかの実行と重なった状態）。
- セルフテスト16件：合格、skipなし。
- Verilator 5.052の`--lint-only --Wall`で、`hardened_lock`の既定構成、`MAX_TRIES=2`、`MAX_TRIES=1`、`HARDENED=0`が、変異0〜8のすべてで警告0件。
- 手で確かめた対照：補助の不変条件を外すと、深さ3の帰納法が成立せず、深さ8で成立すること（`tries2`）。

計画外の誤りを、作業用の写しのRTLへ10個入れて、固定の計画（`scenarios`と`single-flips`）とランダム（seed 17、300操作）を当てました。
