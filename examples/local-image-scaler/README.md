# 有理比の画像の縮小・拡大を、厳密な有理数のモデルと照合する

画像を3/4や5/3のような有理比で縮小・拡大する回路の教材です。補間は**最近傍（中心合わせ）**に絞りました。双線形の補間は、重みの丸めの決め方で期待値が変わり、ビット一致の判定と許容誤差の判定が混ざるためです。最近傍なら、出力の各画素がどの元画素から来るかが一意に決まり、ビット一致で判定できます。

誤りが出やすいのは、出力の画素の中心が元の画素の境界にちょうど乗る位置、比に応じて繰り返す・飛ばす位置、右端と下端、フレームの大きさを変えたとき、出力を待たされたときです。この例は、それぞれを固定シナリオに入れ、Pythonの`fractions.Fraction`で書いた厳密なモデルと1画素ずつ比べます。

入出力は、ほかの画像の例（[Sobel IP](../local-image-sobel/README.md)、[畳み込みの窓](../local-conv-window/README.md)）と同じ8ビットの画素のストリーム（`in_valid`・`in_pixel`・`in_ready`、`out_valid`・`out_pixel`・`out_last`・`out_ready`）です。

## 仕様

[`image_scaler.sv`](rtl/image_scaler.sv)は、`in_w`×`in_h`の元画像を`out_w`×`out_h`へ変えます。出力の画素(x, y)は、次の元画素を取ります。

```text
列 = floor((x + 1/2) × in_w ÷ out_w)      行 = floor((y + 1/2) × in_h ÷ out_h)
```

出力の画素の中心（x＋1/2）を元画像の座標へ写し、その点を含む元画素を選ぶ、という意味です。中心がちょうど境界に乗るときは、右（下）の画素を取ります。

回路は割り算をしません。列ごとに2つの整数を比べます。

| 値 | 意味 |
| --- | --- |
| `ax` ＝ (2x＋1)×`in_w` | 出力の中心の位置（2×`out_w`倍した単位） |
| `bx` ＝ 2×`out_w`×(p＋1) | 元の列 p の右端の位置（同じ単位） |

`ax < bx` なら出力 x は列 p を取り、`ax`に2×`in_w`を足します。そうでなければ p を1つ進め、`bx`に2×`out_w`を足します。両辺とも整数なので位相はずれず、出力`out_w`÷g 個ごと（g は2つの大きさの最大公約数）に、ちょうど最初と同じ位相へ戻ります。行も同じ規則で`ay`と`by`を比べます。

ストリームの流れは次のとおりです。

1. 待機中に、フレームの最初の画素を受け取ったときの`cfg_in_w`・`cfg_in_h`・`cfg_out_w`・`cfg_out_h`を取り込み、フレームの終わりまで保ちます。途中で入力が変わっても無視します。
2. 元画像の1行を行バッファへ受け取ります（その間`in_ready`は1）。
3. その行から作る出力の行をすべて出します（その間`in_ready`は0）。縮小では、出力の行を作らない元の行もあります。
4. 次の元の行へ進みます。最後の元の行を終えると待機へ戻ります。

大きさが0か、上限（`MAX_W`・`MAX_H`）を超えるときは、待機中に`cfg_error`を1にし、`in_ready`を0にして画素を受け取りません。`out_last`はフレームの最後の出力画素だけに付きます。

| 構成 | 上限 | 固定シナリオの行数 | 固定シナリオのフレーム・出力画素 |
| --- | --- | --- | --- |
| `max12` | 12×12 | 509 | 10フレーム・173画素 |
| `max24h6` | 24×6（2のべき乗でない幅） | 665 | 10フレーム・269画素 |

## 期待値と、位相の累積誤差

期待値は[`model.py`](model.py)の`resize`です。`Fraction(2x+1, 2) × Fraction(in, out)`の切捨てで元の座標を直接求め、回路の累算器は使いません。セルフテストは、回路と同じ比較の方法をPythonで書いたものが、1〜24のすべての大きさの組で`resize`と一致することも確かめます。

多くの画像処理回路は、比を固定小数点の「1画素あたりの位相の歩幅」にして足し続けます。歩幅の丸めの誤差は画素ごとに積み重なり、行の途中で選ぶ元画素がずれます。`model.py`の`first_drift`で、その位置を数えました（小数部のビット数ごとに、最初にずれる出力の番号）。

| 比（元→出力） | 4ビット | 6ビット | 8ビット | 10ビット |
| --- | --- | --- | --- | --- |
| 3→4 | ずれない | ずれない | ずれない | ずれない |
| 5→3 | 9 | 33 | 129 | 513 |
| 7→5 | 6 | 18 | 66 | 258 |
| 2→3 | 17 | 65 | 257 | 1025 |
| 4→3 | 1 | 1 | 1 | 1 |

3→4は歩幅0.75が2進数で割り切れるのでずれません。4→3は、出力1の中心がちょうど元の境界に乗るので、丸めた歩幅がわずかに小さいだけで、最初の数画素で左の画素を取ってしまいます。境界にちょうど乗る位置は、丸めに最も弱い位置です。この回路は整数の比較なので、どの比でもずれません。

## 要求と目標

6要求・28目標を、2つの構成とも固定シナリオだけで満たします（[`requirements.json`](requirements.json)）。25目標はPythonの計画が行に付けた札で、その行が検査を通ったときにだけテストベンチが出力します。残る3目標（入力の途切れ、出力中の入力の待ち、出力の逆圧）は、テストベンチが自分で観測して出力します。

| 要求 | 目標 |
| --- | --- |
| `SCALE-MAP` | 列と行の境界ちょうど、同じ元画素の繰返し（列・行）、元画素の飛越し（列・行）、位相が最初へ戻る位置 |
| `SCALE-EDGE` | 右端・下端が最後の元画素、1画素幅の元画像と出力、上限の幅の縮小・拡大 |
| `SCALE-RATIO` | 縮小、拡大、等倍 |
| `SCALE-SIZE` | 大きさの違うフレームを続けて処理、フレームの途中の大きさの変更の無視 |
| `SCALE-CONFIG` | 4つの大きさのそれぞれについて、0と上限を1つ超える値の拒否（8行。各行は1つの規則だけに反する） |
| `SCALE-STREAM` | 入力の途切れ、出力中の入力の待ち、出力の逆圧での保持、`out_last` |

固定シナリオのフレームは、3/4（両方向に境界ちょうど）、5/3（繰返し。元の幅が奇数なので境界には乗らない）、等倍、1画素幅、強い縮小（飛越し）、上限の幅の2つ、途中の大きさの変更、拒否の8行、拒否の後の正しい大きさ、上限の大きさから1画素への縮小です。

## テストベンチ

[テストベンチ](tb/image_scaler_tb.sv)は、行をすべて読んでから、入力側と出力側を同じクロックの繰返しで動かします。行の種類は3つです。

| 種類 | 列 | 意味 |
| --- | --- | --- |
| 大きさ | `in_w` `in_h` `out_w` `out_h` 旗 | 読んだ時点で入力へ出す。拒否の行は、それより前の出力をすべて受け取り、回路が待機に戻ってから、`cfg_error`と`in_ready`を確かめる |
| 画素 | 値、待ち、先頭、先行の出力数 | 待ちのクロックだけ`in_valid`を下げてから出す。フレームの先頭の画素には、それより前のフレームの出力の数を持たせる |
| 期待 | 値、`last`、待たせる数 | 出力が現れたら、決めたクロックだけ`out_ready`を下げてから受け取って比べる |

失敗のラベルは次のとおりです。テストベンチの時間切れ（`SCALE_TIMEOUT`）は、どの変異の予定にも使いません。

| ラベル | 検査 |
| --- | --- |
| `SCALE_DATA`・`SCALE_LAST` | 受け取った画素と`out_last`が期待と違う（Xを含む） |
| `SCALE_HOLD` | 待たせている間に、出力が消えたか変わった |
| `SCALE_CONFIG` | 拒否すべき大きさで、`cfg_error`が1でないか、`in_ready`が1 |
| `SCALE_FRAME` | 前のフレームの出力が出そろう前に、次のフレームの先頭の画素を受け取った（出力の受け取り待ちの1画素だけは許す） |
| `SCALE_EXTRA` | 期待が残っていないのに出力が出た（全行の後に、十分な時間を待って確かめる） |
| `SCALE_UNKNOWN` | 制御の出力がX |
| `SCALE_TIMEOUT` | 進まないまま一定の時間が過ぎた |

## 意図的な誤実装

| 変異 | 内容 | 検出 |
| --- | --- | --- |
| 1 | 列の比較を`ax <= bx`にする（境界ちょうどで左の画素） | `SCALE_DATA` |
| 2 | 列を左上合わせにする（`floor(x × in_w ÷ out_w)`） | `SCALE_DATA` |
| 3 | 2行目以降の出力の行で、列の位相を最初へ戻さない | `SCALE_DATA` |
| 4 | 行の比較を`ay <= by`にする（境界ちょうどで上の画素） | `SCALE_DATA` |
| 5 | 累算器を、最大の大きさが必要とする幅より1ビット狭くする | `SCALE_DATA` |
| 6 | `out_last`を毎行の終わりに付ける | `SCALE_LAST` |
| 7 | `out_ready`を見ずに出力を上書きする | `SCALE_HOLD` |
| 8 | 大きさをフレームの途中も入力から読む | `SCALE_DATA` |
| 9 | 大きさの上限を確かめない | `SCALE_CONFIG` |

2つの構成とも、9種類を固定シナリオで検出します（18件）。

変異1と4は、境界にちょうど乗る位置がないと見つかりません。元の大きさが奇数なら、(2x＋1)×`in`は奇数で、2×`out`×(p＋1)と等しくならないので、境界には決して乗りません。5/3のフレームだけでは見つからず、3/4のフレームが見つけます。

変異5は、上限に近い大きさのフレームでしか現れません。`max12`では累算器が9ビットから8ビットになり、セルフテストの計算では、誤るのは大きさの組（11, 12）・（12, 11）・（12, 12）だけです。そのうち（11, 12）と（12, 12）は、元の列の番号が回り続けて止まり、時間切れになります。時間切れで見つけたことにしないため、固定シナリオは誤った画素が出る（12, 11）のフレームを、止まる（12, 12）より先に置いています。`max24h6`では、元と出力の幅が22〜24の組で誤った画素が出ます。

## 実行方法

```sh
python3 examples/local-image-scaler/run.py --profile smoke --out artifacts/image-scaler-smoke
python3 examples/local-image-scaler/run.py --profile nightly --out artifacts/image-scaler-nightly
python3 -m unittest discover -s examples/local-image-scaler/tests
```

[共通シミュレーションランナー](../local-common/README.md)を使います。ランダムは、大きさ・画素・入力の途切れ・出力の待ちを乱数で決めたフレームを、smokeで4枚×1 seed、nightlyで12枚×3 seed流します。JUnitはsmoke 24件／nightly 28件（構成ごとに固定1、ランダム1／3、変異9と、要求の判定1）です。

## 確認範囲と残る制限

- 最近傍だけです。双線形などの補間、色の画像、行バッファを2本使う同時の受け取りと出力は扱いません。元の行を受け取る間は出力せず、出力する間は受け取らないので、処理の速さは最適ではありません。
- 大きさは8ビットの入力で、上限は`MAX_W`・`MAX_H`です。リセットはフレームの外でだけ確かめ、フレームの途中のリセットは確かめていません。
- 位相の累積誤差の表は、モデルの固定小数点の計算です。固定小数点の歩幅を使う回路は作っていません。
- 画像処理の規格や文献の補間の定義とは照合していません。中心合わせの式はこの教材で決めたものです。
- Linux、kirimasim、統合ランナー経由では実行していません。

## 確認記録

2026-11-21に、Python 3.13、Icarus Verilog 14.0開発版、Verilator 5.052で確認しました。

- smoke（seed 17・3・100）とnightly（`--timeout 60`、seed 17〜19）が合格し、2構成とも28目標に届きました。nightlyの`manifest.json`は約1.9 MBです。
- セルフテスト11件が合格しました（Icarusでの実行を含みます。Icarusがなければ失敗します）。
- RTLのlint（Verilator `--lint-only --Wall`）は、2構成×変異0〜9で警告0件です。

計画外の誤りを、作業用の写しのRTLへ10個入れて、2構成の固定シナリオにかけました。9個が不合格になりました。最初は「1画素幅の元画像でも行の取り込みに入る」誤りが時間切れでしか見つからなかったので、フレームの先頭の画素で前のフレームの出力の数を確かめる`SCALE_FRAME`の検査を足し、検査で見つかるようにしました。

| 誤り | 結果 |
| --- | --- |
| 行の位相の初期値を0にする、列の歩幅を1大きくする、行の終わりの判定を1つ早める、出力の有効を受け取りで下げない、画素を1つ前の番地へ書く | `SCALE_DATA` |
| 最後の元の行の判定を1つ早める | `SCALE_LAST` |
| 1画素幅の元画像でも行の取り込みに入る、出力中も入力を受け取る | `SCALE_FRAME` |
| 大きさ0の検査から出力の高さを外す | `SCALE_CONFIG` |
| リセットで`out_pixel`を0にしない | 合格（`out_valid`が0の間の値で、使われない） |
