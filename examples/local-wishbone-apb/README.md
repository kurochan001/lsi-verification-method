# WishboneからAPBへのブリッジを、待ち・エラー・途中で離れるマスターについて検証する

バスのブリッジは、2つのプロトコルの「待ち方」と「終わり方」の違いを埋める回路です。検証で見落としやすいのは、次の3点です。

- **途中で離れるマスター**：Wishboneのマスターは、応答を待たずにサイクルを終えられます（CYCを下げる）。APBは、選択した転送を途中でやめられません。ブリッジは、始めた転送を最後まで行い、その結果を誰にも返さないようにします。
- **待っている次の要求**：離れたマスターは、すぐ次の要求を出せます。前の転送がまだAPBで続いている間に、その応答を次の要求へ渡してしまう誤りが起きます。
- **意味のない値**：APBのPSLVERRとPRDATAは転送の最後のクロックでだけ意味を持ち、WishboneのSTBはCYCがなければ意味を持ちません。意味のないクロックの値に反応する誤りは、行儀のよい刺激では見えません。

この例は、Wishbone B4のクラシックの標準（単一サイクル）のスレーブ側と、APB4のマスター側を持つ小さなブリッジを、回路とは別の書き方のモデルと、期待値を使わないプロトコルの監視の両方で確かめます。既存のバス変換の例は[AHB／AXI4-LiteからAPBへのブリッジ](../local-bus-bridge/README.md)と[幅変換](../local-width-converter/README.md)で、Wishboneを扱う例はこれが最初です。位置付けは[バスプロトコルの検証手順](../../docs/method/bus-protocol-verification.md)にあります。

## 仕様

[`rtl/wb_apb_bridge.sv`](rtl/wb_apb_bridge.sv)は、データ幅32ビット、アドレス幅`AW`（既定16）のブリッジです。リセットは`rst_n`（Lowで有効、同期）で、両側に共通です。Wishboneのリセットは本来Highで有効ですが、ほかの例に合わせました。

扱うWishboneは、**クラシックの標準モード**だけです。マスターはACKかERRを受け取るまで要求を保ちます。パイプラインモード（STALL）、登録フィードバックのバースト（CTI・BTE）、RTY、タグは扱いません。

| Wishbone（スレーブ側） | APB（マスター側） | 対応 |
| --- | --- | --- |
| `cyc_i`・`stb_i` | `psel`・`penable` | 両方が1のクロックを要求とみなす |
| `we_i`・`adr_i`・`dat_i` | `pwrite`・`paddr`・`pwdata` | 受け付けたクロックの値を保持して出す。読出しでは`pwdata`は0 |
| `sel_i` | `pstrb` | 書込みではそのまま。読出しでは`pstrb`は0 |
| `ack_o` | `pready`（`pslverr`が0） | APBが終わった次のクロックに1回 |
| `err_o` | `pready`と`pslverr` | ACKの代わりに1回。読出しデータは0 |
| `dat_o` | `prdata` | ACKのクロックだけ。`sel_i`で選ばれなかったバイトは0 |

1つの転送は、次の順に進みます。待ちがなければ4クロックです。

1. **受付**：待機中に`cyc_i`と`stb_i`がそろったクロックで、要求を取り込みます。このクロックでは、まだ何も出しません。
2. **SETUP**：`psel`だけを1にします。1クロックです。
3. **ACCESS**：`penable`も1にして、`pready`が1になるまで待ちます。`pslverr`と`prdata`は、`pready`が1のクロックの値だけを取ります。
4. **応答**：次のクロックに、`ack_o`か`err_o`を1クロック出します。応答は、そのクロックに`cyc_i`と`stb_i`がそろっているときだけ出します。

選択していないクロックの`pwrite`・`paddr`・`pwdata`・`pstrb`は0にします。応答のクロックの次から、次の要求を受け付けます。

### マスターが途中で離れたとき

SETUPかACCESSの間に`cyc_i`が0のクロックが1つでもあれば、その転送は「離れた」ものとして扱います。

- APBの転送は、`pready`が来るまで続けます。書込みはAPB側で実行されます。取り消せません。
- 終わっても応答のクロックは作らず、すぐ待機へ戻ります。
- 離れたマスターが次の要求を出して待っていても、取り込むのは待機へ戻ってからです。待っている要求のアドレスやデータは、続いているAPBの転送に混ざりません。
- 応答のクロックでちょうど`cyc_i`が0になった場合は、応答を出さずに待機へ戻ります。

`cyc_i`を保ったまま`stb_i`だけを途中で下げるのは、クラシックの標準モードのマスターには許されない動作なので、扱いを決めていません（刺激にも入れていません）。

## 独立した期待値

[`run.py`](run.py)の`Plan`は、ブリッジの状態を持ちません。1つの転送を、要求の内容、APBの待ちのクロック数、マスターが離れるクロック、リセットのクロックから、**クロックの並び（時系列）として直接書き下します**。回路は4状態の状態機械なので、書き方が違います。たとえば「離れた転送には応答のクロックがない」ことを、回路は取消しのフラグと状態の遷移で、モデルは並びの長さで表します。

期待値とは別に、テストベンチ（[`tb/wb_apb_tb.sv`](tb/wb_apb_tb.sv)）が、期待値を使わない監視を毎クロック行います。

| 側 | 監視する規則 | ラベル |
| --- | --- | --- |
| APB | `penable`は`psel`と一緒にだけ出る。SETUPはちょうど1クロック。選択した転送は、`pready`まで`psel`・`penable`を保ち、`pwrite`・`paddr`・`pwdata`・`pstrb`を変えない。読出しの`pstrb`は0 | `WBA_APB_PROTOCOL` |
| Wishbone | ACKとERRは同時に出ない。要求のあるクロックにだけ出る。APBの転送が終わった次のクロックにだけ出る。2クロック続けて出ない | `WBA_WB_PROTOCOL` |
| 共通 | 出力にXがない | `WBA_UNKNOWN` |

モデルとの比較のラベルは、APB側の出力が`WBA_APB`、ACKとERRが`WBA_RESPONSE`、読出しデータが`WBA_DATA`です。比較は`!==`で行うので、出力がXでも不合格になります。テストベンチは1クロックに1行を与えるだけで、何かを待つループがないので、時間切れのラベルはありません。

### 監視だけでは見つからない誤り

監視は、プロトコルの規則に反した瞬間を見つけます。規則に反しない誤りは見つけません。これを確かめるため、モデルとの比較を止めた行（監視だけが判定する行）で、変異を入れた回路を毎回実行します。

| 変異 | モデルとの比較 | 監視だけ |
| --- | --- | --- |
| 1 離れた転送の応答を、待っていた次の要求へ返す | `WBA_RESPONSE` | **合格のまま** |
| 2 SETUPのクロックから`penable`を出す | `WBA_APB` | `WBA_APB_PROTOCOL` |
| 3 読出しでも`pstrb`を出す | `WBA_APB` | `WBA_APB_PROTOCOL` |
| 4 保持したアドレスの代わりに、今のアドレスを出す | `WBA_APB` | `WBA_APB_PROTOCOL` |
| 5 エラーをACKで返す | `WBA_RESPONSE` | **合格のまま** |
| 6 読出しデータを`sel_i`で絞らない | `WBA_DATA` | **合格のまま** |
| 7 `pready`を待たない | `WBA_APB` | `WBA_APB_PROTOCOL` |
| 8 応答のクロックの要求を、新しい要求として取り込む（転送が2回になる） | `WBA_APB` | **合格のまま** |
| 9 取消しのフラグを次の受付で戻さない（以後、応答しなくなる） | `WBA_RESPONSE` | **合格のまま** |

変異1は、この例でいちばん見てほしい誤りです。応答は「APBの転送が終わった次のクロック」に「要求のあるクロック」で出るので、2つのプロトコルの規則はどれも守られています。誤っているのは「どの要求への応答か」で、これは転送の対応を知っているモデルでなければ分かりません。変異8（1つの要求でAPBへ2回書く）と変異9（応答が来なくなる）も、どちらの規則にも反しません。

## 刺激

固定シナリオ（409行）だけで、26個の目標すべてに届きます。規則ごとに、その規則だけを試す行を持ちます。

- **通常の転送**：書込みと読出し、アドレスの両端（0と最大）、待ち0・1・3・4クロック。
- **バイト選択**：1レーンずつ、選択なし（0）、飛び飛び（5と10）を、書込みと読出しの両方で。
- **エラー**：書込みと読出し。待ちのクロックで`pslverr`と`prdata`を動かしても、結果が変わらないこと。
- **要求でも応答でもないクロック**：`cyc_i`だけ、`stb_i`だけ（アドレス・データつき）、選択していないときの`pready`・`pslverr`、SETUPのクロックの`pready`。
- **途中で離れるマスター**：離れるクロックを、SETUP、待ちの1クロック目と2クロック目、最後のクロック、応答のクロックの5通りにし、それぞれ、次の要求なし、読出しの要求が待つ、書込みの要求が待つ、の3通りと組み合わせます。待ち0の転送と、エラーで終わる転送でも行います。
- **連続する要求**：応答の次のクロックに次の要求を出す4件と、待機を1クロック挟む1件。
- **リセット**：転送の5つのクロックそれぞれでリセットし、直後の転送が正しく終わること。離れた後のリセットも1件。

ランダム試験は、要求、待ち（0〜5クロック）、エラー（約1/6）、離れるクロック、待っている要求、リセット、意味のないクロックの値を乱数で選びます。smokeは40転送×1 seed、nightlyは300転送×3 seedです。

## 要求と目標

要求は[`requirements.json`](requirements.json)の6件、目標は26個です。目標は、テストベンチが端子の値から数えます。変異と監視だけの実行は、目標に数えません。

| 要求 | 内容 | 目標 |
| --- | --- | --- |
| `WBA-TRANSFER` | 1つの転送が1つのAPBの転送になり、1回だけ応答する | 8 |
| `WBA-ERROR` | `pslverr`は最後のクロックの値だけを取り、ERRで返す | 2 |
| `WBA-SELECT` | `sel_i`を`pstrb`へ渡し、読出しでは0にして、データを絞る | 4 |
| `WBA-IGNORE` | 意味のないクロックの値に反応しない | 4 |
| `WBA-LEAVE` | 離れた転送を最後まで行い、応答しない。待っている要求は後で受け付ける | 6 |
| `WBA-RESET` | どのクロックのリセットからも復帰する | 2 |

## 構成と件数

構成は、アドレス幅16ビットの`aw16`と、8ビットの`aw8`の2つです。1構成あたりのケースは、固定1、ランダム1（nightlyは3）、変異の検出9、監視だけでの検出4、監視だけでは見つからないことの診断5です。JUnitは、要求と目標の判定を構成ごとに1件加えて、smoke 42件、nightly 46件です。

## 実行

```sh
python3 examples/local-wishbone-apb/run.py --out artifacts/local-wishbone-apb-smoke
python3 examples/local-wishbone-apb/run.py --profile nightly --seed 17 --out artifacts/local-wishbone-apb-nightly
python3 -m unittest discover -s examples/local-wishbone-apb/tests
```

`--configuration aw8`で1構成だけ、`--demo-bug 1`〜`9`で変異を入れた回路に通常の試験を当てられます（終了コード1になります）。保存される証跡は、[共通シミュレーションランナー](../local-common/README.md)のものです。セルフテストは13件で、Icarus Verilogが必要です（ないときはskipせずに失敗します）。

## 確認範囲と残る制限

- 扱うのはWishbone B4のクラシックの標準モードだけです。パイプラインモード、バースト、RTY、タグ、データ幅の変換、複数スレーブの選択は扱いません。
- マスターは規則を守る前提です。`cyc_i`を保ったまま`stb_i`だけを途中で下げる、応答の前に要求の内容を変える、といった動作への反応は決めておらず、確かめていません。
- 離れた転送の書込みは、APB側で実行されます。これは仕様として決めたことで、取り消す手段はありません。離れた転送のエラーは、どこにも知らせません。
- APB側の`pprot`と、スレーブが応答しないときの時間切れはありません。`pready`が来なければ、ブリッジは待ち続けます。
- モデルと回路は、同じ人が同じ仕様から書いています。外部の実装や検証用IPとは照合していません。
- 仕様の元は、OpenCoresのWishbone B4と、ArmのAPB（IHI 0024）です。本文は写していません。節番号とは照合しておらず、ここに書いた規則の出どころは「未照合」です。
- フォーマルは使っていません。規則は、固定シナリオとランダム試験の範囲で確かめたものです。
- Linuxとkirimasimでは実行していません。テストベンチは`string`、`$fscanf`、`$value$plusargs`を使い、階層参照と`force`は使いません。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13、Icarus Verilog 14.0開発版で、次を確かめました。

- smoke（seed 17・3・100）とnightly（seed 17、`--timeout 60`）が合格。JUnitは42件と46件、2構成とも26／26目標で、全目標に固定シナリオだけで届きます。nightlyの1ケースは最長で約0.1秒、`manifest.json`は約8 MBです。
- 変異9種類を、2構成で18件、予定のラベルで検出。監視だけの実行は、変異2・3・4・7を検出し、変異1・5・6・8・9は合格のまま残ります（上の表のとおり）。
- セルフテスト13件が合格。
- RTLは、Verilator 5.052の`--lint-only --Wall`で、2構成・変異0〜9の全20通りが警告0件。`tools/check_tb_races.py`の候補は0件。

変異とは別に、作業用の写しのRTLへ小さな誤りを21個入れて、smokeにかけました。19個は、固定シナリオが2構成とも不合格にしました（`cyc_i`か`stb_i`の片方だけで受け付ける、離れたことをSETUP・待ち・最後のクロックのどれかで見落とす、応答を要求で絞らない、SETUPの`pready`で終える、離れた転送を途中でやめる、アドレスの最上位ビットを落とす、など）。合格のまま残った2個は、動作に差が出ない誤りです。

- 読出しデータを、最後のクロックだけでなくACCESSの毎クロックで取り込む。最後のクロックでも取り込むので、使う値は同じです。
- リセットで取消しのフラグを戻さない。フラグは受付のたびに戻すので、通常の回路では結果が変わりません（変異9と組み合わせたときだけ、Xが出力に出ます）。
