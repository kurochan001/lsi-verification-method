# 内部スキャンと、縮退故障を検出するATPGパターンを検証する

[JTAG TAP](../local-jtag-tap/README.md)はチップ端子の境界走査、[MBIST](../local-mbist/README.md)はメモリセルの故障を扱います。この例は、内部のフリップフロップをスキャンチェーンで制御・観測し、組合せ回路の単一縮退故障（stuck-at-0／1）を検出するパターンを生成します。ATPGは、自動テストパターン生成（Automatic Test Pattern Generation）の略です。スキャンの基本構造は[OpenROADのDFT資料](https://openroad.readthedocs.io/en/latest/main/src/dft/README.html)を参照しています。

## ロード・キャプチャ・アンロード

```mermaid
flowchart LR
  accTitle: ATPGパターンを実際のスキャンチェーンで検証する
  accDescr: Pythonで入力を全数調査し、故障を検出するパターンを選ぶ。RTLへ初期状態をシフト入力し、機能動作を1クロック実行して結果を取り込み、シフト出力する。無故障と故障時の応答差をシリアル出力で観測する。
  A["64入力を全数調査<br/>14単一縮退故障"] --> P["貪欲法で3パターンを選ぶ"]
  P --> L["4ビットをシフト入力"] --> C["機能動作を1クロック<br/>応答をキャプチャ"]
  C --> U["4ビットをシフト出力"] --> O["無故障時の応答との差を観測"]
```

回路は4個のフリップフロップと2ビットの一次入力を持ちます。`scan_enable=1`ならシフトし、0なら組合せ回路の出力を取り込みます。`forward`では`q[3]`、`reverse`では`q[0]`からシフト出力します。リセットは全フリップフロップを0にします。

[`atpg.py`](atpg.py)は、初期状態16通り×一次入力4通りを全数調査します。7個の名前付き内部ノードの、それぞれsa0／sa1の計14故障を対象にし、無故障と異なるキャプチャ値を作れる入力を調べます。残る故障を最も多く検出する入力を順に選び、3パターンへまとめます。最小パターン数を証明するアルゴリズムではありません。

意図的に、ノード`n5`を論理0としています。`n5`のsa0は冗長故障であり、64入力のどれでも応答を変えません。生成したパターンは、**全14故障のうち13故障、検出可能な13故障のすべて**を検出します。冗長故障を検出成功に含めません。対象は指定したノード出力の単一故障で、全ゲート端子・配線分岐・スキャンセルを網羅した故障リストではありません。

テストベンチは、ロード・キャプチャ・アンロードをRTLで実行し、内部状態とシリアル出力の両方を比較します。故障の検出数は、アンロード時の**実際の`scan_out`**が無故障時と異なった故障の種類数です。Pythonモデルの検出数をそのままログに出すものではありません。無故障の期待値は論理式をまとめた別の式、故障時の期待値は名前付きノードの故障モデルで計算します。

## 実行と検出する誤り

Python 3.10以上とIcarus Verilogを使い、リポジトリのルートで実行します。

```sh
python3 examples/local-scan-atpg/atpg.py
python3 examples/local-scan-atpg/run.py
python3 examples/local-scan-atpg/run.py --profile nightly
python3 -m unittest discover -s examples/local-scan-atpg/tests -v
```

最初のコマンドは、入力数・故障数・検出可能数・冗長故障・選んだパターンをJSONで表示します。`run.py`は毎回パターンを生成し、通常の64入力と全14故障×3パターンを必ず試します。その後、ランダムな機能／シフト動作を加えます。

構成は`forward`・`reverse`です。JUnitはsmoke 14件／nightly 18件、通常ケースの目標は10個で、各ケースの`COUNT detectable_faults=13`も照合します。判定・証跡は[共通手順](../local-common/README.md)を使います。

| 変異 | 誤り | 検出ラベル |
| --- | --- | --- |
| 1 | シフト方向を逆にする | `SCAN_SHIFT` |
| 2 | scan_enableを無視して機能動作する | `SCAN_SHIFT` |
| 3 | キャプチャしても状態を更新しない | `SCAN_CAPTURE` |
| 4 | `n3`への故障注入の接続を外す | `SCAN_CAPTURE` |

変異4は、DUTではなく検証用の故障モデルへの誤りです。`--demo-bug 1..4`は通常ケースにも誤りを入れ、終了コード1を確認します。7セルフテストには、無故障式とノードモデルの全64入力の一致、パターンの故障検出集合、**全64入力×14故障を両シフト方向のRTLで実行**する照合、非対称なビット列のシリアル順序を含みます。

2026-10-31に、Python 3.14.7・Icarus Verilog 14.0開発版で2構成のsmoke／nightlyと7セルフテストが成功しました。Verilator 5.052でRTLの全構成・変異0〜4をlintしています。

## 確認範囲

明示的に書いたスキャン回路と故障注入点を持つ、小規模なデジタル教材です。OpenROADを実行してスキャン挿入した結果や、製造テストのサインオフではありません。合成後の故障リスト抽出・故障等価性・複数故障・遷移故障・ブリッジ故障・at-speed試験・テスト電力・ATE波形は対象外です。`fault_*`は教材の検証用ポートであり、製品のテストアクセス方式ではありません。
