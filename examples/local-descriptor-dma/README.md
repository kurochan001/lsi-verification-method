# リング式ディスクリプタと既存DMAを結合検証する

新しいリング制御がAXI4でディスクリプタを読み、[既存APB DMA](../local-dma/README.md)へ実際に設定してコピーを実行します。ディスクリプタ取得とコピーの読出しが、同じ[AXI4 RAM](../local-axi4/README.md)を直列に共有します。

```text
start(head,count) → AXIでディスクリプタ4ワードを取得
                             ↓
                 APBで既存DMAを設定・開始
                             ↓
                 AXIコピー → 状態読出し
                             ↓
          次のリング位置へ進む／終了・エラー・中断＋IRQ
```

## 範囲と停止方針

リング深さ2／4、各エントリ16バイト、先頭0x1800です。内容は転送元・転送先・ワード数・flagsの4ワードで、flags=1だけを実行対象にします。startでheadと件数を指定し、件数分を順に処理します。headはリング内、件数は0〜深さで、0件は転送なしで完了します。flagsの所有権返却、動的なtail追加、リンクリストは実装しません。

完了数は正常に終わったディスクリプタだけを数えます。取得エラー・flags不正・コピーのR/Bエラーでは後続へ進みません。Bエラーで既に反映された書込みは残り、前の正常完了分も戻しません。abortは発行したAXI要求を取り消さず、現在の取得・コピーの規則に従って排出してから停止します。

教材の試験は、各スロットで異なる1〜4ワードを、重ならない領域へコピーします。既存コピーコアの一般的な境界・サイズ制限は元の例を参照してください。入力やレジスタ配置は本教材独自のものです。

## 検査

Pythonが順番・完了数・エラー・中断・取得数・書込みの残るスロットを独立に計算します。SVは取得の実アドレス・長さ、コピー先・ID・Wデータ・ストローブ・最終ビート、最終状態・IRQ、RAM全8192バイトを照合します。ディスクリプタ自身や転送先以外の変化も失敗です。

空／全件／周回、4種類のエラー、取得／コピー中のabort、head・件数の不正、動作中リセットと再実行を各13目標で確認します。ring2は待ちなし、ring4-stallsはAR/AW/Wの受付を周期的に止めます。4変異はリング位置の進め方、flags無視、IRQ欠落、コピーのデータ破損です。

```sh
python3 examples/local-descriptor-dma/run.py
python3 examples/local-descriptor-dma/run.py --profile nightly
python3 -m unittest discover -s examples/local-descriptor-dma/tests -v
```

[共通手順](../local-common/README.md)を使います。smoke 20操作、nightly 160操作×3 seedに固定12操作を加えます。2構成のJUnitは14／18件、確認テストは5件です。キャッシュ・CPU・OS・仮想アドレス・任意個数の未完了要求を含むDMAシステムの検証ではありません。
