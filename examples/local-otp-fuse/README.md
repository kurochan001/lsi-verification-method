# 1回だけ書けるメモリ（OTP）の書込み・冗長・電源断を検証する

OTP（One-Time Programmable、ヒューズ）は、チップの製造後に1回だけ書ける記憶です。鍵、設定、トリミングの値、ライフサイクルの状態を持たせます。セルは0から1へしか変わらず、元に戻せません。書込みには長いパルスが要り、その途中で電源が切れることもあります。そのため、普通のレジスタにはない次の点を確かめる必要があります。

- 書き込んだ後は、それ以上書き換えられないこと（ロック）。
- セルの不良（1にならない、最初から1）を、冗長で吸収できること。
- 書込みの途中で電源が切れても、中途半端な値を「書けた」と扱わないこと。
- セキュリティに関わる状態は、電源を切って書込みを止めても、緩い側へ戻らないこと。

この教材では、データを3つ写して多数決で読むOTPのコントローラーを作り、電源断と不良セルを模したセルの配列をテストベンチに置いて確かめます。ライフサイクルの状態をOTPから読み込み、[セキュリティ・ライフサイクルの例](../local-secure-lifecycle/README.md)のレジスタ回路へ渡す小さな上位もこの例の中に書き、接続の効果も確かめます。ライフサイクルの例のファイルは変えずに使います。

セルの配列は、物理の振る舞いを単純にした模型です。実際のOTPマクロの電気特性、書込み電圧、セルの劣化、読出しの余裕（マージン）は扱いません。位置付けは[セキュリティの検証手順](../../docs/method/security-verification.md)と[メモリの検証手順](../../docs/method/memory-verification.md)にあります。

## 仕様

1語（WBビット）ごとに、セルの配列に4行を持ちます。

| 行 | 内容 |
| --- | --- |
| 0・1・2 | データの3つの写し |
| 3 | ロックの行。ビット0〜2がロックの3つの写しで、ほかのビットは使わない |

### セルの規則（テストベンチの模型）

- セルは0から1にしか変わりません。書込みのパルスが、同じ行・同じマスクのまま`PROG`サイクル続いたときだけ、マスクの1のセルが1になります。
- 途中で切れたパルス（電源断）は、何も書きません。
- 不良セルは、1にならないもの（0に固着）と、最初から1のもの（1に固着）の2種類です。

### コントローラー（[`otp_ctrl.sv`](rtl/otp_ctrl.sv)）

| 要求 | 動作 | 応答 |
| --- | --- | --- |
| 読出し | ロックの行と3つの写しを読む | `resp_data`＝ビットごとの多数決、`resp_any`＝3つのOR、`resp_corrected`＝写しが一致しない、`resp_locked`＝ロックの多数決 |
| 書込み（ロック済み） | 何も書かない | `resp_err`と`resp_locked`が1 |
| 書込み | 3つの写しを1行ずつ書き、読み戻す。多数決が書いた値と同じならロックの行を書く | 成功：`resp_locked`が1。読み戻しが違えば`resp_err`が1で、ロックしない |

決めたことは次のとおりです。

- **ビットは消せない**：書込みは、すでに1のビットを0にできません。違う値が半分書かれた語へ書くと、読み戻しが違って`resp_err`になり、ロックしません。
- **ロックは最後**：ロックの行は、3つの写しを書き、読み戻しで確かめた後にだけ書きます。電源が切れてロックの前で止まった語は、ロックされずに残り、同じ値をもう一度書けば完成します。
- **リセットは非同期**：電源断もリセットとして見えます。パルスはその瞬間に止まり、セルは書けた分だけ残ります。
- **応答までのクロック数**：要求を受けたクロックの立上りから数えて、読出しは4、ロック済みへの書込みは1、成功した書込みは4×PROG＋4、読み戻しの違う書込みは3×PROG＋4です。写しの行rは(r＋1)×PROG＋1で書け、ロックの行は4×PROG＋4で書けます。モデルはこの時刻表で、電源断の後にどの行が書けたかを決めます。
- **受付**：処理中は`req_ready`が0です。テストベンチは、処理中に次の要求を出したままにして、受け付けられないことも確かめます。

### ライフサイクルの読込み（[`otp_lifecycle_top.sv`](rtl/otp_lifecycle_top.sv)）

語0・1・2がライフサイクルです。語iを書くと、1段進みます。リセットのたびに、読込み回路が3語を読み、終わるまでレジスタ回路をリセットに留め、ホストからOTPを使えなくします。

- **段の数え方**：どれかの写しのどれかのビットが1なら、その段は書かれたと数えます。電源が切れて1つの写ししか書けなくても、段は進みます。セキュリティに関わる状態は、電源を切っても緩い側へ戻らないようにするためです。データの語は多数決で読むのと、ここで扱いを変えています。
- **状態**：書かれた段がなければ0（TEST）、語0なら1、語0・1なら2、語0・1・2なら3です。間の抜けた組合せ（語0なしで語1など）は、最も制限の強い3にします。
- **接続の効果**：レジスタ回路では、TESTのときだけ鍵（KEY0）を書けます。

## 確かめること

### テストベンチの模型が、モデルを使わずに確かめる規則

| 検査ラベル | 規則 |
| --- | --- |
| `OTP_RESET` | リセット中（電源断の間）にパルスを出さない |
| `OTP_PULSE` | パルスの長さは、電源断で切れたとき以外、ちょうどPROGサイクル |
| `OTP_LOCKED` | ロック済みの語の行にパルスを出さない |
| `OTP_ORDER` | ロックの行のパルスは、その書込みで3つの写しを書き終えた後 |
| `OTP_MASK` | ロックの行のパルスは、ロックの3つのセルだけを書く |

### モデルとの比較

| 検査ラベル | 内容 |
| --- | --- |
| `OTP_DATA` | 応答の多数決とOR |
| `OTP_ERR`・`OTP_FLAG`・`OTP_STATUS` | 応答の誤り・写しの不一致・ロック |
| `OTP_LATENCY` | 応答までのクロック数 |
| `OTP_READY`・`OTP_RESP` | 処理中と読込み中は受け付けず、空いていれば受け付ける。応答は1サイクルだけ |
| `LC_STATE` | 読込み後のライフサイクル |
| `LC_LOAD` | 読込み中はレジスタ回路がリセットに留まり、鍵の書込みが無視される |
| `LC_ACCESS` | 鍵の書込みと読出しの可否と値 |
| `OTP_TIMEOUT`・`OTP_X` | 応答や読込みが終わらない（検査とは別のラベル）、Xが出る |

### 固定シナリオと目標

固定シナリオは、両構成とも54行です。空の語の読出し、処理中の要求を待たせた書込み、ロック済みへの書込み、写しの1つの0固着と1固着、2つの写しの同じビットの0固着（保証の外で、読み戻しが違う）、最上位ビットだけが違う読み戻し、ロックの行の0固着と1固着、電源断（写しの途中、ロックのパルスの途中、ロック済みの語）、電源断の後の書き直し、違う値の書き直し、ライフサイクルの電源断での前進、段の抜け、各段での鍵の書込みを含みます。

[要求カタログ](requirements.json)は5要求・19目標で、どちらの構成でも固定シナリオだけで19目標に届きます。ランダムな刺激は、開始時に最大3個の不良セルを置き、読出し・書込み・電源断（任意のクロック数で）・リセット・鍵の操作を混ぜます。完了の件数は、行数、読出し、書込み、断られた書込み、電源断、リセットに加えて、模型が数えた完全なパルスの数も照合します。

## 7つの誤りと、見つける検査

| 番号 | 誤り | 検査 |
| --- | --- | --- |
| 1 | 書込みがロックを見ない | `OTP_LOCKED` |
| 2 | 読出しが写し0だけを使う | `OTP_DATA` |
| 3 | 写しの不一致を、写し0と1だけで判定する | `OTP_FLAG` |
| 4 | ロックの行を、データより先に書く | `OTP_ORDER` |
| 5 | パルスが1サイクル短い | `OTP_PULSE` |
| 6 | リセット中も、パルスが次のクロックの立上りまで続く | `OTP_RESET` |
| 7 | ライフサイクルの段を、多数決で数える | `LC_STATE` |

- **変異4**は、電源が切れなければ、最後にできあがる値は正しい回路と同じです。電源断がロックとデータの間に来ると、未完成のデータのままロックされ、二度と直せません。模型の規則が、順序そのものを見つけます。
- **変異7**は、データの読み方としては正しい多数決です。ライフサイクルの書込みを1つの写しの後で止めると、多数決では段が進まず、TESTのまま鍵が書けます。電源を切ってセキュリティの状態を巻き戻せる、という誤りです。

`--demo-bug 1`〜`7`で、正常回路の計画に誤りを入れられます。

## 確認範囲と残る制限

- **模型の単純化**：パルスは、全部書けるか何も書かないかのどちらかです。実際のセルの、書込みの弱い状態や読出しの余裕は扱いません。書込みの電圧、パルスの電流、読出しの電気的な条件も扱いません。
- **ロックの応答**：書込みの成功でロックの行を書いた後、ロックを読み戻しません。ロックの3つのセルのうち2つが0に固着していると、応答は「ロック済み」でも、実際にはロックされません（固定シナリオでは扱っていない）。
- **1ビットの訂正だけ**：多数決は、1つのビット位置の1つの写しの不良を吸収します。同じビット位置の2つの写しの不良は保証の外で、読み戻しで書込みを断ります。
- **ライフサイクル**：段は進むだけで、戻す操作はありません。段の意味は、レジスタ回路のTESTとそれ以外だけです。レジスタ回路のデバッグ鍵やタンパーは、この例では使っていません。
- **出典**：OTPやライフサイクルの仕組みは、特定の製品や規格の写しではなく、この教材の仕様です。
