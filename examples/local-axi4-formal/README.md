# AXI4回路の制御証明・データBMC・到達性

[AXI4 RAM](../local-axi4/README.md)そのものを小さいメモリ構成で検証します。制御の非有界証明と、条件を絞ったデータの有界検査を分けるローカル教材です。全AXI4やDMA・インターコネクトの証明ではありません。

## 準備と実行

[共通フォーマル手順](../local-formal-common/README.md)で固定版のYoWASP・Z3を準備し、activateしてから実行します。

```sh
python3 examples/local-axi4-formal/run.py --out artifacts/axi4-formal
python3 examples/local-axi4-formal/run.py --configuration bytes16 --task safety-proof
python3 -m unittest discover -s examples/local-axi4-formal/tests -v
```

`bytes16`／`bytes32`の2構成。データ幅32ビット、2ビットID、INCR 1／2ビート、各方向2件までの未完了転送です。アドレス入力も各メモリに合わせて4／5ビットに縮め、RTLの13ビットポートへゼロ拡張します。8KiB・4ビートまでのシミュレーション構成全体を証明した結果ではありません。

## タスクと保証範囲

各構成9タスク、計18件のJUnitを出します。

- `safety-proof`：B／Rの保持、リセット、受付から最終応答までの件数と上限、書込みの未処理件数＋完了応答の保存、リングポインター等の補助不変条件、計11個のassertを非有界に証明します。
- `data-bmc`：ID、LAST、RESP、任意に選んだ1バイトのデータ比較を加え、計15個を既定深さ12まで検査します。**このタスクは、読書きを合わせて1件ずつ完了させる入力へ制限**します。複数未完了取引の全データ整合性の証明ではありません。
- `scenario-cover`：2件の書込み受付、2件の読出し受付、W先行、B／R待ち、2ビート読出し、ゼロWSTRB、未完了時のリセット、復帰の9目標を到達確認します。こちらはデータBMCの直列化制約を入れません。到達経路でもデータassertを有効にしますが、到達だけで任意の並行入力列を証明したとは扱いません。
- `detect-mutation1..4`：データ反転、BIDの誤り、RLAST反転、WSTRB無視について、予定したデータ／ID／LAST assertの反例を要求します。
- `overconstrained-proof`／`detect-overconstraint`：常時リセットという過剰な仮定で証明はPASSしても、全正常目標が深さ12で未達になることを確認します。

RTLに追加した`FORMAL`専用の不変条件もassertとして証明します。assumeで成立させるものではありません。通常のシミュレーション動作は変えません。

## 仮定・抽象化・期待値

共通の仮定は最初のエッジでのリセット、AW／W／ARが待たされたときのVALID・ペイロード保持です。BREADY／RREADYに公平性の仮定はありません。

制御証明では、メモリ読出し値を任意の値としてレジスタへ取り込む**過大近似**を使います。取込み後の保持や受付数は元の制御です。値を固定して正しく見せる手法ではなく、この証明でデータの正しさを主張しないための抽象化です。制御タスクでは非整列・領域を越える要求も禁止しません。

データBMCと通常coverでは、実際のメモリを使います。整列・領域内・長さ1／2・AWLENと整合するWLASTを仮定します。データBMCにはさらに、AWとARを同時に出さず、未完了がある間は次のアドレスを出さない3条件を加えます。これらはマニフェストとコンパイル済みモデルで確認できます。

参照側は受付したAW／ARの番地・長さ・IDを別キューへ保存します。任意の定数`watched_byte`で1バイトを選び、WSTRBで許可された書込みだけ期待値を更新し、そのバイトを含む読出しと比較します。選択を特定番地へ固定していないため、各メモリ内の任意のバイトが検査対象になれます。読出しのスナップショットは同じエッジの書込みより前の値という、元RTLの動作に合わせています。

単一クロック・2値・`async2sync`によるサンプリング時のリセットです。短パルス、X/Z、CDC、物理タイミング、無限時間の完了性は対象外です。

## 確認と証跡

2026-10-27に固定版ツールとPython 3.14.7で全18タスクが予定どおりの結果となり、通常coverは9×2＝18目標、変異は4×2＝8反例を確認しました。ランナーとは別に、計画・制約・対象範囲を確認する3テストがあります。保存と厳密な終了判定は[共通手順](../local-formal-common/README.md)を参照してください。
