# 合成できる自己判定テストベンチを、RTLと合成後のネットリストの両方で確かめる

FPGAの試作や実機の評価では、シミュレーションのテストベンチは使えません。この例は、刺激の生成・応答の圧縮・合否の判定をすべてRTLで書いた「合成できるテストベンチ」です。LFSRが小さなALUへ刺激を与え、MISRが全応答を16ビットの署名へ圧縮し、比較器が最後の署名を1ビットの合否にします。遅延、ファイル操作、`$display`を持たないので、同じ記述をシミュレーションでもFPGAでも使えます。

確かめることは3つです。

- **合成できて、構造が残ること**：Yosysで汎用ゲートへ合成し、フリップフロップの数が設計のレジスタの数とちょうど一致することを確かめます。観測されない回路は合成で消えるので、数が減れば、テストベンチの一部が実機に載っていないことになります。
- **ネットリストでも同じ結果になること**：合成したネットリストを、RTLと同じテストベンチと同じ期待値でシミュレーションします。
- **何が見えて、何が見えないか**：実機では合否のビットしか見えないことが多くあります。合否だけを見る「チップの見え方」と、刺激・応答・署名まで見る「全部の見え方」を分け、署名の別名（エイリアシング）で誤りが見えなくなる場合を示します。

FPGA・エミュレーター・実チップでは、何も実行していません。試作と実機の評価で、シミュレーションと何が違うかは、[試作と実機評価の手順](../../docs/method/prototyping-and-post-silicon.md)にまとめています。製造試験のためのLBISTは[LBISTの例](../local-lbist/README.md)が扱います。この例は、自己判定の仕組みを試作の検証に使う場面に絞り、合成後のネットリストでの確認、2つの見え方の比較、別名の確率の数え上げを加えています。

## 仕様

| 部品 | 動作 |
| --- | --- |
| LFSR（16ビット） | 右シフトで、新しいビット15は、ビット0・2・3・5の排他的論理和（x^16＋x^14＋x^13＋x^11＋1）。0以外の65,535状態を1周する。開始のたびに種`SEED`から始め、1パターンごとに1つ進む |
| ALU（試験の対象） | 入力は`a = lfsr[7:0]`、`b = lfsr[15:8]`、`op = {lfsr[12], lfsr[3]}`。0が加算、1が減算（桁上げのビットは借りなし）、2がAND、3がXOR（桁上げは0）。結果の9ビット`{carry, value}`をレジスタに入れる |
| MISR（16ビット） | 左シフトし、ビット15が出るときに`0x1021`を戻し、応答の9ビットを下位へ足す。初期値は0 |
| 制御 | アイドルの`start`で開始する。`PATTERNS`個のパターンを1クロックに1つずつ与え、ALUの結果は1クロック遅れて署名へ入る。最後の応答の次のクロックで`done`を立て、最終の署名が`GOLDEN`と一致したときだけ`pass`を立てる。`busy`の間の`start`は無視する。リセットはすべてを0へ戻す |

`fault_xor`は、ALUの応答に誤りを入れる検証用の入力です。実機では0につなぎます。

構成は2つです。

| 構成 | 実行するもの | パターン数 | 種 | 期待の署名 |
| --- | --- | --- | --- | --- |
| `rtl-p64` | RTL | 64 | `0xace1` | `0xdca2` |
| `netlist-p40` | Yosysで合成したネットリスト | 40 | `0x1d2b` | `0x38d0` |

期待の署名は、ランナーがPythonのモデルから計算し、パラメーター`GOLDEN`としてRTL、または合成の前の`chparam`へ渡します。

## 合成と構造の確認

`netlist-p40`では、変異ごとに次の手順でネットリストを作ります。

1. `chparam`でパターン数・種・期待の署名・変異を決める。
2. `synth -flatten`で汎用ゲートにし、初期値を消して、リセットのない`$_DFF_P_`だけにする（同期リセットはその前の論理になる）。
3. `stat`の`$_DFF_P_`の数が、LFSR 16＋署名16＋ALUの結果9＋パターンの計数（`PATTERNS`のビット長）＋制御4（`busy`・`done`・`pass`・応答の取込み）とちょうど一致することを確かめる。40パターンでは51個です。
4. 一致しなければ、そのビルドを失敗にする（そのネットリストのケースはすべてエラーになり、合格しない）。

セルフテストは、署名を出力につながない形に書き換えた写しを合成し、Yosysが署名のレジスタを消して、このビルドが拒否されることを確かめます。

シミュレーションでは、ネットリストとYosysの`simcells.v`を同じテストベンチで動かします。合成で決まったパラメーターはネットリストにないので、テストベンチは`generate`でパラメーターなしの接続に切り替えます。

## 独立した期待値

`model.py`は、仕様を「リスト」で書き直したモデルです。

- 刺激は、種から始まるLFSRの状態のリストです。応答は各状態のALUの結果のリスト、署名はそのリストを順にたたんだ値です。
- 1クロックごとの期待値は、開始からの経過クロック数で計算します。回路の計数器や取込みのフラグは持ちません。
- 期待の署名`GOLDEN`もこのモデルから作ります。セルフテストは、ALUを整数の演算と、署名の計算を別の書き方と照合します。

テストベンチは、各行の入力を与え、エッジの前の出力を比べます。判定は全部ビット一致です。

| 見え方 | 比べるもの | 失敗のラベル |
| --- | --- | --- |
| 両方 | `busy`・`done`・`pass`が未知でないこと | `ST_X` |
| 両方 | `busy`・`done` | `ST_DONE` |
| 両方 | `pass` | `ST_PASS` |
| 全部の見え方だけ | LFSRの値、応答、署名（未知でないことも） | `ST_STIMULUS`、`ST_RESPONSE`、`ST_SIGNATURE` |

## 刺激

- **`scenario`**：全部の見え方で、開始・`busy`の間の`start`・完了の後の再開始・実行中のリセット・完了の後のリセットを通します。続けてチップの見え方で、誤りのない実行、応答を1つ誤らせた実行、無関係な2つを誤らせた実行を通し、最後に全部の見え方へ戻ります。全目標に、この固定の場面だけで届きます。
- **`random-seed*`**：seedから、全部の見え方の実行、途中のリセット、チップの見え方での誤りつきの実行（誤りの数・位置・値は乱数）を混ぜます。smokeは4操作、nightlyは12操作×3 seedです。

## 要求と目標

5要求・14目標です（`requirements.json`）。

| 要求 | 目標 |
| --- | --- |
| `ST-STIMULUS` | ALUの4つの演算がすべて現れる |
| `ST-SIGNATURE` | 桁上げのビットが1の応答、署名の最上位ビットからの戻し |
| `ST-VERDICT` | 誤りのない実行の合格、誤りを入れた実行の不合格 |
| `ST-CONTROL` | `busy`の間の`start`、完了の後の再開始、実行中と完了の後のリセット |
| `ST-VIEW` | チップの見え方と全部の見え方 |

## 意図的な誤実装

| 変異 | 内容 | 予定のラベル |
| --- | --- | --- |
| 1 | 減算の`+1`を忘れる | `ST_RESPONSE` |
| 2 | ANDの桁上げに加算の桁上げを出す | `ST_RESPONSE` |
| 3 | ANDとXORの選択が入れ替わる | `ST_RESPONSE` |
| 4 | LFSRの帰還の位置を1つ誤る | `ST_STIMULUS` |
| 5 | 署名へ応答の桁上げのビットを入れない | `ST_SIGNATURE` |
| 6 | パターンを1つ少なく数える | `ST_DONE` |
| 7 | 最後の応答を入れる前の署名で合否を決める | `ST_PASS` |

変異はすべて、`scenario`で両構成とも予定のラベルで検出します。ネットリストの構成では、変異を入れたRTLを合成し直して実行します。

ほかに、見え方を分ける3つのケースがあります。

- **`detect-mutation1-chip-view`**：チップの見え方だけで、変異1（ALUの誤り）を実行します。応答は見えませんが、署名が変わるので、`pass`が0になり`ST_PASS`で見つかります。
- **`detect-aliasing-full-view`**：応答を2つ、署名の中で打ち消し合うように誤らせます（下の節）。全部の見え方では、1つ目の誤った応答で`ST_RESPONSE`になります。
- **`survive-aliasing-chip-view`**：同じ誤りを、チップの見え方で実行します。最終の署名は期待値と一致し、`pass`は1になります。合格で終わることを確かめる診断です。

## 署名の別名

MISRの1ステップは、可逆な線形の写像に応答を足したものです。そのため、**誤りが1つだけなら、最終の署名は必ず変わります**。セルフテストは、両構成の全パターン位置について、代表の誤りの値（1、2、`0x100`）と、先頭と最後の位置では1〜511の全部の値で、署名が変わることを確かめます。

2つ以上の誤りは、打ち消し合うことがあります。1つ目の誤り`e`が1ステップ進むと`fold(e, 0)`になるので、次の応答にちょうどその値を誤らせると、差は0へ戻ります。この例では`e = 0x0a5`、次の誤りは`0x14a`です（`model.cancelling_fault`）。差が10ビット目へはみ出す`e`（例：`0x1ff`）では、1つの応答では打ち消せません。

誤りの並びがすべて同じ確からしさで起きるとすると、別名になる割合は数え上げで決まります。署名をnビット、入力を全部でmビット（応答の幅×パターン数）とすると、0以外の誤りの並び2^m−1通りのうち、署名を変えないものは2^(m−n)−1通りです。割合はほぼ2^−nで、この例の16ビットでは約1.5×10^−5です。セルフテストは、4ビットのMISRで、1ビット×8回、2ビット×6回、3ビット×4回の全部の並びを数え、この式とちょうど一致することを確かめます（例：1ビット×8回では255通り中15通り）。

この割合は「誤りの並びが一様に起きる」という仮定の下の値です。実際の故障は特定の並びを作るので、この割合で検出の確率を見積もってはいけません。1つの誤りは必ず見つかる、という性質の方が実用的です。

## 実行

```sh
python3 examples/local-synth-testbench/run.py --out artifacts/local-synth-testbench-smoke
python3 examples/local-synth-testbench/run.py --profile nightly --out artifacts/local-synth-testbench-nightly
python3 -m unittest discover -s examples/local-synth-testbench/tests
```

必要なツールはIcarus VerilogとYoWASP版のYosys（`--yosys`、既定は`yowasp-yosys`）です。`simcells.v`はYosysの導入先から探し、`--cell-library`で指定もできます。`--configuration`で構成を絞れます。`--demo-bug 1`〜`7`は通常のケースにも変異を入れ、終了コード1になることを確かめます。

出力は[共通ランナー](../local-common/README.md)の形式です。ネットリストの構成では、変異ごとのディレクトリに`netlist.v`、`synthesis.log`、`stat.txt`が残り、`builds.json`の`preparation`にフリップフロップの数を記録します。JUnitは、2構成でsmoke 26件／nightly 30件です（構成ごとに、固定1＋ランダム1／3＋変異の検出9＋診断1＋目標の判定1）。

セルフテストは13件です。LFSRの周期、ALUと整数の演算、各構成で全演算と桁上げが現れること、署名の別の書き方、1つの誤りが必ず見つかること、打ち消し合う2つの誤り、4ビットのMISRの数え上げ、件数とフリップフロップの数、構造の確認の判定、全構成の実行と証跡と`--demo-bug`、seedの再現、署名を消した合成が拒否されることを確かめます。IcarusかYosysが見つからなければ、skipせずに失敗します。

## 確認範囲と残る制限

- 合成はYosysの汎用ゲートまでです。FPGAのツールでの合成、配置配線、タイミング、実機での動作は確かめていません。
- 構造の確認は、フリップフロップの数の一致だけです。組合せ回路の一部が定数になって消える誤りは、数では見つかりません（ネットリストのシミュレーションで見つけます）。
- 実機で使うときは、結果の`done`・`pass`をLEDやピンへ出し、署名はデバッグ用の読出しで取り出す、といった接続が別に要ります。この例はその上位を持ちません。
- 別名の割合は、一様な誤りという仮定の下の数え上げです。故障のモデルごとの検出の確率は扱いません。
- ALUの全入力を試すものではありません。40〜64パターンの範囲で、全演算と桁上げを通るだけです。

## 確認記録

2026-11-21に、Python 3.13、Icarus Verilog 14.0開発版、YoWASP版Yosys 0.70で、smoke（seed 17・3）とnightly（`--timeout 60`、約21秒）が合格し、全目標14／14に両構成で届きました。ネットリストの構成では、8回の合成（変異0〜7）のすべてで、フリップフロップは51個で期待どおりでした。1回の合成は約4秒です。セルフテスト13件も合格しました。RTLはVerilator 5.052の`--lint-only --Wall`で、変異0〜7と`PATTERNS=40`の構成で警告0件でした。

計画の外の誤りを、作業用の写しのRTLへ11個入れてsmokeにかけ、10個が不合格になりました。

| 誤り | 最初に落ちた検査 |
| --- | --- |
| 加算の桁上げを捨てる | `ST_RESPONSE` |
| 減算の桁上げを反転する | `ST_RESPONSE` |
| 署名の多項式を`0x1023`にする | `ST_SIGNATURE` |
| 応答を署名の上位へ足す | `ST_SIGNATURE` |
| 開始で署名を消さない | `ST_SIGNATURE` |
| 開始で`pass`を消さない | `ST_PASS` |
| リセットで`done`を消さない | `ST_X`（電源投入後に一度も値が決まらない） |
| 演算の選択のビットを入れ替える | `ST_RESPONSE` |
| LFSRを逆向きに回す | `ST_STIMULUS` |
| パターンの計数器を1ビット狭くする | `ST_STIMULUS` |
| 応答の取込みのフラグを常に1にする | 合格のまま。`busy`の間は最初のクロックを除いて元から1で、開始で0へ戻るので、動作に差が出ない |
