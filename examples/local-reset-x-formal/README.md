# リセット後に値が決まることを、不定の初期値から証明する

電源を入れた直後のレジスタの値は決まっていません。RTLシミュレーションはこれをXで表しますが、`if`や`case`の条件がXのとき、シミュレータは「偽」や「どれにも一致しない」側の枝を実行します。その枝がたまたま正しい値を代入していると、Xは消え、波形はきれいに見えます。実際の回路では、そのレジスタは0か1のどちらかで、もう一方の枝を通ることがあります。これがXの楽観（X-optimism）です。

この教材では、リセットのあるレジスタとないレジスタが混ざった小さなパイプラインについて、次の2つを、レジスタの最初の値を一切決めずにフォーマルで証明します。

- リセットから決まったサイクル数のうちに、指定した出力とレジスタの値が決まること。
- リセットのないデータレジスタの不定値が、`out_valid`が立っている間の`out_data`以外へ流れないこと。

あわせて、Xから始めるシミュレーションでは合格するのに、証明では反例が出る誤りを2つ示します。

リセットとクロック停止の動作そのものは[クロック停止とリセットの例](../local-clock-reset/README.md)、電源を切った領域のXは[複数電源領域の例](../local-power-domains/README.md)で扱います。フォーマル検証の進め方は[フォーマル検証の手順](../../docs/method/formal-verification.md)にあります。

## 対象回路

[`reset_x_unit.sv`](rtl/reset_x_unit.sv)は、`STAGES`段のパイプラインです。入力を受け取り、`STAGES`サイクル後に出力します。

| レジスタ | リセット | 値が決まる時点 |
| --- | --- | --- |
| フラッシュカウンター`init`、先頭の有効ビット`v[0]`、加算幅の設定`step`、出力数のカウンター`count`、エラーフラグ`err` | あり（同期） | `rst`が1のクロックエッジ |
| 2段目以降の有効ビット`v[1]`〜 | なし | 前段の値が流れてくる。j段目は、リセットのエッジからjエッジ後 |
| データレジスタ`d[0]`〜 | なし | 有効なデータが書かれたとき。それまでは不定のまま |

2段目以降の有効ビットにリセットがないので、リセットの直後には不定の有効ビットがパイプラインに残っています。回路は、リセットのエッジから`STAGES-1`エッジのあいだ`ready`を下げ、その間は最後の有効ビットを`out_valid`へ出しません。この`STAGES-1`サイクルが、仕様の「Nサイクル」です。リセットは1サイクルで足ります。

出力の仕様は次のとおりです。

| 出力 | 仕様 |
| --- | --- |
| `ready` | リセットのエッジから`STAGES-1`エッジ後に1。それまで0 |
| `out_valid` | `ready`が1で、最後の段が有効なとき1 |
| `out_data` | `out_valid`が1のときだけ意味を持つ。0のときは不定でよい |
| `odd` | `out_valid`が1のときの`out_data`のパリティ。0のときは0 |
| `count` | 出力1個につき1（`step`が1なら2）増える4ビットのカウンター |
| `err` | `ready`が0のときに入力が来たら1。リセットまで保持 |

`stage_valid_o`などの観測用の出力は、検査のためのもので、機能には含めません。

## 不定の初期値の表し方

Yosys 0.70とSBY（smtbmc、Z3）で、次の2つを試しました。

- 初期値を書かないレジスタ。smtbmcは最初の状態で任意の値を取らせます。
- `(* anyinit *)`を付けたレジスタ。同じく最初の値が任意になります。

小さな回路で到達性を調べ、どちらのレジスタも最初のステップで1になれることを確かめました。この教材は前者を使います。対象のRTLに何も足さずに済むためです。RTLには`initial`も、宣言での初期値もありません（セルフテストが確かめます）。

証明には、最初にリセットがかかるという仮定も置きません。仮定は0個です。すべての検査は、`rst`が1のエッジを一度見た後（`f_seen`）にだけ働きます。

## フォーマルで証明すること

[`reset_x_formal.sv`](reset_x_formal.sv)は、検査を2組持ちます。パラメーター`VALUES`で切り替えます。

### 2つの複製を比べる（`VALUES=0`）

同じ回路を2つ置き、同じ入力を与えます。2つの複製のレジスタは、それぞれ別の任意の値から始まります。リセットの後、ある信号が2つの複製で必ず等しければ、その信号は最初の値に依存せず、入力だけで決まっています。これを「値が決まる」ことの定義にします。

| 検査 | 内容 |
| --- | --- |
| `ap_known_ready` | `ready`が等しい |
| `ap_known_stream` | `out_valid`が等しく、1のときは`out_data`も等しい |
| `ap_known_odd` | `odd`が等しい |
| `ap_known_count`、`ap_known_err`、`ap_known_step` | カウンター、エラーフラグ、設定が等しい |
| `ap_known_stages` | j段目の有効ビットは、リセットからjエッジ後には等しい |
| `ai_known_init`、`ai_known_data` | 帰納法の補助。フラッシュカウンターが経過サイクル数と等しい。有効な段のデータが等しい |

`out_data`は、`out_valid`が0のあいだは比べません。到達性の検査`cp_unknown_data`は、その間に2つの複製の`out_data`が実際に違う値になれることを確かめます。不定値は本当にあり、隠れているだけです。

### 値と比べる（`VALUES=1`）

2つの複製が同じ誤った値にそろうことがあります。たとえばカウンターのリセット値が1でも、2つの複製は一致します。そこで、1つの複製を値と比べる検査を別に持ちます。

| 検査 | 内容 |
| --- | --- |
| `ap_reset_values` | リセットのエッジの直後に、`out_valid`・`odd`・`count`・`err`・`step`・`v[0]`が0 |
| `ap_ready_time` | `ready`は、リセットから`STAGES-1`エッジ後にちょうど1になる |
| `ap_valid_model`、`ap_count_model`、`ap_err_model` | 初期値を決めた小さなモデルと一致する |
| `ai_step_model`、`ai_init_model`、`ai_stage_model` | 帰納法の補助 |

どちらの組も、k帰納法（深さ5）で非有界に証明します。データの値そのものは、モデルと比べていません。

## シミュレーションで確かめること

[`reset_x_tb.sv`](tb/reset_x_tb.sv)は、1行を1サイクルとして入力を与え、エッジの後の出力を[参照モデル](model.py)の期待値と`!==`で比べます。仕様が値を決めている出力にXが出れば不合格です。参照モデルは不定を`None`で持ち、仕様が値を決めていない所（`out_valid`が0のときの`out_data`、まだ流れきっていない有効ビット）は比べません。

電源投入時のレジスタの値は、4通りを試します。

| 始め方 | 内容 |
| --- | --- |
| X | 何も設定しない。RTLシミュレーションの通常の始め方 |
| zeros | 全レジスタを0にしてから始める |
| ones | 全レジスタを1にしてから始める |
| mixed | フラッシュカウンターを0、`step`と`err`を1にしてから始める |

期待値は4通りとも同じです。出力が電源投入時の値に依存しないことが仕様だからです。

### 目標

[`requirements.json`](requirements.json)は6要求・21目標です。

| 要求 | 目標 |
| --- | --- |
| RX-POWER | X・zeros・ones・mixedの4通りの始め方 |
| RX-RESET | 1サイクルのリセット、長いリセット、データが流れている途中のリセット |
| RX-FLUSH | `ready`の立上り、そのとき全段の有効ビットが決まっていること、フラッシュ中の入力の拒否 |
| RX-DATA | 無効な間の不定の`out_data`、通過、連続、パリティの奇と偶 |
| RX-COUNT | 加算幅1と2、一周 |
| RX-ERR | セット、保持、リセットでの解除 |

## 6つの誤りと、見つける検査

| 番号 | 誤り | Xからのシミュレーション | 証明（2つの複製） | 証明（値） |
| --- | --- | --- | --- | --- |
| 1 | カウンターにリセットがない | `RX_COUNT` | `ap_known_count` | 実行せず |
| 2 | `odd`を`out_valid`で絞っていない | `RX_ODD` | `ap_known_odd` | 実行せず |
| 3 | `ready`が1サイクル早い | `RX_READY` | `ap_known_stream` | `ap_ready_time` |
| 4 | エラーフラグのリセットが、フラッシュカウンターが0の間だけ抜ける（`if`） | **合格する** | `ap_known_err` | 実行せず |
| 5 | 設定`step`のリセットが、フラッシュカウンターが0の間だけ抜ける（`case`） | **合格する** | `ap_known_step` | 実行せず |
| 6 | カウンターのリセット値が1 | `RX_COUNT` | **合格する** | `ap_reset_values` |

### シミュレーションが見逃す誤り（4と5）

誤り4は、エラーフラグのリセットの条件に、フラッシュカウンターが0でないことを足したものです。

```systemverilog
if (rst && init != 0) err <= 1'b0;
else if (err)         err <= 1'b1;
else                  err <= refuse;
```

一度正しくリセットされた後は、`rst`が1でフラッシュカウンターが0になるのは長いリセットの2サイクル目以降だけで、そのとき`err`はもう0です。正しい回路と同じ動作をします。違いが出るのは電源投入の直後だけです。フラッシュカウンターがたまたま0、`err`がたまたま1で始まると、最初のリセットは`err`を消さず、`err`は1のまま残ります。

Xから始めるシミュレーションでは、`init`がXなので最初の条件はXです。`if`はXを偽として扱い、次の`else if (err)`もXで偽になり、最後の枝が`err`へ0を代入します。Xは1サイクルで消え、期待値と一致します。誤り5は同じことを`case (init)`の`default`で起こします。

始め方ごとの結果は次のとおりです。

| 始め方 | 誤り4 | 誤り5 |
| --- | --- | --- |
| X | 合格（見逃す） | 合格（見逃す） |
| ones | 合格（見逃す）。フラッシュカウンターが0でないので、リセットが効く | 合格（見逃す） |
| mixed | `RX_ERR` | `RX_COUNT` |

初期値を0や1で埋める方法でも、見つかるかどうかは埋め方しだいです。証明は、埋め方を選ばずに反例（フラッシュカウンターが0、フラグが1で始まる状態）を出します。nightlyのランダム試験3 seedも、Xから始まる構成ではこの2つを見つけません。

### 2つの複製の比較が見逃す誤り（6）

リセット値が誤っていても、2つの複製は同じ誤った値になります。`known-misses-mutation6`は、2つの複製の検査が深さ12まで合格することを診断として記録します。値と比べる検査は反例を出します。「値が決まる」ことと「正しい値になる」ことは、別に確かめます。

## 実行

```sh
python3 examples/local-reset-x-formal/run.py --out artifacts/reset-x
python3 examples/local-reset-x-formal/run.py --profile nightly --out artifacts/reset-x-nightly
. artifacts/toolchains/formal-venv/bin/activate
python3 examples/local-reset-x-formal/formal.py --out artifacts/reset-x-formal
python3 -m unittest discover -s examples/local-reset-x-formal/tests
```

`run.py`は[共通シミュレーションランナー](../local-common/README.md)、`formal.py`は[共通フォーマル手順](../local-formal-common/README.md)を使います。オプションは両者の説明のとおりです。

構成は2つです。`stages3`は3段・データ8ビット、`stages2`は2段・データ4ビットで、シミュレーションとフォーマルで同じです。

| 実行 | 1構成の内訳 | JUnit |
| --- | --- | --- |
| シミュレーションsmoke | 固定シナリオ4（始め方ごと）＋ランダム1 seed（300サイクル）＋検出6＋見逃しの診断4、合否判定1 | 32件 |
| シミュレーションnightly | ランダムが3 seed（各3000サイクル） | 36件 |
| フォーマル | 証明2＋到達1＋反例7＋見逃しの診断1 | 22件 |

`--demo-bug 1..6`（フォーマルは`1..4`）は、正常な検査の側へ誤りを入れます。シミュレーションでは、4と5はmixedの固定シナリオだけが不合格になり、Xの固定シナリオは合格します。

## 証跡

シミュレーションは、行ごとの入力と期待値、波形、`COVER`と`COUNT`のログ、`manifest.json`・`coverage.json`・`summary.json`・`junit.xml`を保存します。フォーマルは、タスクごとのSBYの設定とログ、読み込んだassert・coverの一覧、反例と到達例の波形とwitnessを保存します。

## 確認範囲

- 対象は、単一クロック・同期リセットの小さな回路です。非同期リセット、リセットの解除のタイミング（recovery／removal）、複数のクロックやリセット領域は扱いません。
- 「値が決まる」ことは、2値の初期値を任意にした2つの複製が一致することで定義しています。メタスタビリティや、0でも1でもない電圧は表しません。
- 証明は2値です。Xそのものを伝搬させる検査（シミュレータのX伝搬の拡張や、Xを扱うフォーマルの機能）は使っていません。Xの悲観（実際には決まる値がシミュレーションでXになること）は扱いません。
- データの値はモデルと比べていません。2つの複製で等しいことと、シミュレーションでの一致だけです。
- メモリ（配列）の初期値は扱いません。データレジスタは1本のベクトルです。
- シミュレーションで電源投入時の値を設定する方法は、テストベンチからの階層参照による代入です。シミュレータの初期値ランダム化の機能は使っていません。
- `if`と`case`がXをどう扱うかは、IEEE 1800の言語仕様で決まっている動作です。節番号は未照合です。
- 確かめたツールは下の記録のものだけです。Verilatorはlintにだけ使っています。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13.15（フォーマルは3.14.7）、Icarus Verilog 14.0開発版、YoWASP版Yosys 0.70とSBY、Z3 4.15.3、Verilator 5.052（lintのみ）で確かめました。

- シミュレーション：smoke 32件、nightly 36件が合格。2構成とも21目標、検出12件、見逃しの診断8件。数秒で終わります。
- フォーマル：22件が合格（証明4、到達2、反例14、見逃しの診断2）。全体で約40秒です。
- `--demo-bug 4`と`5`をnightlyで実行し、Xから始まる固定シナリオとランダム試験は合格、mixedから始まるものだけが不合格になることを確かめました。
- セルフテスト23件が合格。
- RTLは、2構成・変異0〜6で`verilator --lint-only -Wall`の警告0件です。

Linuxとkirimasimでは実行していません。
