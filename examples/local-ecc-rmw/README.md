# ECC付きRAMの部分書き込みとRead-Modify-Write

32／64bitのSECDED付きRAMへ、Byte enableを使って一部のバイトを書き込みます。[8bitのECCメモリ例](../local-ecc-memory/README.md)から、ワード単位のECCとバイト単位の更新を組み合わせる教材です。[4教材の入口](../local-memory-common/README.md)から関連例へ進めます。

## データだけの書き換えでは足りません

例えば`0x11223344`の第1バイトだけを`0xAA`にすると、データは`0x1122AA44`です。ECCの検査ビットも、この新しいワードに対応する値へ更新します。本例では、部分書き込みを「旧ワードを同期読出し → 必要なら1bit誤りを訂正 → 指定バイトを変更 → ECCを再計算 → 書戻し」として実装します。[OpenTitanのSRAM制御](https://opentitan.org/book/hw/ip/sram_ctrl/doc/theory_of_operation.html)にも、ワードの整合性ビットを更新するための部分書き込みのRead-Modify-Writeが説明されています。

RTLの状態は`IDLE → READ → DECODE → WRITE → RESPONSE`です。途中に別の要求を受理すると、読み出した旧値が古くなり、新しい書き込みを失う恐れがあります。本例は要求から応答の受理まで他の要求を待たせます。TBは同一ワードの別バイトへの次要求を提示し、最初の応答まで待った後に両方の更新が残ることも確認します。

## インターフェースと契約

- `DATA_W`は32／64、既定32です。深さは既定8ワードで、回帰も深さ8です。アドレスはRAMのワード番号です。32bitの符号語は39bit、64bitは72bitです。
- `req_valid && req_ready`の立上りで、方向・アドレス・データ・ストローブを受理します。`req_strb[0]`は`req_data[7:0]`を選びます。送信側は待機中の要求を保持します。
- 全バイト有効なら旧値を読まずワード全体とECCを書き換えます。全ストローブ0は無変更で正常応答し、故障も消しません。
- 部分書き込みの旧値に1bit誤りがあれば、訂正してから変更し、`rsp_corrected=1`を返します。旧値が2bit誤りなら`rsp_uncorrectable=1`と`rsp_error=1`を返し、保存値を変更しません。全ワード書き込みなら、旧値が訂正不能でも新しい符号語で置き換えられます。
- 読出しは訂正済みのデータを返し、1bit誤りは書き戻します。訂正不能時の応答データは0です。書き込みの応答データも0です。
- `rsp_valid && !rsp_ready`の間はデータと全ステータスを保持します。応答を受理するまで次の要求を受け付けません。
- 同期・アクティブLowリセットで制御と保留要求を破棄します。RAM配列はリセットしません。初期内容は未規定なので、TBは各ワードを正常に書いてから使います。コミット前に中断した部分書き込みは反映されません。

バックグラウンドのスクラブはアイドル時だけ始めます。同じエッジでは「リセット → 試験用注入 → 正常要求 → スクラブ開始」の優先順位です。開始済みの処理を途中で割り込みません。通常要求と修復が同一ポートを取り合うため、1つの処理を終えてから次へ進みます。スクラブは全ワードを巡回し、訂正可能な誤りだけを書き戻します。

## 故障と独立した期待値

`inject_valid && inject_ready`で、指定ワードの**実際の符号語メモリ**へ`inject_mask`を一度XORします。データ出力に一時的なマスクを掛ける方式ではありません。注入は検証用フックで、アイドル時だけ受理し、正常要求とは区別します。通常動作のSEUモデルは0／1の反転です。持続するstuck-atや任意の多重故障はこの教材の対象外です。

[model.py](model.py)は故障のないバイト配列と、別管理の故障位置集合を持ちます。1bitなら訂正、2bitなら拒否という契約から期待値を作り、RTLのシンドロームや復号データを正解に使いません。正常書き込み・修復で故障集合も更新し、故障を意図せず蓄積させません。

## 試験と意図的な誤実装

全バイトレーン、ゼロストローブ、全符号語ビットの単一反転、代表的な2bit反転、読出し修復、巡回修復、前景要求との競合、同じワードへの次要求、RMW途中のリセット、応答停止、seed付きランダム試験を実行します。要求・必須目標は[requirements.json](requirements.json)へ対応付けています。単一故障は修復または全ワード再書き込みで独立させます。

4種類の変異は、非選択バイトの上書き、ECCの再計算漏れ、訂正通知の欠落、スクラブ有効時に旧値で部分書き込みを上書きする誤りです。通常試験と区別して検出します。セルフテストでは、未知値を内部保持値へ与えた診断が4値比較で拒否されることも確認します。X注入の診断を物理SEUとは呼びません。

固定試験には、全8ワードへ訂正可能な故障を1個ずつ入れてからスクラブを1巡させ、その後の全ワードの読出しで訂正の通知が出ないことを確かめる手順があります。訂正の書戻しの後に巡回の番地を0へ戻す、進めない、1つ飛ばす、といった誤りは、1巡で直せるワードが減るので、この読出しで見つかります。テストベンチの時間切れは、検査の失敗とは別のラベル（`ECC_RMW_TIMEOUT`）で報告します。変異で回路が止まっただけの実行を、予定どおりの検出とは数えません。

```sh
python3 examples/local-ecc-rmw/run.py --out artifacts/ecc-rmw-smoke
python3 examples/local-ecc-rmw/run.py --profile nightly --seed 42 --out artifacts/ecc-rmw-nightly
python3 examples/local-ecc-rmw/run.py --waves --out artifacts/ecc-rmw-wave
python3 -m unittest discover -s examples/local-ecc-rmw/tests -v
```

smokeは2構成×1 seed、nightlyは2構成×3 seedです。固定試験に加えるランダム操作は各seed 32／128組、JUnitは10／14件です。セルフテストは7件です。波形は`width32/seed17/trace.vcd`などで、`state`、`read_word`、`write_word`、要求・応答・スクラブ信号を追います。注入成立と訂正通知を先に確認し、その後の再読出しが訂正なしで正しいことを確認します。

## ファイルと確認範囲

[ecc_rmw_ram.sv](rtl/ecc_rmw_ram.sv)がRAM・符号化・復号・直列化制御、[ecc_rmw_tb.sv](tb/ecc_rmw_tb.sv)が入力とNBA後の判定、[run.py](run.py)が回帰計画です。共通の実行環境・証跡は[共通手順](../local-memory-common/README.md)を参照してください。

2026-11-20にIcarus Verilog 14.0開発版でsmoke／nightlyを実行しています。正確な版と結果は[実行記録](../../PROVENANCE.md#memory-integration-four)へ記録します。他シミュレータでの実行、特定のSRAMマクロへの合成、物理タイミング、ECCの故障率やスクラブ周期の設計は未確認です。3bit以上の故障に、任意の訂正・検出を保証しません。

2026-11-21に、レビューで見つかった試験の抜けを補いました。それまでの固定試験は、1巡に置く訂正可能な故障が1個だけで、訂正の書戻しの後に巡回の番地を0へ戻す回路でもsmoke・nightlyが合格していました。全ワードへ故障を入れる手順を足し、作業用の写しのRTLで、番地を0へ戻す・進めない・1つ飛ばすの3通りの誤りがsmokeで不合格になることを確かめています。番地を0へ戻す誤りは、セルフテストでも毎回確かめます。JUnitの件数は変わりません。
