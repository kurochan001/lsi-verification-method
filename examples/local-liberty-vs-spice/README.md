# Libertyのフリップフロップの数値を、トランジスタの回路から測り直す

STAは、Libertyに書かれた遅延・セットアップ・ホールドの表を信じて計算します。この例では、その表の数値がどこから来るのかを、トランジスタで組んだDフリップフロップをngspiceで解いて確かめます。CLK→Qの遅延を測り、セットアップ時間とホールド時間を二分探索で求め、測った値と表の値を対応付けます。

**回路・モデルカード・表の数値は、すべてこの教材のために作った架空のものです。** 実際の製造プロセスの特性ではなく、PDKも使っていません。MOSFETは、式を手で書けるレベル1（Shichman-Hodges）のモデルです。[OpenSTAの例](../local-sta/README.md)や[遅延つきのゲートレベルシミュレーションの例](../local-gate-timing/README.md)が使う教材用のLibertyも架空の値で、この例の測定値と「一致」することは求めません。比べるのは桁と傾向だけです。

## 対象の回路と測り方

- **回路**：トランスミッションゲートによるマスター・スレーブ型で、立上りエッジで取り込みます。クロックの反転と再反転、マスターとスレーブのそれぞれに順方向のインバーターと帰還のインバーター、2段の出力バッファーを持ち、トランジスタは24個です。ネットリストは[`cells.py`](cells.py)が作ります。
- **モデルカード**：電源は1.8 V、チャネル長は0.18 µmです。しきい値は±0.45 V、`KP`はNMOSが220 µA/V²、PMOSが110 µA/V²、`LAMBDA`は0.05 /Vです。単位インバーターの幅を0.5 µmと1.0 µmにして、`KP×W`をそろえています。寄生は、インバーターの出力ごとの4 fFの容量と、ゲートの重なり容量（0.25 fF/µm）で代表させています。
- **刺激**：クロックとデータは区分線形の電圧源です。50%の点が指定した時刻に来るようにし、20%から80%までの時間を「遷移時間」として与えます。最初のクロックで古い値を取り込ませ、3 nsの立上りエッジを測定の対象にします。
- **測定**：しきい値は50%です。CLK→Qは、クロックが50%を横切ってからQが50%を横切るまでの時間です。出力の遷移時間は20%から80%までです。Libertyのしきい値の宣言と同じにしています。
- **ソルバー**：固定版のngspice 47の共有ライブラリーを使います。`reltol=1e-4`、`abstol=1e-13`、`vntol=1e-7`、刻み1 ps、最大刻み2 psに固定しています。

## セットアップとホールドの二分探索

合否の基準を先に決めます。データを十分早く（クロックの1 ns前に）与えたときのCLK→Qを基準の遅延とし、次のどちらかなら「取り込めなかった」と判定します。

- Qが新しい値にならない（クロックから1 ns以内に50%を横切らない、または最後の値が新しい値から電源の10%以上離れている）。
- Qは新しい値になるが、**CLK→Qが基準の遅延の110%を超える**。

セットアップ時間は、データの50%の点をクロックの50%の点よりどれだけ前に置けば取り込めるかの、最小の値です。ホールド時間は、データを早く与えたうえで、クロックの後どれだけ経ってから古い値へ戻せば取り込んだ値が残るかの、最小の値です（負の値もあります）。

探索は−300 psから+500 psの区間で始めます。下端で取り込めないこと、上端で取り込めることを確かめ、区間の幅が1 ps以下になるまで半分に分けます。この区間では12回の試行で幅が約0.78 psになります。試行は16回で打ち切り、収まらなければ失敗にします。表に載せる値は、取り込めた側の端です。すべての試行（値、合否、遅延）を結果に残し、ランナーが「報告した境界の両端を実際に試したか」「境界より上は全部取り込み、下は全部失敗か」を照合します。

基準の決め方で値は変わります。データ・クロックとも遷移時間10 psの立上りでは、110%の基準で3.91 ps、「とにかく新しい値になればよい」基準では−2.34 psでした。前者の境界の少し外側では、Qは新しい値になりますが、CLK→Qが107 psから154 psへ伸びます。後段のタイミングがこの遅れを見込んでいなければ、取り込めていても回路は誤ります。

## 測った表

[`characterized.json`](characterized.json)が測定値の記録で、[`ff_measured.lib`](ff_measured.lib)はそれをLibertyの書式にしたものです。単位はps、fFです。

CLK→Qの遅延（立上りのQ。行はクロックの遷移時間、列は負荷）：

| クロックの遷移時間 | 10 fF | 50 fF | 100 fF |
| ---: | ---: | ---: | ---: |
| 10 ps | 102.53 | 119.36 | 138.88 |
| 50 ps | 118.26 | 135.10 | 154.61 |
| 100 ps | 132.46 | 149.30 | 168.82 |

セットアップ時間とホールド時間（立上りのデータ。行はデータの遷移時間、列はクロックの遷移時間、負荷は20 fF）：

| データの遷移時間 | セットアップ 10 ps | セットアップ 100 ps | ホールド 10 ps | ホールド 100 ps |
| ---: | ---: | ---: | ---: | ---: |
| 10 ps | 3.91 | −25.00 | 1.56 | 20.31 |
| 100 ps | 37.50 | 7.81 | −8.59 | 7.03 |

立下りの表と出力の遷移時間の表も、同じファイルにあります。

読み取れる傾向は次のとおりで、ランナーが毎回確かめます。

- 遅延は、負荷とともに増え、クロックの遷移時間とともに増えます。最も速い条件と最も遅い条件で約1.65倍の差があります。
- 負荷に対する傾きは約0.404 ps/fFです。最終段のインバーターが負荷を電源の半分だけ動かす時間として、レベル1の式から求めた値は0.400 ps/fFです（下の「判定の根拠」）。
- セットアップ時間は、データの遷移が遅いほど大きく、クロックの遷移が遅いほど小さくなります。ホールド時間は、クロックの遷移が遅いほど大きくなります。負の値も現れます。

## 既存の教材用Libertyとの対比

既存の3つのLiberty（[OpenSTAの例](../local-sta/README.md)のslow・fastと、[ゲートレベルの例](../local-gate-timing/README.md)のもの）のDFFは、表の4点がすべて同じ値です。遷移時間にも負荷にも依存しません。

| | 既存（slow） | 既存（fast） | 既存（ゲートレベル） | この例の測定値 |
| --- | ---: | ---: | ---: | ---: |
| CLK→Q | 200 ps | 100 ps | 300 ps | 102.53〜168.82 ps |
| セットアップ | 200 ps | 100 ps | 200 ps | −25.00〜37.50 ps |
| ホールド | 300 ps | 200 ps | 100 ps | −8.59〜20.31 ps |

CLK→Qは同じ桁です。セットアップとホールドは、既存の値の方が1桁ほど大きく、余裕を多く見た値になっています。どちらも架空の値なので、この差に意味はありません。意味があるのは、**一定値の表では、入力の遷移時間と負荷による違いがSTAに現れない**という点です。ランナーは、既存の表が一定値であることと、測った表に20%以上の幅があることを確かめます。既存のLibertyは読むだけで、書き換えません。

## 判定の根拠

| 判定 | 許容・範囲 | 根拠 |
| --- | --- | --- |
| ドレイン電流（6点） | 相対誤差1e-6以内 | レベル1の式を[`model.py`](model.py)に手で書いた値との比較。飽和・線形・遮断の各領域。実測の最大は約3e-8（`gmin`の分）。遮断領域は1 nA以下 |
| インバーターのしきい値 | 0.9 V ± 1 µV | `KP×W`としきい値が対称なので、ちょうど電源の半分になる |
| 遅延と遷移時間（表との比較） | 0.5 ps ＋ 0.3% | 表は同じ回路の測定値。手元での再実行の差は0.005 ps以下（表を0.01 psに丸めた分）で、ソルバーの相対許容誤差を10分の1にしたときの差は0.07 ps。その約7倍以上の余裕を取り、OSによる浮動小数点の差を見込んだ。中間のバッファーの幅を20%変えた回路の差（1.2 ps）は見分けられる |
| セットアップ・ホールド（表との比較） | 2 ps | 探索の格子（約0.78 ps）の2.5個分。わずかな差で境界が格子1つ分ずれても不合格にしないため。格子より細かい違いは見分けられない |
| 負荷への傾き | 式の値 ± 20% | 傾き ＝（VDD/2）÷ 最終段の平均電流。平均電流は、`Vds=VDD`と`Vds=VDD/2`の電流の平均。PMOSの幅4 µm、NMOSの幅2 µmで、どちらも0.400 ps/fF |
| 最も速い条件の遅延 | 段数からの見積りの1/3〜3倍 | 5段がそれぞれ5.5 fFを電源の半分だけ動かす時間の和（44 ps）。トランスミッションゲートと遷移時間を無視した見積りなので、桁の確認に留める。実測は94 ps |
| 表の点の間（ランダムな点） | 双線形補間 ± (2 ps ＋ 0.5%) | 遷移時間に対する遅延は少し曲がっているので、補間には誤差が残る。升目の中央を含む136点（68か所×立上り・立下り）で測った最大の差は1.10 ps。その約2倍を許容にした |
| ソルバーの設定 | 遅延1 ps、探索2 ps | `reltol=1e-5`、刻み0.5 psにして、四隅の遅延と探索4件を取り直す。実測の差は遅延0.07 ps、探索0 ps |

測定値と比べる表は、同じ回路から測って保存したものです。そのため、表との一致が示すのは「測定が再現すること」と「回路や測り方を変えたら気付けること」で、値そのものの正しさではありません。値の裏付けは、上の表のうち式から決まる4行（電流、しきい値、負荷への傾き、段数の見積り）です。

## 不合格にする場合

次の負例を毎回実行し、それぞれ決めたラベルで不合格になることを確かめます。

| ケース | 内容 | ラベル |
| --- | --- | --- |
| `detect-table-delay` | 表の遅延を8%大きくする | `TABLE_DELAY` |
| `detect-table-setup` | 表のセットアップを10 ps大きくする | `TABLE_SETUP` |
| `detect-table-hold` | 表のホールドを10 ps小さくする | `TABLE_HOLD` |
| `detect-weak-output` | 最終段のインバーターの幅を半分にする | `TABLE_DELAY` |
| `detect-slow-master` | マスターの記憶ノードの容量を5倍にする（遅延は変わらず、セットアップだけ変わる） | `TABLE_SETUP` |
| `detect-no-operating-point` | 電源に値の違う理想電圧源を2つつなぐ（解がない） | `SPICE_ERROR` |
| `detect-stuck-clock` | クロックを動かさない（Qが変化しない） | `MEAS_MISSING` |
| `detect-timeout` | 測定のプロセスを0.2秒で打ち切る | `SPICE_TIMEOUT` |
| `detect-nan` | 結果の1つをNaNにする | `MEAS_INVALID` |
| `detect-truncated` | 結果から1件を抜く | `MEAS_MISSING` |

ngspiceのエラー、時間切れ、欠けた測定、数値でない結果は、どれも合格にはなりません。1件のジョブが失敗しても、残りのジョブは実行して記録します。

## 実行と出力

[実行環境](../../tools/ENVIRONMENT.md#ngspiceとspice協調例)の手順で固定版のngspiceを用意し、その`install/bin`をPATHに入れます。

```sh
python3 examples/local-liberty-vs-spice/run.py --out artifacts/liberty-vs-spice-smoke
python3 examples/local-liberty-vs-spice/run.py --profile nightly --out artifacts/liberty-vs-spice-nightly
python3 -m unittest discover -s examples/local-liberty-vs-spice/tests
```

`--ngspice-config`で`lsi-ngspice-config`の場所を指定できます。`--seed`は、表の点の間に置くランダムな点（遷移時間と負荷）を決めます。

smokeは31件で、ngspiceの解析は約480回、手元では約16秒です。nightlyは35件で、ランダムな点が3 seedに増え、セットアップとホールドの合否を20 psおきに並べて境界が1つだけであることを確かめる検査が加わります（約550回、約17秒）。構成は1つです。要求は7件、目標は27個で、どれも固定の検査で届きます。

出力先には、`manifest.json`、`summary.json`、`junit.xml`のほかに次のものが残ります。

- `main/jobs.json`、`main/results.json`：測定のジョブと結果。探索のすべての試行を含みます。
- `main/setup-rise-inside.csv`など6つ：セットアップの境界の内側・外側と、大きく割り込んだ場合の、クロック・データ・Qの波形。大きく割り込むと、Qは古い値のままになります。
- `weak-output/`、`slow-master/`など：負例ごとの測定。

表を作り直すときは、次のスクリプトで新しい表とLibertyを別のディレクトリへ書き出し、差を読んでから置き換えます。回帰には含めていません。

```sh
python3 examples/local-liberty-vs-spice/characterize.py --out artifacts/liberty-vs-spice-table
```

セルフテストは31件です。レベル1の式、刺激の時刻と遷移時間、交差時刻の補間、取り込みの判定（ちょうど110%と、わずかに超えた場合）、表の検査、許容の境界、探索の記録の照合、Libertyの書出しと読戻しを確かめます。固定版のngspiceでの実行も1回含み、実際の結果を書き換えると決めたラベルで不合格になることを確かめます。ngspiceが用意されていない場合は、skipせずに失敗します。

## 確認範囲と残る制限

- 回路、モデルカード、寄生の容量、表は架空です。実際のセルの特性ではなく、実際のライブラリの特性化の手順（多数の入力条件、温度、電源、ばらつき、ノイズ、電力）の代わりにもなりません。
- 表と比べる測定は、表を作ったのと同じコードによるものです。値そのものの裏付けは、式から決まる4つの検査に限られます。フリップフロップの内部の遅延を、段ごとに式と照合してはいません。
- セットアップとホールドは、互いに独立に測っています。片方を詰めるともう片方が変わる関係（相互依存）は扱いません。合否の基準は110%の1通りで、表に載せたのは遷移時間2×2点、負荷20 fFだけです。
- 合否がオフセットに対して1つの境界だけを持つことは、nightlyの20 psおきの並びと、探索の試行どうしの整合で確かめています。すべてのオフセットについての証明ではありません。
- メタスタビリティ（取り込みに失敗する境界の近くで、解決に長い時間がかかる現象）の確率的な扱い、最小パルス幅、非同期のセット・リセット、スキャンは扱いません。
- 作った`ff_measured.lib`は、この例の読み取り処理で表と一致することを確かめただけで、OpenSTAなどのSTAツールには読み込ませていません。入力の容量などの値は仮のものです。
- ソルバーの設定への依存は、1通りの厳しい設定との比較だけです。レベル1以外のモデル、温度、電源電圧の違いは扱いません。
- Libertyの書式の規格とは照合していません（既存の教材用Libertyの書き方に合わせています）。
- Linuxでは実行していません。許容は、OSによる浮動小数点の差を見込んで決めていますが、実際の差は確かめていません。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13、固定版のngspice 47（共有ライブラリー）で、smoke（31件。seed 17・3・100）、nightly（35件、`--timeout 60`。seed 17〜19と3〜5）、セルフテスト31件が合格しました。Linux、統合ランナー経由、全セルフテストでは実行していません。

作業用の写しへ、ネットリスト・測定・判定の小さな誤りを1つずつ入れてsmokeを実行した結果は、次の節のとおりです。
