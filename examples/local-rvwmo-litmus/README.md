# ストアバッファのリトマス試験とフェンス

2つのhartが別々の共有変数に1を書き、相手の変数を一度ずつ読みます。書込みは各hartの1段バッファを通ります。両方の読み出しが0になる結果が、ストアとロードの間に入れるフェンスでどう変わるかを調べる教材です。

| 観察する条件 | 動作 |
| --- | --- |
| フェンスなし | 相手のストアがメモリへ届く前に両方のロードが完了し、両方が0を読み得る |
| 両hartがフェンスを実行 | 各ロードが自分のストアの排出を待つ。両方が0を読むには互いの排出より先にロードを終える必要があり、この順序は成立しない |
| 排出とロードが同じエッジ | ロードはエッジ直前の値を読む。待機中のロードはフェンスが退いた次のエッジから完了できる |
| リセット | メモリ、待機中のストア、フェンス、ロード結果が初期状態へ戻る |

## シミュレーション

`buf2`・`buf3` はストア受理から公開までの遅延が2・3クロックです。Pythonモデルは各ストアの公開予定時刻を記録し、2つのロードを同じメモリのスナップショットで評価します。固定刺激には、同時・時間差の発行、排出後のフェンス、リセットによる中断が含まれます。ランダム試験ではピンの同時入力もサイクル単位で比較します。順序に関する禁止結果の検査は、各hartが順番にストア、フェンス、ロードを要求した区間で行います。

フェンスの待機を無視する変異は `MEM_ORD`、排出先の取り違え、排出の早まり、ロード元の取り違えは `MEM_DATA` で検出します。[要求と7つの観測目標](requirements.json)

## 形式検証

`DRAIN=2` で、リセット、両ストア、フェンスの順を固定し、その後のロード要求の時刻をhartごとに自由にします。k帰納法で、両方のロード完了後に両方の値が0になる状態を排除します。ストアの公開期限と、公開フラグが立った変数の値を補助命題として証明します。カバーではフェンス付きで両方が1、フェンスなしで両方が0・両方が1に到達します。フェンスを迂回する変異では禁止結果の反例を要求します。[証明ハーネス](formal/litmus_formal.sv)

この試験の範囲は、2番地・各hart1ストアと1ロードのSBパターンです。RVWMO全体へのISA適合性、複数キャッシュ間のコヒーレンス、任意のプログラムは範囲外です。[ストアバッファの状態探索例](../local-store-buffer/README.md)と併読できます。

## 実行と確認範囲

```sh
python3 examples/local-rvwmo-litmus/run.py --out artifacts/rvwmo-smoke
python3 examples/local-rvwmo-litmus/run.py --profile nightly --out artifacts/rvwmo-nightly
python3 -m unittest discover -s examples/local-rvwmo-litmus/tests -v
```

形式検証にはYoWASP版SBY・YosysとZ3を使います。2026-11-23の実測はsmoke 12件、nightly 16件、各構成で7目標すべてに到達し、4変異を検出しました。単体テストは形式検証4件を含む13件です。
