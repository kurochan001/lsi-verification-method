# CICデシメーションフィルターの幅と折返しを、厳密な整数モデルとの一致で確かめる

CIC（Cascaded Integrator-Comb）フィルターは、乗算器を使わずに、積分器と櫛形（comb）の縦続だけでサンプルレートを下げます。検証で間違えやすいのは、次の3点です。

- **レジスタの幅**：出力の振幅は、入力の（比×遅延）の段数乗倍まで大きくなります。1ビット足りないだけで、最大振幅に近い入力のときだけ結果が壊れます。
- **積分器の折返し**：積分器は直流を足し続けるので、必ずあふれます。2の補数で折り返したまま計算を続ければ、最終の幅が足りている限り結果は正しい、という性質に頼ります。飽和させると壊れます。
- **デシメーションの位相**：どのサンプルで出力するかが1つずれても、多くの入力ではそれらしい値が出ます。

この例は、小さなCICデシメーターを、回路とは別の構成で書いた厳密な整数モデルとビット一致で照合します。判定に許容誤差は使いません。固定小数点の丸めと飽和は[固定小数点FIRの例](../local-dsp/README.md)が扱っています。位置付けは[演算回路の検証手順](../../docs/method/arithmetic-datapath-verification.md)にあります。

## 仕様

[`cic_decimator.sv`](rtl/cic_decimator.sv)は、`STAGES`段の積分器、`RATE`分の1の間引き、`STAGES`段の櫛形（遅延は出力サンプルで`DELAY`個）からなります。入力は符号つき8ビット（`IN_W`）です。

| 信号 | 動作 |
| --- | --- |
| `in_valid`・`in_data` | `in_valid`が1のクロックで、サンプルを1つ受け取る。受け取れないサイクルはない（逆圧なし）。`in_valid`が0のサイクルの`in_data`は使わない |
| `sync` | 同期の再開。履歴（積分器と櫛形の遅延）を捨て、次に受け取るサンプルを周期の1つ目にする。同じサイクルに出されたサンプルは受け取らずに捨てる |
| `out_valid`・`out_data` | 再開の後、受け取ったサンプルの`RATE`個ごとに1つ出力する。`RATE`個目を受け取った次のサイクルに、`out_valid`を1サイクルだけ1にする。`out_data`が意味を持つのは`out_valid`が1のサイクルだけ |
| `rst_n` | 非同期リセット。周期の途中でも、履歴と位相を初期値へ戻す |

再開（リセットまたは`sync`）の後に受け取ったサンプルを x[0], x[1], … とすると、k番目の出力は、長さ`RATE`×`DELAY`の移動和を`STAGES`回かけた列の、n ＝ k×`RATE`＋`RATE`−1 の値です。再開より前のサンプルは0として扱います。

### 幅の決め方

移動和を1回かけると、振幅は最大で`RATE`×`DELAY`倍になります。`STAGES`回かけるので、利得は G ＝（`RATE`×`DELAY`）の`STAGES`乗です。入力の最小値は −2の（`IN_W`−1）乗なので、出力の最小値は −2の（`IN_W`−1）乗×G です。これを2の補数で表すには、

`OUT_W` ＝ `IN_W` ＋ ⌈log2 G⌉

ビットが要ります（⌈ ⌉は切上げ）。この回路は途中の段を切り詰めないので、積分器と櫛形のレジスタはすべてこの幅です。Hogenauerが示したCICのビット成長の考え方と同じ内容で、式はこの例で導き直しました。元の論文とは照合していません。

| 構成 | 段数 | 比 | 遅延 | 利得 G | `OUT_W` | 1ビット少ない幅に収まる直流の範囲 |
| --- | --- | --- | --- | --- | --- | --- |
| `n3-r4-m1` | 3 | 4 | 1 | 64 | 14 | −64〜63 |
| `n2-r5-m2` | 2 | 5 | 2 | 100 | 15 | −81〜81 |

`n3-r4-m1`は利得が2のべき乗で、最小の入力（−128）の直流が、14ビットの最小値（−8192）にちょうど一致します。`n2-r5-m2`は2のべき乗でない場合です。

### 途中の折返し

積分器は入力の累積和を持つので、直流が続けば必ず`OUT_W`ビットの範囲を出ます。この回路は、あふれを検出も飽和もせず、折り返したまま足し続けます。加算と減算は2の`OUT_W`乗を法として正しく、最終の出力は必ず`OUT_W`ビットに収まるので、折返しは結果に影響しません。この性質は、すべての段が同じ幅を持つことに依っています。

## 独立した期待値

[`run.py`](run.py)の`Model`は、回路とは別の構成で書いた参照モデルです。

- 積分器も櫛形も持ちません。受け取ったサンプルの列に、長さ`RATE`×`DELAY`の移動和を`STAGES`回かけます。
- Pythonの整数は桁あふれしないので、語長も折返しもありません。出した値が`OUT_W`ビットに収まらなければ例外にします。つまり、モデルは幅が足りることも毎回確かめています。

セルフテストは、このモデルを別の2つの求め方と突き合わせます。1つは、移動和の多項式のべき乗から求めた係数（インパルス応答）です。もう1つは、積分器と櫛形を`OUT_W`ビットの剰余で計算する、回路と同じ構造のPythonの計算です。3つが一致することで、「折り返す構造」と「折り返さない和」が同じ値になることを、回路を動かす前に確かめます。

テストベンチ[`cic_tb.sv`](tb/cic_tb.sv)は、1行が1クロックのベクトルを読み、クロックの前に`out_valid`と`out_data`を期待値と比べます。比較は`!==`で行うので、有効な出力がXなら不合格です。時刻の誤りは`CIC_VALID`、値の誤りは`CIC_DATA`と、別のラベルで報告します。`in_valid`が0のサイクルには、`in_data`へ0でない値（0x5a）を与え、使われないことを確かめます。

## 刺激

| ケース | 内容 |
| --- | --- |
| `boundaries` | 固定シナリオ。下の表の区間を`sync`で区切って並べる。`n3-r4-m1`で525行、`n2-r5-m2`で849行 |
| `small-signal` | 1ビット少ない幅に収まる範囲の端（上の表の値）だけを使う固定シナリオ。直流は、第1積分器が折り返す長さまで続ける |
| `random-seed<n>` | 乱数の操作列。リセット、`sync`（サンプルつき・なし）、空きサイクル、最大振幅の直流、最大振幅の符号の入替え、一様乱数のサンプルを混ぜる。smokeは40操作×1 seed、nightlyは300操作×3 seed |

`boundaries`の区間は次のとおりです。どの目標も、乱数に任せず、この固定シナリオだけで届きます。

| 区間 | 狙い |
| --- | --- |
| 入力なしの空きサイクル | 受け取れる状態で入力が来ない |
| 最小値（−128）の直流、最大値（＋127）の直流 | 出力の最小値と最大値。第1積分器が折り返す長さまで続ける |
| 最大振幅を1サンプルごとに入れ替える | 最大振幅の交番 |
| 最大振幅を`RATE`×`DELAY`サンプルごとに入れ替える | 出力が正負の両端の近くまで振れる |
| 1ビット少ない幅に収まる端の「1つ超え」の直流（正・負） | 収まらない最小の振幅 |
| 同じ端の「ちょうど」の直流（正・負） | 収まる最大の振幅 |
| 第1積分器の累積和が、周期の最後のサンプルで半分の範囲を超える直流（正・負） | 第1積分器だけが狭い誤りを、その出力で見せる |
| 0の列 | 0を入れれば0が出る |
| 空きサイクルを挟んだ小さい値の列 | 受け取らないサイクルを位相に数えない |
| 周期の途中で、サンプルを出しながら`sync` | 履歴とサンプルを捨て、位相を合わせ直す |
| 周期の途中で、履歴があるままリセット | 履歴と位相が初期値へ戻る |

逆圧はないので、「処理中に次の要求を出し続ける」に当たるのは、連続してサンプルを与える通常の区間です。

## 要求と目標

[`requirements.json`](requirements.json)は5要求・14目標です。全通常ケースの合格に加えて、構成ごとに全目標への到達を要求します。

| 要求 | 目標 |
| --- | --- |
| `CIC-WIDTH`（幅） | `range/min`、`range/max`（出力がとりうる最小値・最大値に一致）、`msb/positive`、`msb/negative`（1ビット少ない幅には収まらない出力） |
| `CIC-WRAP`（折返し） | `wrap/integrator`（第1積分器が折り返した）、`wrap/output-after-wrap`（折り返した後の出力が照合に合格した） |
| `CIC-PHASE`（位相） | `phase/first-output`、`phase/gap`、`phase/sync-realign`、`sync/discard-sample` |
| `CIC-RESET` | `reset/midstream` |
| `CIC-ARITH`（値） | `result/zero`、`result/positive`、`result/negative` |

`wrap/integrator`だけは、テストベンチが回路の中の第1積分器を読んで判定します。同じ符号の2数を足して符号が変わったことを見るだけで、合否には使いません。

## 意図的な誤実装

変異は7種類です。`detect-mutation<n>`は`boundaries`のベクトルで実行し、予定したラベルで不合格になることを要求します。

| 変異 | 内容 | ラベル |
| --- | --- | --- |
| 1 | すべてのレジスタの幅を1ビット削る | `CIC_DATA` |
| 2 | 積分器を、折り返さずに飽和させる | `CIC_DATA` |
| 3 | 櫛形の遅延を1つ短く読む（遅延1の構成では、引かない） | `CIC_DATA` |
| 4 | 再開の後の位相が1サンプルずれている | `CIC_VALID` |
| 5 | `sync`が位相を合わせ直さない（履歴は捨てる） | `CIC_VALID` |
| 6 | `in_valid`が0のサイクルにも積分する | `CIC_DATA` |
| 7 | 第1積分器の幅だけを1ビット削る | `CIC_DATA` |

### 幅を1ビット削った誤りは、どこを削ったかで見え方が違う

変異1と変異7は、どちらも「1ビット足りない」誤りですが、見つかる条件が違います。この例は、その差を追加の2ケースで毎回確かめます。

| ケース | ベクトル | 結果 |
| --- | --- | --- |
| `detect-mutation1` | `boundaries` | 検出。最大振幅の直流で、出力が狭い幅の範囲を出る |
| `survive-mutation1-small-signal` | `small-signal` | **合格のまま（見逃す）**。診断ケースとして、合格することを確かめる |
| `detect-mutation7` | `boundaries` | 検出 |
| `detect-mutation7-small-signal` | `small-signal` | 検出 |

- **変異1（全段を一様に削る）**：全体が1ビット少ない幅の剰余で正しく計算されるので、出力は「正しい値を狭い幅へ折り返したもの」になります。正しい出力が狭い幅に収まる限り、誤りは見えません。`small-signal`は、収まる範囲の端ちょうどの振幅まで使い、第1積分器が折り返す長さまで直流を続けますが、それでも合格します。全14目標のうち、この誤りが見える出力を要求するのは、`CIC-WIDTH`の4目標（`range/min`、`range/max`、`msb/positive`、`msb/negative`）だけです。
- **変異7（第1積分器だけを削る）**：第1積分器は入力の累積和そのものなので、小さい直流でも、続けば狭い幅を出ます。そこで折り返した値は、後ろの広い段から見ると、最上位ビットの重みだけずれた入力です。そのずれは、後ろの段を通って出力の最上位ビットを反転させます。

ただし、変異7が出力に見えるかどうかは、折り返す時刻と位相の関係に左右されます。最初の版の固定シナリオでは、`n3-r4-m1`でこの変異が合格しました。直流が半分の範囲を超えるサンプルが、いつも周期の1つ目に当たっていたためです。そこで入ったずれは、出力に使われる時刻には偶数の重みでしか現れず、最上位ビットの重みの偶数倍は法の中で消えます。固定シナリオに、累積和が周期の最後のサンプルで半分の範囲を超える区間（`run.py`の`crossing`）を足して、両方の構成で確実に見えるようにしました。セルフテストが、この区間がその時刻に範囲を超えることを確かめます。

乱数だけに任せた場合の参考値です。モデルに一様乱数の入力を10万サンプル与えると、狭い幅の範囲を出た出力は、`n3-r4-m1`で25,000個のうち454個、`n2-r5-m2`で20,000個のうち0個でした（seed 1、この例の実行とは別に1回だけ数えた値）。後者の構成では、一様乱数だけの試験は変異1をまず見つけません。この例のランダム試験は、最大振幅の直流を混ぜているので、300操作では6個のseedすべてで変異1を検出しました。

## 実行

```sh
python3 examples/local-cic-decimator/run.py --out artifacts/local-cic-decimator-smoke
python3 examples/local-cic-decimator/run.py --profile nightly --seed 17 --out artifacts/local-cic-decimator-nightly
python3 -m unittest discover -s examples/local-cic-decimator/tests
```

必要なツールはIcarus Verilogだけです。`--configuration`で構成を1つに絞れます。`--demo-bug 1`〜`7`は、通常のケースにも変異を入れ、リグレッションが終了コード1になることを確かめます。`--iterations`はランダム試験の操作数、`--seed`は開始seedです。`--out`には新しいディレクトリを指定します。

出力は[共通ランナー](../local-common/README.md)の形式で、`manifest.json`、ケースごとの`vectors.txt`・`simulation.log`・`wave.vcd`・`result.json`、`coverage.json`、`summary.json`、`junit.xml`です。JUnitは、2構成でsmoke 26件／nightly 30件です（構成ごとに、固定2＋ランダム1／3＋変異の検出8＋診断1＋目標の判定1）。

セルフテストは13件です。モデルの3通りの求め方の一致、幅が必要かつ十分であること、収まる範囲の端の値、固定シナリオの性質、計画の名前とラベル、全構成の実行と証跡、`--demo-bug`の終了コード、期待値を書き換えたときと出力をXにしたときのラベルを確かめます。Icarus Verilogが見つからなければ、skipせずに失敗します。

## 確認範囲と残る制限

- 途中の段を切り詰めない構成だけです。Hogenauerの切詰め（後ろの段ほど下位ビットを捨てて幅を減らす方法）と、その雑音の見積りは扱いません。切り詰める構成では、段ごとに幅が違い、この例の「全段が同じ幅だから折返しが打ち消される」という説明はそのままでは使えません。
- デシメーションだけです。補間（インターポレーション）、通過域の落込みの補償フィルター、周波数応答の判定は扱いません。判定はビット一致だけで、許容誤差や統計は使っていません。
- 逆圧はありません。出力は受け取り側を待たず、1サイクルだけ出ます。
- 幅と折返しの性質は、2構成・入力8ビットでの実行と、モデルの検算で確かめたものです。任意の段数・比・遅延についての証明ではありません。フォーマルの検査は入れていません。
- `out_valid`が0のサイクルの`out_data`は検査しません。下の確認記録にあるとおり、その値だけが変わる誤りは合格します。
- 利得は32ビットの整数で計算するので、（`RATE`×`DELAY`）の`STAGES`乗が2の31乗を超える構成は対象外です。
- 3つの計算（回路、移動和のモデル、積分器と櫛形のPython）は、同じ人が同じ仕様から書いています。外部の実装とは照合していません。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13、Icarus Verilog 14.0開発版で確かめました。Linuxとkirimasimでは実行していません。

- smoke（seed 17・3・5・99）とnightly（seed 17）が合格し、2構成とも14／14目標です。変異7種類は、2構成で予定のラベルどおり16件を検出し（変異7の`small-signal`での検出を含む）、変異1が`small-signal`で合格のまま残る診断2件も予定どおりでした。実行時間は、smoke・nightlyとも数秒です。
- セルフテスト13件が合格しました。
- RTLは、2構成・変異0〜7で`verilator --lint-only --Wall`（5.052）の警告0件です。`tools/check_tb_races.py`の候補は0件です。
- 既存の変異とは別に、作業用の写しのRTLへ小さな誤りを12個入れてsmokeにかけました。10個は、2構成とも固定シナリオが不合格にしました（`out_valid`が下がらない、`sync`が積分器・櫛形の遅延・2段目以降の積分器を残す、`sync`と同時のサンプルを積分する、2段目以降の櫛形が誤った値を覚える、櫛形がサンプルの前の積分器の値を読む、積分器をレジスタ経由でつなぐ、周期が2回目から短くなる、入力を符号なしで広げる）。合格のまま残った2個は、`out_data`を毎サンプル更新する誤りと、`out_data`のリセット値を変える誤りで、どちらも`out_valid`が0のサイクルの`out_data`だけが変わります。仕様が意味を定めていない値なので、動作に差が出ない誤りと判断しました。
