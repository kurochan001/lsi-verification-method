# 8b/10b符号の符号化・復号・ワード整列を、全数とフォーマルで確かめる

8b/10b符号は、8ビットのデータを10ビットの符号にして送る方式です。0と1の数をそろえて直流成分をなくし、同じビットが長く続かないようにして、受信側がクロックを取り出せるようにします。この例は、符号器・復号器・コンマによるワード整列の3つの回路を対象に、次のことを確かめる教材です。

- 全データ符号（256個）と全制御符号（12個）を、2つのランニングディスパリティ（それまでに送った1と0の差の符号）の両方で符号化した結果。
- 10ビットの全1024通りを、両方のディスパリティで復号器へ入れた結果（受理、ディスパリティ違反、符号違反）。
- 符号列の性質（符号ごとの1の数、累積の差、同じビットの連続、コンマの現れる位置）。
- 「復号(符号化(x))＝x」と、その逆向きの「復号器が受理する符号は、符号器が送る符号だけ」の、帰納法による証明。

シリアル通信の物理層に近い例は、[CRC・ACK・再送リンク](../local-retry-link/README.md)（フレームと再送）と[UART](../local-uart/README.md)（ビットのサンプル）にあります。ライン符号そのものを扱う例は、これが最初です。

## 仕様

ビットの名前は慣例に従います。8ビットのデータは`HGFEDCBA`（`A`がビット0）、10ビットの符号は`abcdei fghj`で、`a`を最初に送ります。この例では符号を`code[9:0]`に入れ、`code[9]`が`a`です。2進数で書いた符号は、そのまま送る順になります。下位5ビット（`EDCBA`、以下x）を6ビットに、上位3ビット（`HGF`、以下y）を4ビットにします。データ符号は`D.x.y`、制御符号は`K.x.y`と書きます。

### 符号器（[`enc_8b10b_comb.sv`](rtl/enc_8b10b_comb.sv)、[`enc_8b10b.sv`](rtl/enc_8b10b.sv)）

- `valid`のサイクルに、`data`・`k`・現在のディスパリティから`code`を組合せ回路で出します。ディスパリティ`rd`（0がマイナス、1がプラス）は、リセットでマイナスになり、`valid`のサイクルの後に更新します。
- 6ビットの部分は、1の数が3個（釣り合い）か、マイナスのとき4個・プラスのとき2個です。`D.7`だけは、釣り合った`111000`と`000111`を、ディスパリティで使い分けます。4ビットの部分も同じ考え方で、`D.x.3`が`1100`と`0011`を使い分けます。
- `D.x.7`の4ビットは`1110`／`0001`ですが、6ビットの末尾と合わせて同じビットが5個続く場合は、代わりの`0111`／`1000`を使います（マイナスでxが17・18・20、プラスでxが11・13・14）。
- 制御符号は`K.28.0`〜`K.28.7`と、`K.23.7`・`K.27.7`・`K.29.7`・`K.30.7`の12個です。それ以外の値で`k`を立てると、`k_err`を1にして`code`を0にし、ディスパリティを動かしません。

### 復号器（[`dec_8b10b_comb.sv`](rtl/dec_8b10b_comb.sv)、[`dec_8b10b.sv`](rtl/dec_8b10b.sv)）

- `valid`のサイクルに、`code`と現在のディスパリティから、`data`・`k`と2つの違反を組合せ回路で出します。
- `code_err`：どちらのディスパリティでも、符号器が送ることのない符号です。`data`と`k`は0にします。
- `disp_err`：符号としては存在するが、今とは逆のディスパリティのときにだけ送られる符号です。値は復号します。
- ディスパリティは、受理したかどうかに関係なく、受け取った10ビットの1の数で更新します（6個以上ならプラス、4個以下ならマイナス、5個なら保持）。

違反の後の扱い（ディスパリティの更新の仕方、`data`を0にすること）は、この教材が決めた仕様です。

### ワード整列（[`comma_align.sv`](rtl/comma_align.sv)）

- 1サイクルに1ビット（`bit_valid`のとき`bit_in`）を受け取ります。直近の10ビットの先頭7ビットがコンマ（`0011111`または`1100000`）なら、その10ビットをワードの境界とします。
- 境界が決まった後は、10ビットごとに`word`と1サイクルの`word_valid`を出します。今の境界と違う位置でコンマを見つけたら境界を移し、`realigned`を1サイクル出します。
- `align_en`が0の間は、境界と違う位置のコンマを無視します。
- リセットの後、受信が10ビットに満たない間は、コンマとして扱いません。

## 構成と期待値の作り方

期待値は、RTLとは別の書き方をした[Pythonのモデル](model.py)から作ります。

| | 書き方 |
| --- | --- |
| 符号器のRTL | 6ビットと4ビットの符号を、値ごとに書き並べた表 |
| モデルの符号化 | 規則から符号を作る（1が3個ならそのまま0を付ける、2個なら1を付ける、1個・4個なら決まった形と補数、規則が当てはまらない6つの値だけ個別に指定） |
| 復号器のRTL | 6ビットと4ビットを別々に復号し、2つをつなぐ規則（ディスパリティの整合、代わりの`.7`の条件、制御符号の条件）で受理を決める |
| モデルの復号 | モデルの符号化を全文字・両ディスパリティについて実行し、10ビット符号から文字への対応表を作って引く |

RTLの表もモデルの規則も、同じ人が同じ公知の符号を思い出して書いたものです。両者と独立な基準は、次の2種類です。

- **広く印刷されている3つの符号**：`K.28.5`が`0011111010`／`1100000101`、`D.21.5`が`1010101010`、`D.10.2`が`0101010101`。セルフテストがモデルと照合します。
- **符号表そのものの性質**：どの符号も1の数が4・5・6個のどれかであること、1が多い符号はマイナスのときにだけ使われてディスパリティを反転させること、1つの10ビット符号が2つの文字に対応しないこと、同じビットの連続が全文字の全組合せで5以下であること、コンマが`K.28.1`・`K.28.5`・`K.28.7`の先頭にしか現れないこと。セルフテストが全数で確かめます。

テストベンチ（[`linecode_tb.sv`](tb/linecode_tb.sv)）は、1行が1クロックのベクトルで3つの回路を動かし、毎サイクル、全出力をモデルの値と`!==`で比べます。これとは別に、モデルを使わない監視を2つ持ちます。符号器が送ったビット列について、同じビットの連続が5を超えないこと（`LC_RUN`）と、1と0の差の累積が±1に収まること（`LC_DISPARITY`）です。

構成は`codec`の1つです。固定シナリオ（4,549行）とランダム（smokeは1 seed、nightlyは3 seed）を実行します。

## 要求と目標

要求は7個、目標は23個です。目標はすべて固定シナリオだけで届くようにしてあり、ランダムには任せていません（セルフテストが確かめます）。

| 要求 | 内容 | 目標 |
| --- | --- | --- |
| `LC-ENCODE` | 全データ符号・全制御符号を両ディスパリティで符号化。制御符号でない制御要求は`k_err` | 全データ×両ディスパリティ（512通り）、全制御×両ディスパリティ（24通り）、不正な制御要求（244通り）、文字のないサイクルでの保持 |
| `LC-BALANCE` | 符号のディスパリティと同じビットの連続 | `D.7`の両方の形、代わりの`.7`、符号の中での5連続、2つの符号にまたがる5連続 |
| `LC-DECODE` | 全1024符号を両ディスパリティで復号 | 2048通り、符号違反、ディスパリティ違反 |
| `LC-ERROR` | 伝送誤りの扱い | 全ビット位置の1ビット反転、違反の後の復号の継続、遅れて現れるディスパリティ違反 |
| `LC-ALIGN` | コンマによる整列 | 10ビット未満ではコンマにしない、最初のコンマ、両方の極性、境界どおりのコンマ、再整列、ビットのないサイクル |
| `LC-ALIGN-ENABLE` | 整列の停止 | 止めている間のコンマの無視、`K.28.7`の後ろにできる偽のコンマ |
| `LC-RESET` | 動作中のリセット | ディスパリティと整列の状態の初期化 |

符号器のディスパリティは、試したい側と違うときに、釣り合っていない符号（`D.3.0`）を1つ送って反転させます。復号器のディスパリティは、1が6個または4個の符号を1つ入れてそろえます。

## 符号表から分かったこと

セルフテストが全数で数えた結果です。

- 符号器が送る10ビット符号は464種類です（釣り合った符号のうち72種類は、両方のディスパリティで使われます）。
- どちらのディスパリティでも、1024通りの内訳は、受理268、ディスパリティ違反196、符号違反560です。
- **1ビットの誤りは、その場では3分の1ほど見つかりません。** 全文字×両ディスパリティ×10ビット位置の5,360通りのうち、符号違反が1,848、ディスパリティ違反が1,592で、残る1,920通り（約36%）は、別の文字として誤りなしで受理されます。この1,920通りは、すべて復号器のディスパリティを符号器とずらします。そのため、後の符号でディスパリティ違反として現れますが、どの符号が誤っていたかは分かりません。固定シナリオは、誤ったデータが違反なしで通り、3文字後に違反が出る場面を1つ含みます。
- **コンマは、`K.28.7`の後ろにだけ、境界からずれた位置に現れます。** 全文字の全組合せで、2つの符号にまたがるコンマは、`K.28.7`の後ろの5ビット目から始まるものだけです（続く文字が`D.3.0`などの場合）。固定シナリオは、整列を許したままこの並びを受けると境界が誤った位置へ動くことと、整列を止めていれば動かないことを示します。通常の通信で`K.28.7`を使わない理由です。

| 2 | 符号器 | `D.20.7`で代わりの`.7`を使わない | `LC_CODE` | `ap_roundtrip` |
| 3 | 符号器 | ディスパリティの更新が4ビットの部分を見ない | `LC_ENC_RD` | `ap_rd_step` |

## フォーマル検証

[`formal.py`](formal.py)は、[共通フォーマルランナー](../local-formal-common/README.md)で、[`linecode_formal.sv`](linecode_formal.sv)の性質を確かめます。対象は符号器と復号器で、ワード整列は含みません。タスクは12個です。

| タスク | 方式 | 内容 |
| --- | --- | --- |
| `codec-proof` | k帰納法（深さ2） | 下の11個の性質を、すべての文字・両ディスパリティ・すべての文字の並び（文字のないサイクルとリセットを含む）について非有界に証明 |
| `scenario-cover` | 到達 | 8個の到達目標（両方の極性のコンマ、`D.7`のプラスの形、代わりの`.7`、2つの符号にまたがる5連続、偽のコンマ、ディスパリティ違反、釣り合っているのに拒否される符号） |
| `detect-mutation1`〜`7` | 有界 | 変異ごとに、表の性質の反例 |
| `forward-misses-mutation5`〜`7` | k帰納法 | 復号器の変異を入れても、前向きの性質だけなら証明が成立することの記録 |

性質は、2つの向きに分かれます。

- **前向き（符号器→復号器）**：
  - `ap_roundtrip`：符号器の出力を復号すると、元の`data`と`k`に戻り、違反は出ない。
  - `ap_k_err`：`k_err`は、制御符号でない値に`k`を立てたときだけ。
  - `ap_disparity`・`ap_rd_step`：符号の1の数は4・5・6個で、6個はマイナスのときだけ、4個はプラスのときだけ。ディスパリティはそれに従って動く。
  - `ap_run`：同じビットの連続は、1つの符号の中でも、直前の符号とつないでも5以下。
  - `ap_comma`：コンマは、3つの制御符号の先頭にだけ現れる。2つの符号にまたがるコンマは、直前が`K.28.7`のときだけ。
- **後ろ向き（任意の10ビット→復号器→符号器）**：ハーネスの入力`free_code`と`free_rd`には制約を置かないので、全1024符号×両ディスパリティについての性質になります。
  - `ap_accept`：復号器が違反なしで受理した符号は、復号した文字を同じディスパリティで符号化した結果と一致する。
  - `ap_other`：ディスパリティ違反にした符号は、逆のディスパリティで符号化した結果と一致する。
  - `ap_dec_rd`：復号器のディスパリティは、10ビットの1の数だけで決まる。

2つの符号にまたがる性質を帰納法で証明するために、補助の性質を2つ置いています。`ai_previous`は、ハーネスが覚えている直前の符号と符号器の今のディスパリティが、直前の文字を符号化した結果と一致することです。`ai_rd_equal`は、符号器と復号器のディスパリティが一致することです。どちらも仮定ではなく、アサーションとして同時に証明します。仮定は、最初のサイクルのリセット（`as_initial_reset`）だけです。

前向きの性質は、復号器へ「符号器が送る符号」しか入れません。そのため、復号器の変異5・6・7を入れても、前向きだけの証明は成立します。この3つのタスクは、「往復が証明できても、復号器が余計な符号を受理しないことは分からない」ことの記録です。後ろ向きの性質と、シミュレーションの全1024符号の試験が、それを確かめます。

変異6は、反例の選び方しだいで`ap_accept`と`ap_other`のどちらも破れます。最初は、macOSで得られた`ap_other`の反例を予定にしていましたが、2026-11-21のLinuxのCIでは同じ固定版のツールが`ap_accept`の反例を選び、予定と違う性質の反例として不合格になりました。そこで、変異6のタスクだけは後ろ向きの性質のうち`ap_other`だけを有効にし（`SIDE=3`）、どの反例でも予定の性質が破れるようにしました。ほかのタスクと性質の内容は変えていません。

## 実行

```sh
# シミュレーション（Icarus Verilog）
python3 examples/local-linecode-8b10b/run.py --out /tmp/linecode-smoke
python3 examples/local-linecode-8b10b/run.py --profile nightly --out /tmp/linecode-nightly

# フォーマル（YoWASP版Yosys・SBY、Z3）。フォーマル用のPython環境で実行する
python examples/local-linecode-8b10b/formal.py --out /tmp/linecode-formal

# セルフテスト
python3 -m unittest discover -s examples/local-linecode-8b10b/tests
```

`--seed`でランダムの開始seed、`--iterations`でランダムの長さ（既定はsmoke 400、nightly 3000。行数はその約4倍）、`--demo-bug 1..9`で正常な試験に変異を入れて不合格になることを確かめられます（終了コード1）。出力先には、`manifest.json`、ケースごとのベクトル・ログ・波形、`coverage.json`、`summary.json`、`junit.xml`が残ります。JUnitは、シミュレーションがsmoke 12件／nightly 14件、フォーマルが12件です。セルフテストは21件です。

## 確認範囲と残る制限

- 符号表は、公知の8b/10b符号（WidmerとFranaszekの1983年の論文の方式。IEEE 802.3の1000BASE-Xの章にも同じ表があります）を、表を見ずに規則と記憶から書いたものです。論文や規格の表・節番号とは**照合していません**。外部の基準は、上に挙げた3つの符号と、符号表の性質だけです。規格への適合の確認ではありません。
- 違反の後の復号器の動作（ディスパリティの更新、出力の値）は、この教材の仕様です。規格の受信側の規則とは照合していません。
- ワード整列は、コンマを1回見つければ境界を決める最小の方式です。複数回の確認、同期の喪失の判定、符号違反の数による再同期は扱いません。
- 整列回路と復号器をつないだ受信経路全体（シリアルのビットから文字まで）は、1つの試験としては確かめていません。符号器→復号器はワード単位、整列はビット単位で、別々に確かめています。
- フォーマルの証明は、符号器と復号器だけです。整列回路の変異8・9は、シミュレーションだけが検出します。
- シリアライザー、クロックの再生、ビットの誤り率、スクランブラーとの組合せ、64b/66bなどほかのライン符号は対象外です。
- 単一クロック・同期リセットの回路です。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13（フォーマルは3.14）、Icarus Verilog 14.0開発版、YoWASP版Yosys 0.70とSBY、Z3 4.15.3で確かめました。

- シミュレーション：smoke（seed 17・3・5）とnightly（seed 17〜19）が合格し、23目標すべてに届きました。nightlyは、統合ランナーが渡すコマンド上限（`--timeout 60`）を付けて実行しています。`--demo-bug 3`は終了コード1でした。
- フォーマル：12タスクが予定どおりの結果でした（証明1、到達1、反例7、前向きだけの証明が成立する記録3）。ほかの実行と重なって負荷の高い状態で、証明が約60秒、全体で約5分でした。負荷のない状態での時間は測っていません。
- セルフテスト：21件が合格しました（Icarusとフォーマルのツールを使うテストを含みます）。
- RTLの5モジュールは、Verilator 5.052の`--lint-only --Wall`で、変異0〜9のすべてについて警告0件でした。`check_tb_races.py`は、この例について候補0件でした。
- 既存の変異とは別に、作業用の写しのRTLへ小さな誤りを13個入れ、smokeにかけました（符号器4、復号器4、整列3、ディスパリティのレジスタ2）。最初は12個が固定シナリオで不合格になり、1個（受信が9ビットの時点でコンマを検出する誤り）が合格のまま残りました。リセットの直後に、リセットで入った0と合わせるとコンマに見える9ビットを与える場面がなかったためです。この場面と目標`align/needs-ten-bits`を固定シナリオへ足し、13個すべてが固定シナリオで不合格になることを確かめました。
- 作る途中で、組合せ回路の表を`always @*`の`case`で書いた版は、Icarusで、リセット後の最初の文字（値0）の符号がXになりました。入力が時刻0から変わらず、ブロックが一度も評価されなかったためと考えています。表を関数にして`assign`で使う形に直し、Xは出なくなりました。

Linuxとkirimasimでは実行していません。統合ランナー（`tools/run_regression.py`）経由の実行は、登録の前なので行っていません。
