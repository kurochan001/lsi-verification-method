# LBIST：疑似ランダム刺激・署名圧縮・エイリアシングを検証する

4入力・4出力の小さな組合せ回路に、8ビットLFSRのPRPGと8ビットMISRを接続した教材です。16／32パターンの実行、署名比較、開始・終了・中断、通常出力の隔離を確認します。[DFTの検証手順](../../docs/method/dft-verification.md)から、[内部スキャン・ATPG](../local-scan-atpg/README.md)、[MBIST](../local-mbist/README.md)、[JTAG](../local-jtag-tap/README.md)との役割の違いも確認できます。

この例は組合せ回路へ直接パターンを与える簡略な並列LBISTです。スキャン挿入やシフト／キャプチャのクロック制御を実装する例ではありません。製品のLBISTにある準備・終了シーケンスと署名確認の考え方は、[TIのLBIST資料](https://software-dl.ti.com/mcu-plus-sdk/esd/AM243X/10_01_00_32/exports/docs/api_guide_am243x/SDL_LBIST_PAGE.html)を参照しています。製品のレジスタや回路は転載していません。

## 1. 刺激と応答の流れ

```mermaid
flowchart LR
  accTitle: 小規模な並列LBISTの刺激と署名
  accDescr: 非ゼロseedのPRPGで組合せ回路を動かし、4ビットの実応答をMISRへ圧縮する。制御回路が規定パターン数と完了時の署名比較を管理する。
  P["8bit PRPG<br/>非ゼロseed"] --> D["4入力・4出力<br/>組合せDUT"]
  D --> M["8bit MISR<br/>実応答を圧縮"]
  M --> R["規定回数の完了後<br/>期待署名と比較"]
```

- PRPGの更新は`{q[6:0], q[7]^q[5]^q[4]^q[3]}`です。下位4ビットをDUTへ与えます。非ゼロの255状態を巡回し、ゼロは抜け出せないので開始時に拒否します。
- MISRの更新は`((s << 1) & 0xff) ^ (s[7] ? 0x1d : 0) ^ response`です。4本の応答を下位4ビットへ並列に入れます。初期署名は0です。
- 各busyサイクルで、更新前のPRPGをDUTへ与え、その応答を署名に取り込みます。最後の応答を含む次署名と、開始時に保持した期待署名を比較します。
- 同じ多項式でも、ビット順・初期値・入力位置・更新回数が異なれば署名は変わります。この定義を使う回路だけの期待値です。

独立したPythonモデルは、DUTを16入力の真理値表、PRPGとMISRをビットのリストで表します。RTLの中間配線を写さず、応答・PRPG・署名・受理数を毎サイクル照合します。seed 1の期待署名は16パターンで`0x62`、32パターンで`0x04`です。

## 2. 制御とテストモードの契約

| 条件 | 期待する動作 |
| --- | --- |
| test_mode=0のstart | 開始しない。通常入力に対する機能出力を返す |
| test_mode=1、アイドル、非ゼロseedのstart | seedと期待署名を保持し、busy=1。署名・件数・以前の結果をクリア |
| ゼロseedのstart | 開始しない。seed_error=1。正常な次のstartで解除 |
| busy中のstart・設定変更 | 進行を維持し、保持したseed・期待署名を変更しない |
| 規定回数の応答取り込み | busy=0、done=1。最後の応答を含む署名を比較してfailedを設定 |
| 完了後、次startまで | done・署名・failed・件数を保持 |
| 実行中のリセット・test_mode解除 | 未完了の試験を中断し、done・署名・状態をクリア。中断を合格完了へ数えない |
| test_mode=1 | 通常出力は0へ隔離。解除すると通常入力の組合せ出力へ戻る |

リセットはアクティブLowの同期リセットです。パターン数は構成に固定し、開始の次のクロックから16／32回を数えます。通常入力とテスト入力の切替はデジタルな選択であり、クロック切替・物理的なグリッチを検査するものではありません。

## 3. 故障とエイリアシング

指定した4出力それぞれのsa0／sa1、計8個の単一縮退故障を注入します。seed 1の両構成で、無故障時と異なる最終署名になり、RTLのfailedが立つことを確認します。`COUNT detected_faults=8`は、完了時の実際のfailedを故障IDごとに数えた値です。対象はこの8個で、内部の全ノード・端子・配線・スキャンセルを列挙した故障集合ではありません。

別の診断ケースでは、最初の応答のbit 0、次の応答のbit 1だけを反転します。このMISRでは最初の差`0x01`が次の更新で`0x02`となり、2回目の差`0x02`と打ち消し合います。**応答は2回異なるのに、最終署名が一致してfailed=0となります。** 実際の応答差2回と最終署名の両方をRTLで確認し、エイリアシングを再現できた診断として記録します。

この2回の反転は、8個の永久的な縮退故障とは異なる限定した応答誤りモデルです。診断ケースの観測は通常ケースの17目標へ加算しません。`failed=0`を「全故障なし」や「製造故障の検出率100%」へ読み替えません。エイリアシング確率も、この例からは評価しません。

`fault_*`と`response_xor`は検証専用の故障注入ポートです。実チップのテストアクセス方式や、実機で任意の故障を注入できることを示しません。

## 4. 実行と検出力の確認

Python 3.10以上、Icarus Verilogの`iverilog`・`vvp`を使い、リポジトリのルートで実行します。出力先は毎回新しくします。

```sh
python3 examples/local-lbist/run.py --out artifacts/lbist-smoke
python3 examples/local-lbist/run.py --profile nightly --out artifacts/lbist-nightly
python3 tools/run_regression.py --example local-lbist --out artifacts/lbist-campaign
python3 -m unittest discover -s examples/local-lbist/tests -v
```

| 変異 | 誤実装 | 期待する検出ラベル |
| --- | --- | --- |
| 1 | PRPGを進めない | `LBIST_SEQUENCE` |
| 2 | MISR更新へ余分な1ビットを入れる | `LBIST_SIGNATURE` |
| 3 | 1パターン早く完了する | `LBIST_CONTROL` |
| 4 | 署名が不一致でもfailedを立てない | `LBIST_RESULT` |

通常の固定ケースには、無故障の3 seed、誤った期待署名、8故障、実行中の再開始と設定変更、途中中断と再実行を含めます。ランダム区間は追加で4回、nightlyは20回×3 seedの試験を実行します。`--iterations`はこの追加試験数です。固定ケースと診断を減らしません。

2構成のJUnit合計はsmoke 16件／nightly 20件です。17目標は構成ごとに通常実行だけで達成します。[共通ランナー](../local-common/README.md)で、終了コード・ラベル・件数・カバレッジ・入力ハッシュ・波形を照合します。

10セルフテストは、全非ゼロseedの255周期、固定した6個の署名、全16入力×無故障／8故障のRTL照合、両構成でのエイリアシング、4変異を確認します。通常出力の隔離を外す誤りと、最後の応答の前に署名比較する誤りを、テストベンチが拒否することも確認します。

## 5. 対象外と製品への展開

実スキャン挿入、複数チェーン・圧縮器・phase shifter、Xマスキング、テストポイント挿入、OCCとat-speed capture、遷移・ブリッジ故障、テスト電力、ATE形式への変換は含みません。[DFTの手順](../../docs/method/dft-verification.md)で、製品側の故障集合・実装・タイミング・復帰条件へ展開してください。
