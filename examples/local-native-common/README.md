# C++モデル・SPICE協調例の共通実行処理

[C++参照モデル](../local-cpp-reference/README.md)と[SPICE協調](../local-spice-cosim/README.md)で、Verilatorのビルド、実行結果の分類、件数・波形・ソースの照合を共通化します。各分野の期待値計算と判定規則は、それぞれの例に置いています。

```mermaid
flowchart LR
  accTitle: ネイティブ検証例の判定経路
  accDescr: 予定を固定し、ビルドと実行の成功、予定件数と波形を確認した通常試験だけから構成別の到達目標を集計する。
  P["ソース・構成・予定判定を固定"] --> B["VerilatorとC++でビルド"]
  B --> X["子プロセスを有限時間で実行"]
  X --> C["終了・RESULT・COUNT・VCD・CSVを照合"]
  C --> G["合格した通常試験だけで到達目標を集計"]
  G --> E["JUnit・JSON・ソース再照合"]
```

| 結果 | 必要な条件 |
| --- | --- |
| 通常試験の合格 | 終了0、唯一の完了記録、予定件数と全COUNTの一致、VCDとCSVの存在 |
| 意図した不具合の検出 | ビルド成功、予定した唯一のCHECK_FAIL、非ゼロ終了、波形の存在 |
| エラー | 起動・ビルド・タイムアウト・件数欠落・別の失敗ラベル・証跡欠落 |

設定は`--profile smoke|nightly`、`--seed`、`--timeout`、`--build-timeout`、`--cxx`、`--verilator`です。追加の外部ツールは各例の引数で指定します。入力列と実行に使う回路もハッシュに含めます。ngspiceの外部ライブラリーは専用のスナップショットでさらに照合します。

`build.json`・`builds.json`には実際のコンパイルコマンド、`executions.json`・試験別`result.json`には実行と判定を保存します。判定数・出力数・クロック数・アナログ解析点数は別の集計として扱います。合格だけで参照モデルの完全性や製品の適合性を保証するものではありません。
