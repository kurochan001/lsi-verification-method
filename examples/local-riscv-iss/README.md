# RISC-Vのパイプラインを、命令セットシミュレーターと1命令ずつ比べる

CPUの検証で広く使われる、命令セットシミュレーター（ISS）との逐次比較の教材です。5段パイプラインのRV32Iコアが退出させた命令を、Pythonで書いたISSが同じプログラムを実行した記録と、1命令ずつ順に比べます。ISSは命令セットの定義だけを実装し、パイプラインを知りません。誤りが出やすいのは、命令の間のデータ依存、ロードの直後の使用、分岐による取消し、データメモリの待ちが重なるところです。固定の命令列と、制約付きのランダムな命令列の両方を使います。

## 退出した命令を順に比べる

```mermaid
flowchart LR
  accTitle: ISSとの逐次比較の構成
  accDescr: 固定の命令列とランダムな命令列をアセンブルし、ISSで実行して退出の記録を作る。記録には依存関係から求めた網羅の印と、各データアクセスの待ちサイクル数を付ける。テストベンチは命令とデータをメモリに読み込んでコアを動かし、退出した命令を記録と順に比べる。
  G["固定の命令列<br/>ランダムな命令列"] --> A["アセンブラ"]
  A --> I["ISS<br/>命令ごとの退出記録"]
  A --> M["命令メモリ"]
  I --> E["期待する退出の列<br/>網羅の印・待ちサイクル"]
  M --> C["5段パイプラインのコア"]
  E --> T["テストベンチ<br/>退出ごとに順に照合"]
  C --> T
```

比べるのは、命令が退出したときの、命令の番地と命令語、書き込んだレジスタと値、ロード・ストアの番地とデータです。パイプラインの中のタイミングはISSと異なるので、比べません。分岐の後に取り込んで取り消した命令は退出しないので、記録にも現れません。

## 対象のコア

[`rv32i_core.sv`](rtl/rv32i_core.sv)は、IF・ID・EX・MEM・WBの5段のパイプラインです。RV32Iの整数命令のうち、ワード単位のロード・ストア、分岐、ジャンプ、演算の32命令を実行します。EBREAKで停止します。命令メモリとデータメモリは分かれていて、データメモリは応答を待たせることがあります。

| 状況 | 対処 |
| --- | --- |
| 直前の命令の結果を使う | EX/MEMから転送する |
| 2つ前の命令の結果を使う | MEM/WBから転送する。両方にあれば新しい方を使う |
| 3つ前の命令の結果を使う | レジスタファイルが、同じサイクルに書き込む値をそのまま渡す |
| ロードの直後に、その結果を使う | 1サイクル空けて、MEM/WBから転送する |
| 分岐の成立・ジャンプ | EXで判定し、後続の2命令を取り消す |
| データメモリの待ち | 全段を止め、WBには空きを入れる |
| x0への書込み | 捨てる。転送もしない |

データメモリの待ちには、注意が必要な点が1つあります。待ちの最初のサイクルにWBにあった命令は、そのサイクルで退出し、次のサイクルには転送元がなくなります。そのため、EXの命令は、待っている間に転送された値を保持し直します。

| サイクル | WB | MEM | EX |
| --- | --- | --- | --- |
| t | `addi x24, x0, 77`（退出） | `lw x25, 12(x10)`（待ち） | `add x26, x24, x4`：x24をWBから転送 |
| t+1 | 空き | `lw x25, 12(x10)`（待ち） | `add x26, x24, x4`：tで保持した値を使う |

## ISSと退出の記録

[`iss.py`](iss.py)には、アセンブラ、ISS、命令列の生成を置いています。ISSは、RISC-Vの非特権仕様の定義どおりに1命令ずつ実行し、番地0からEBREAKまでの退出を記録します。パイプラインの段や転送は一切持ちません。

ISSとアセンブラが誤っていると、比較は誤ったものを正解にします。そこでセルフテストで、アセンブラが作る命令語をLLVMの`llvm-mc`（RV32向け）の出力と照合し、ISSの結果を手で計算した値と比べます。

テストベンチ[`core_tb.sv`](tb/core_tb.sv)は、退出があるたびに、次に期待する記録と比べます。

| 検査ラベル | 内容 |
| --- | --- |
| `ISS_FLOW` | 命令の番地か命令語が違う（制御の流れがずれた） |
| `ISS_DATA` | 書き込んだレジスタ・値、ロード・ストアの番地・データが違う |
| `ISS_END` | 退出の数が違う、停止しない、サイクルの上限を超えた |
| `ISS_X` | 退出や停止の信号が不定値 |

## 固定の命令列とランダムな命令列

固定の命令列は、32命令すべてと次の内容を順に含みます。

1. 境界値（0x80000000、0xffffffff、0x7fffffff）を使った演算命令
2. 距離1・2・3の依存と、同じレジスタへの2つの書込みのうち新しい方の転送
3. x0への書込みと、その直後のx0の読出し
4. ロードの直後の使用、ロードした値のストア、ストアとロードの往復、ロードした値での分岐
5. 待っているロード・ストアをはさんだ転送（上の表の場面）
6. 6種類の分岐のそれぞれの成立・不成立と、取り消される命令
7. JALと、直前に書いたレジスタを基底にしたJALR（飛び先の最下位ビットを0にする場合を含む）
8. 3回まわるループ（後ろへの分岐が2回成立する）

データアクセスは順に0〜3サイクル待たせ、上の5の場面では2サイクル以上待たせます。

ランダムな命令列は、[riscv-dv](https://github.com/chipsalliance/riscv-dv)のような命令生成器の考え方を小さく写したものです。分岐とジャンプは前方だけにして、必ず終わるようにします。x10はデータ領域の基底に固定し、ほかの命令はx1〜x9を使います。半分の確率で直近3命令が書いたレジスタを読み、依存を多く作ります。x0への書込みも4%混ぜます。データアクセスの25%は1〜3サイクル待たせます。

退出の記録には、ISSの実行順から求めた依存の印（距離、ロードの直後の使用、分岐の成否など）を付けます。テストベンチは、記録と一致した退出の印を目標に加算します。データメモリの待ちは、テストベンチが自分で観測します。[要求カタログ](requirements.json)は4要求・16目標で、固定の命令列だけで16目標に達します。

## 意図的な誤実装

| 番号 | 誤実装 | 期待する検出ラベル |
| --- | --- | --- |
| 1 | x0に宛てた結果も転送する | `ISS_DATA` |
| 2 | ロードの直後の使用で、1サイクル空けない | `ISS_DATA` |
| 3 | JALRの飛び先を、転送前のレジスタ値で計算する | `ISS_FLOW` |
| 4 | データメモリの待ちの間、EXが転送された値を保持し直さない | `ISS_DATA` |

seed 17〜19のランダムな命令列だけで実行すると、変異1〜3は300命令でもすべてのseedで検出できます。変異4は、300命令では3つのseedのうち2つ、2000命令では3つすべてで検出しました。変異4は、待ちと転送が同じサイクルに重なったときだけ現れます。データアクセスを1つも待たせない場合は、固定の命令列でもランダムな命令列でも検出できません。セルフテストで、この前提を確かめています。

## 実行

```sh
python3 examples/local-riscv-iss/run.py --out artifacts/riscv-iss
python3 examples/local-riscv-iss/run.py --profile nightly --out artifacts/riscv-iss-nightly
python3 -m unittest discover -s examples/local-riscv-iss/tests -v
```

[共通手順](../local-common/README.md)を使います。構成は`rv32i`の1つです。`--iterations`はランダムな命令列の命令数で、smokeは300命令×1 seed、nightlyは2000命令×3 seedです。JUnitはsmokeが7件、nightlyが9件です。セルフテストは8件で、アセンブラの照合にはHomebrew版LLVMなどの`llvm-mc`と`llvm-objcopy`が必要です。

## 確認範囲

2026-10-31に、Python 3.14.7、Icarus Verilog 14.0開発版で、smoke／nightly、16目標、4種類の変異、セルフテスト8件が成功しました。アセンブラの照合にはLLVM 23.1.4の`llvm-mc`を使いました。Verilator 5.052の`--lint-only -Wall`では、変異0〜4のどれでも警告はありません。

対象は、RV32Iのうちワード単位のロード・ストアと演算・分岐・ジャンプです。バイト・ハーフワードのアクセス、境界に合わない番地、FENCE・ECALL・CSR、例外と割り込み、特権命令、圧縮命令、M拡張、キャッシュ、分岐予測は扱いません。比較は与えた命令列の範囲で行うもので、すべての命令列について正しさを示すものではありません。形式的に示す方法には、退出のポートを使う[riscv-formal](https://github.com/YosysHQ/riscv-formal)があります。
