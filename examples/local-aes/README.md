# AES-128の暗号化コアを、公開の例・独立したモデル・固定の時間・消去で確かめる

AES-128の暗号化コアを、次の4つの観点で確かめる教材です。

- **値**：公開の例（FIPS 197の付録）と、標準ライブラリだけで書いた独立のモデルの暗号文に一致する。
- **時間**：受け付けてから結果までのクロック数と、公開の信号（ready・busy・out_valid・progress）の列が、鍵とデータに依らない。
- **消去**：中断（cancel）・リセット・結果の受け取りの後に、状態・ラウンド鍵・ラウンド定数が0になる。
- **出力のゲート**：結果を出していない間、出力の端子に途中の状態が見えない。

時間と消去は、シミュレーションに加えて、2つの複製を比べるフォーマルの証明（自己合成）でも確かめます。

**対象外**：電力・電磁波などのサイドチャネルへの耐性、故障注入攻撃への対策、マスキングは扱いません。ここで確かめる「時間が一定」は、デジタルの端子のクロック単位の性質です。認証・適合の主張もしません。復号、AES-192とAES-256も扱いません。

## 仕様

| 端子 | 向き | 意味 |
| --- | --- | --- |
| `clk`、`rst_n` | 入力 | クロックと、同期のリセット（Lowで有効） |
| `start`、`key[127:0]`、`block[127:0]` | 入力 | `ready`のクロックに`start`が1なら、`key`と`block`を受け付ける |
| `cancel` | 入力 | 処理中・結果の保持中・待機中のどこでも処理を取り消して消去する。`start`と同じクロックなら`cancel`が優先 |
| `out_ready` | 入力 | 結果を受け取るクロック |
| `ready` | 出力 | 受け付けられる（処理中でも結果の保持中でもない） |
| `busy`、`progress[3:0]` | 出力 | 処理中と、何ラウンド目か（1〜10。待機中と保持中は0）。どちらも公開の情報 |
| `out_valid`、`out_block[127:0]` | 出力 | 結果と暗号文。`out_valid`が0の間、`out_block`は0 |

バイトの並びはFIPS 197と同じで、128ビットの値のバイト`i`はビット`[127-8i -: 8]`、バイト`4c+r`が列`c`の行`r`です。

- **時間**：受け付けたクロックに`block ^ key`と鍵を取り込み、続く10クロックで1ラウンドずつ処理します。ラウンド鍵は、そのクロックで1つ先へ進めます。受け付けたクロックから11クロック目に`out_valid`が1になり、`out_ready`まで保持します。受け取った次のクロックから、次を受け付けます。
- **消去**：最後のラウンドで、ラウンド鍵とラウンド定数を0にします。結果を受け取ったクロックで、状態も0にします。`cancel`とリセットは、3つとも0にします。待機中のコアは、データを1ビットも持ちません。
- 処理中に`key`と`block`が変わっても、受け付けた値で計算します。処理中と保持中の`start`は無視します。

## 期待値の作り方

期待値は3つの層に分けています。

1. **公開の例**：FIPS 197（2001年版）の付録の例を、数個だけ使います。付録Bの暗号化の例、付録C.1のAES-128の例、付録A.1の鍵の展開の例（1ラウンド目と10ラウンド目の鍵）、5.1.1節のS-boxの例（{53}→{ed}）です。付録と節の番号は記憶によるもので、本文とは照合していません。値は、次の独立のモデルが同じ値を出すことで確かめています。
2. **独立のモデル**（[`model.py`](model.py)）：回路とは書き方を変えています。

   | 部分 | モデル | 回路 |
   | --- | --- | --- |
   | S-box | GF(2^8)の逆元を全探索で求め、アフィン変換をビットごとの式で計算した表 | 254乗をべき乗の積で求め、回転したコピーの排他的論理和 |
   | ShiftRows・MixColumns | `[行][列]`の4×4の表と、一般の体の掛け算 | ビットの切り出しと`xtime` |
   | 鍵の展開 | 44語を先にすべて求める | 1クロックに1ラウンド鍵を求める |

   セルフテストは、回路と同じ254乗の方法でS-boxをPythonで計算し直し、モデルの表と一致することも確かめます。
3. **公開の信号の時刻表**（`run.py`の`Plan`）：鍵もデータも見ずに、`ready`・`busy`・`out_valid`・`progress`の期待値を作ります。テストベンチは毎クロック、コアをこの時刻表と比べるので、どの入力でも制御の列が同じであることを確かめていることになります。セルフテストは、同じ公開の入力に違う鍵とデータを与えた2つの時刻表が、制御の列で一致し、暗号文の列で違うことを確かめます。

## 要求と目標

| 要求 | 内容 | 目標 |
| --- | --- | --- |
| AES-VECTORS | FIPS 197の付録の例の暗号文 | 付録Bと付録C.1の結果 |
| AES-DATA | どの鍵とブロックでもモデルと同じ暗号文 | 全0・全1の鍵とブロック |
| AES-TIME | 時間と制御の列が鍵とデータに依らない | 11クロックの結果、処理中の入力の変化 |
| AES-FLOW | 受け付け、無視、保持、連続 | 待機の空き、処理中と保持中の`start`、保持、受け取った次のクロックの受付け |
| AES-CANCEL | 処理中・保持中・待機中の`cancel`とリセット | `cancel`の4場面、リセットの2場面 |
| AES-ZERO | 待機中と保持中の消去 | `cancel`・リセット・結果の受け取りの後の消去 |

22目標すべてに、固定シナリオ（184行）だけで届きます。ランダムは、一様な128ビットの鍵とブロックで、処理中の`start`、入力の変化、保持、途中の`cancel`とリセットを混ぜます。smokeは12操作×1 seed、nightlyは60操作×3 seedです。

## 判定のラベル

| ラベル | 判定 |
| --- | --- |
| `AES_TIMING` | 受け付けた処理の途中か、最初の結果のクロックで、制御の信号が時刻表と違う。または、結果までが11クロックでない |
| `AES_FLOW` | それ以外のクロックで、制御の信号が時刻表と違う |
| `AES_ZERO` | 待機中に状態・ラウンド鍵・ラウンド定数のどれかが0でない。または、保持中にラウンド鍵かラウンド定数が0でない（テストベンチがコアの内部のレジスタを読む） |
| `AES_LEAK` | `out_valid`が0なのに`out_block`が0でない |
| `AES_DATA` | 結果のクロックの暗号文がモデルと違う |

比較はすべて`!==`で行い、Xは不合格です。

## 変異

| 番号 | 誤り | 予定のラベル | フォーマル |
| --- | --- | --- | --- |
| 1 | 全0のブロックは5ラウンドで終える（データに依る時間） | `AES_TIMING` | `ap_timing`の反例 |
| 2 | `cancel`がラウンド鍵を消さない | `AES_ZERO` | `ai_idle_clear`の反例 |
| 3 | リセットが状態を消さない | `AES_ZERO` | `ai_idle_clear`の反例 |
| 4 | 処理中も`out_block`に状態を出す | `AES_LEAK` | `ai_gate`の反例 |
| 5 | S-boxの1要素（{53}）が違う | `AES_DATA` | 対象外 |
| 6 | ShiftRowsの向きが逆 | `AES_DATA` | 対象外 |
| 7 | MixColumnsの係数の1つが3ではなく1 | `AES_DATA` | 対象外 |
| 8 | ラウンド定数を還元なしで2倍する（9ラウンド目から誤る） | `AES_DATA` | 対象外 |
| 9 | 最後のラウンドでもMixColumnsを行う | `AES_DATA` | 対象外 |

9種類とも、固定シナリオで予定のラベルで検出します。

- **変異1はランダムでは見つかりません**：一様な128ビットのブロックが全0になることはないからです。計画には、変異1をランダムの入力だけで実行し、合格のまま終わることを確かめる診断（`random-misses-mutation1`）を入れています。固定シナリオは全0のブロックを含むので検出します。フォーマルの証明は、特定の値を用意しなくても、すべての入力について反例を見つけます。
- **変異8**は、ラウンド定数が0x80の次で誤るので、9ラウンド目と10ラウンド目の鍵だけが違います。

## フォーマル：2つの複製の比較

[`aes_ct_formal.sv`](aes_ct_formal.sv)は、2つのコアに同じ公開の入力（`rst_n`・`start`・`cancel`・`out_ready`）を与え、鍵とブロックは別々に任意にします。

- **`ap_timing`**：`ready`・`busy`・`out_valid`・`progress`が、すべてのクロックで一致する。
- **コアの中の補助の不変条件**：
  - `ai_round`：ラウンドは10以下。
  - `ai_idle_clear`：待機中は状態・ラウンド鍵・ラウンド定数が0。
  - `ai_valid_clear`：保持中はラウンド鍵とラウンド定数が0で、ラウンドも0。
  - `ai_gate`：`out_valid`が0なら`out_block`は0。

  仮定ではなく、アサーションとして証明します。
- **データパスの抽象化**：証明では、ラウンドの計算と鍵の展開の結果を、毎クロック任意の値に置き換えます（`` `ifdef FORMAL ``の中の`anyseq`）。この置換えで、性質は「どんなデータパスでも成り立つ」という、実際の回路より強い主張になります。データパスを残した版では、帰納段階が1分を超えても終わりませんでした。暗号文の値はこの証明の対象外で、シミュレーションがモデルと比べます。

| タスク | 方式 | 結果 |
| --- | --- | --- |
| `constant-time-proof` | k帰納法（深さ3） | 成立 |
| `scenario-cover` | 到達（深さ16） | 4目標（結果、処理中の`cancel`、保持、受け取った次のクロックの受付け）に到達 |
| `detect-mutation1`〜`4` | 有界検査（深さ16） | 予定の性質の反例 |
| `timing-proof-misses-mutation7` | k帰納法 | 成立（値の誤りは時間の証明には現れない、という診断） |

証明の深さは3です。コアの中の不変条件は2クロック目から確かめるので、1ステップ余分に要ります。共通フォーマルランナーの`--demo-bug`は1〜4を受け付け、この例ではどれも証明を不合格にする変異です。

## 追加で入れた誤り

既存の変異とは別に、作業用の写しのRTLへ小さな誤りを12個入れ、smokeを実行しました。

| 誤り | smokeの結果 |
| --- | --- |
| `xtime`の還元の定数が違う | `AES_DATA` |
| `ready`が保持中を見ない | `AES_TIMING`（最初の結果のクロックで食い違うため） |
| 結果を受け取っても状態を消さない | `AES_ZERO` |
| 最後のラウンドの判定が9 | `AES_TIMING` |
| 終わりでラウンド定数を消さない | `AES_ZERO` |
| 受け付けた鍵の1ビットが違う | `AES_DATA` |
| RotWordを省く | `AES_DATA` |
| 最初のAddRoundKeyを省く | `AES_DATA` |
| 保持中の`cancel`を無視する | `AES_FLOW`（固定シナリオ） |
| MixColumnsの4行目の係数が違う | `AES_DATA` |
| `progress`が1つずれる | `AES_TIMING` |
| `out_block`のゲートを`out_valid`ではなく`busy`で作る | 合格のまま |

11個は、固定シナリオで不合格になりました。最後の1個は動作に差が出ない誤りです。待機中は状態が0なので、`busy`が0のときに状態を出しても`out_block`は0のままです。消去が正しい限り同じ動作で、消去が誤ればその誤りを`AES_ZERO`が見つけます。

## 確認範囲と残る制限

- 暗号化だけです。復号、AES-192とAES-256、ほかの動作モード（CBC、CTR、GCMなど）は扱いません。1クロックに1ラウンドの構成だけです。
- サイドチャネル（電力・電磁波）への耐性、故障注入攻撃への対策は対象外です。時間が一定なのは端子のクロック単位で、組合せ回路の遅延や消費電流がデータに依存しないことは示しません。
- 消去は、このコアのレジスタについてです。外の配線や、`key`・`block`の入力を駆動する側の記憶は扱いません。
- フォーマルの証明は、データパスを抽象化した形です。暗号文の正しさは、公開の例と独立のモデルとの比較（与えた入力の範囲）で確かめたもので、全入力の証明ではありません。
- モデルと回路は同じ人が同じ規格の読み方で書いています。外部の基準は、FIPS 197の付録の例の値だけです。FIPS 197の本文と付録の番号とは照合していません。2023年の改訂版との対応も確かめていません。
- Linux、kirimasim、統合ランナー経由では実行していません。
