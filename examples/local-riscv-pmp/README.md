# RISC-VのPMPを、優先順位・アクセス範囲・ロックから検証する

PMP（Physical Memory Protection）は、物理アドレスの領域ごとに読出し・書込み・命令実行を許可する機構です。単に先頭アドレスが領域内にあるかを見るだけでは不十分です。最も番号の小さいエントリーがアクセスの一部に一致したら、そのエントリーでアクセス全体を許可できるかを決めます。後の広い領域で救済したり、Mモードだから境界越えを許可したりすると、保護をすり抜けます。

この例は、[RISC-V特権仕様 v20260120のPMP節](https://docs.riscv.org/reference/isa/v20260120/priv/machine.html#_physical_memory_protection)の判定規則を、4エントリーに縮小して実装した教材です。仕様上の実装数は0・16・64であり、4エントリーのこの回路はPMP全体の準拠実装ではありません。[APBのアクセス保護](../local-access-control/README.md)とは異なり、領域の符号化とメモリアクセス全体の包含を扱います。

## 回路と期待値

```mermaid
flowchart LR
  accTitle: PMPのRTLとバイト単位の期待値
  accDescr: 同じ設定書込みとアクセスをRTLとPythonモデルへ与える。RTLは区間の重なり、モデルはアクセスする各バイトの所属を調べ、許否・一致エントリー・設定状態を比較する。
  I["設定書込み・物理アクセス"] --> R["RTL：区間の重なりを判定"]
  I --> P["Python：各バイトが領域内か判定"]
  R --> C["許否・一致エントリー・設定状態を照合"]
  P --> C
```

- OFF・TOR・NA4・NAPOT、4バイトの設定粒度、16／18ビットの物理アドレスを扱います。アクセスは1・2・4バイトで、非整列アクセスも1つの不可分な要求として検査します。
- TORの下限には、直前のエントリーがOFFでも、そのアドレスレジスタを使います。下限が上限以上の領域は一致しません。
- R/W/Xと実効特権モードで判定します。未一致はUモードでは拒否、Mモードでは許可します。ロックしていない領域ではMモードの権限チェックを省略しますが、アクセス全体の包含は必要です。
- Lビットは設定とアドレスをリセットまで固定します。ロックしたTORは、直前のアドレスレジスタも固定します。OFFのエントリーでもロックは有効です。
- 予約されたR=0,W=1は、Wを0として読み戻すWARL動作を選びました。未実装の物理アドレスビットと設定の予約ビットは0です。アドレス空間を越える要求、未対応のサイズ・アクセス種別は、教材のインターフェースで拒否します。

設定はクロック端で反映し、そのサイクルのアクセスは更新前の設定で判定します。リセットでは全設定をOFF・0にします。[`run.py`](run.py)の期待値はPythonの整数と`range`で領域を表し、アクセスする各バイトの所属から判定します。設定とアドレスの読み戻しも毎サイクル照合するため、拒否後に状態が変わる誤りを見逃しません。

## 実行と検出する誤り

リポジトリのルートで、Python 3.10以上とIcarus Verilogを使います。

```sh
python3 examples/local-riscv-pmp/run.py
python3 examples/local-riscv-pmp/run.py --profile nightly
python3 -m unittest discover -s examples/local-riscv-pmp/tests -v
```

構成は`pa16`・`pa18`です。各構成で固定シナリオ、ランダムシナリオ、4変異を実行し、JUnitはsmoke 14件／nightly 18件です。通常ケースで要求する目標は16個です。出力・終了・COUNT・カバレッジ・ソースのハッシュの判定は[共通手順](../local-common/README.md)を使います。

| 変異 | 誤り | 検出ラベル |
| --- | --- | --- |
| 1 | 番号の大きいエントリーを優先する | `PMP_DECISION` |
| 2 | アクセスの一部だけが一致すれば許可する | `PMP_DECISION` |
| 3 | ロックした領域でもMモードの権限を無視する | `PMP_DECISION` |
| 4 | ロックしたTORの直前のアドレスを書き換えられる | `PMP_STATE` |

`--demo-bug 1..4`は通常ケースにも変異を入れ、終了コード1になることを確かめるオプションです。セルフテスト7件には、先頭が領域外でも一部が優先エントリーに掛かるアクセス、OFFのロック、NAPOTの最大範囲、逆転したTOR、誤った期待値の拒否を含みます。

2026-10-31に、Python 3.14.7・Icarus Verilog 14.0開発版で2構成のsmoke／nightlyと7セルフテストが成功しました。Verilator 5.052でRTLの全構成・変異0〜4をlintしています。

## 確認範囲

独立したPMP判定回路のシミュレーションです。プロセッサのCSR命令、例外発生、MPRVの実効特権計算、PMA、ページング、PMPキャッシュ、Smepmpは含みません。`machine`には実効特権モードを与えます。コアへの組込みやフォーマル証明は、この例では実施していません。
