# I2Sの送信器と受信器を、ビット列のモデルと照合する

音声用のシリアルバスI2S（Inter-IC Sound）の送信器と、外から来るクロックで動く受信器を検証する教材です。「語の先頭ビットは、ワードクロックの切替から1ビット遅れて出る」という、I2Sで取り違えやすい規則を中心に、左右のチャネル、語長とスロット長、長さの違うスロットの扱いを確かめます。

期待値は、回路とは別の書き方をしたPythonのモデルが作ります。送信器と受信器をつないだループバックだけでは、両方が同じ誤解を持つと一致してしまうので、送信器の端子と受信器の出力を、それぞれモデルと照合します。

## 仕様

教材として決めた仕様です。信号は次の3本です。

| 信号 | 意味 |
| --- | --- |
| `sck` | ビットクロック |
| `ws` | ワードクロック。0が左、1が右のスロット |
| `sd` | データ。語の最上位ビットから送る |

送信側は`sck`の立下りで`ws`と`sd`を変え、受信側は`sck`の立上りで取り込みます。`ws`は、語の最上位ビットより1ビット周期だけ早く変わります。言い換えると、`ws`が変わった周期の`sd`には、まだ前のスロットの最後のビットが載っています。

### 送信器（`i2s_tx`）

- システムクロック`clk`を2分周して`sck`を作るマスターです。リセットの後は止まらずに動き続けます。
- 1スロットは`SLOT`ビット、1フレームは左と右の2スロットです。語長`WORD`が`SLOT`より短いときは、語の後ろを0で埋めます。
- 入力は`in_valid`／`in_ready`の握手で、左右の組を1つだけ待たせます。待ちがある間は`in_ready`が0で、次の組を受け取りません。
- フレームの先頭で待ちがなければ、0のフレームを送り、`underrun`を1クロックだけ立てます。
- リセットは同期です。リセットの後、`ws`は1で始まり、2回目の`sck`の立下りで0になって、その1周期後に最初のフレームの左の語が始まります。

### 受信器（`i2s_rx`）

- 外から来る`sck`をそのままクロックに使うスレーブです。`sck`の立上りだけで動くので、周期が一定でなくても結果は変わりません。
- `ws`の変化を見つけた立上りの、次の立上りを語の最上位ビットとして取り込みます。
- 語長を超えるビットは捨て、足りないビットは0として扱います。
- スロットの長さが`SLOT`と違えば、`errors`を1つ進めます。語は、受け取った分をそのまま渡します。
- 左の語の後に右の語が来たときだけ、組として`left`・`right`へ出し、`frames`を1つ進めます。リセットの後、右から始まった最初の語は渡しません。`ws`の変化より前のビットは読みません。
- リセットは非同期です（クロックが来ていなくても初期化できるようにするためです）。

`frames`と`errors`は8ビットのカウンターで、折り返します。

## 構成

| 構成 | 語長 | スロット長 | 内容 |
| --- | --- | --- | --- |
| `w16-s16` | 16 | 16 | 語がスロットをちょうど埋める |
| `w24-s32` | 24 | 32 | 32ビットのスロットに24ビットの語を載せ、後ろの8ビットは0 |

テストベンチは、受信器の入力を、送信器の端子（ループバック）と、ベクトルが直接動かす外部の端子とで切り替えます。切替えは、受信器をリセットしている間だけ行います。外部の端子では、`ws`と`sd`を先に変え、その後で`sck`を動かすので、同じ時刻の実行順には依存しません。

## 独立した期待値

[`run.py`](run.py)のモデルは、回路と書き方を変えています。

| 対象 | 回路 | モデル |
| --- | --- | --- |
| 送信器 | 位置のカウンターとシフトレジスタ | リセットからのクロック数の算術。フレームのビット列は、取り込みの時点で作った一覧から位置で引く |
| 受信器 | ビットごとに動くマスクとカウンター | 立上りで取った（`ws`、`sd`）の一覧を、`ws`が変わった位置で切り分ける |

セルフテストには、3つ目の読み方（`ws`を1サンプル遅らせて、変わり目で切る）があり、送信器のモデルの端子の列から、送った組が順に読み出せることを確かめます。`ws`が最上位ビットのちょうど1周期前に変わることと、端子が`sck`の立下りでしか変わらないことも、モデルの出力の列から直接確かめます。

モデルと回路は、同じ人が同じ仕様の読み方で書いています。外部の実装や測定器とは照合していません。

## 実行方法

```sh
python3 examples/local-i2s-audio/run.py --profile smoke --out artifacts/i2s-smoke
python3 examples/local-i2s-audio/run.py --profile nightly --seed 17 --out artifacts/i2s-nightly
python3 -m unittest discover -s examples/local-i2s-audio/tests
```

[共通シミュレーションランナー](../local-common/README.md)を使います。必要なツールはIcarus Verilogだけです。`--configuration`で構成、`--iterations`でランダム試験の操作数、`--demo-bug 1..7`で通常の試験に誤りを入れた実行を選べます。

各ケースのディレクトリに、入力と期待値の列（`vectors.txt`）、ログ、波形が残ります。ベクトルの1行は1クロックで、入力8列と、その立上りの前に見えるはずの出力9列です。

## 試験

固定シナリオ`boundaries`は、次の場面を順に通ります。全17目標に、この固定シナリオだけで届きます。

- **握手**：受け取れるのに何も出さない、待ちがある間も次の組を出し続ける、フレームの途中に中途半端な空きを入れる、何も出さずに空のフレームを送らせる。
- **データ**：左だけ・右だけの最上位ビット、左だけ・右だけの最下位ビット、全ビット1、左右で違う交番の値。
- **リセット**：フレームの途中でのリセットと、その後の送受。
- **外部クロックでの受信**：`sck`のLowやHighを数クロックに延ばした不均一なクロック、右のスロットから始まるビット列。
- **スロットの長さ**：ちょうど`SLOT`、1ビット短い、1ビット長い（余分なビットは1）、語長より短い、1ビットだけ、4ビット長い、長さカウンターが1周する長さ。

ランダム試験は、リセットと入力元の切替え、送る組と空き、外部のビット列（スロット長とクロックの形を乱数で決める）を混ぜます。smokeは1 seed、nightlyは3 seedです。

テストベンチの検査は、列ごとにラベルを分けています。

| ラベル | 見るもの |
| --- | --- |
| `I2S_TX_FLOW` | `in_ready`と`underrun` |
| `I2S_TX_SCK` | `sck` |
| `I2S_TX_WS` | `ws` |
| `I2S_TX_SD` | `sd` |
| `I2S_RX_VALID` | `frames`（組を渡した回数） |
| `I2S_RX_DATA` | `left`と`right` |
| `I2S_RX_ERROR` | `errors` |

比較はすべて`!==`で、出力がXなら不合格です。テストベンチは待ち合わせをしない（1行が1クロック）ので、時間切れの検査はありません。

## 要求と目標

[`requirements.json`](requirements.json)に、6要求・17目標があります。

| 要求 | 内容 | 目標 |
| --- | --- | --- |
| `I2S-TIMING` | `ws`が語より1ビット早く変わる、最上位ビットから送る | 3 |
| `I2S-CHANNEL` | 左右の対応、右から始まった語を渡さない | 2 |
| `I2S-FLOW` | 待ちは1組、空のフレームと`underrun` | 4 |
| `I2S-SLAVE` | 外部クロックの立上りだけで取り込む | 3 |
| `I2S-LENGTH` | 余分なビットを捨てる、足りないビットは0、長さの違いを数える | 4 |
| `I2S-RESET` | フレームの途中のリセット | 1 |

## 変異

| 番号 | 場所 | 誤り | ラベル |
| --- | --- | --- | --- |
| 1 | 送信器 | `ws`が語と同時に変わる（1ビット先行しない） | `I2S_TX_WS` |
| 2 | 送信器 | 最下位ビットから送る | `I2S_TX_SD` |
| 3 | 送信器 | 左右が入れ替わる | `I2S_TX_SD` |
| 4 | 送信器 | 空のフレームで`underrun`を立てない | `I2S_TX_FLOW` |
| 5 | 受信器 | `ws`の変化を見た立上りを、語の最上位ビットとして取り込む | `I2S_RX_DATA` |
| 6 | 受信器 | 語長を超えるビットを捨てずに取り込み続ける | `I2S_RX_DATA` |
| 7 | 受信器 | 短いスロットを数えない（長いものだけ数える） | `I2S_RX_ERROR` |

7種類を、2構成とも固定シナリオが予定のラベルで検出します。変異1と5は、送信器と受信器が逆向きに同じ1ビットを間違える組です。両方を同時に持つ回路どうしをつなぐと通信は成立するので、ループバックの結果だけでは見つかりません。この教材では、送信器の端子をモデルと直接比べるので、変異1は`ws`の列で見つかります。

## 確認範囲と残る制限

- 対象は標準のI2S形式だけです。左詰め・右詰めの形式、TDM（3チャネル以上）、マスタークロック（MCLK）、サンプリング周波数の切替えは扱いません。
- 送信器はマスターだけ、受信器はスレーブだけです。受信器がマスターになる構成、送信器がスレーブになる構成はありません。
- 受信器の出力は`sck`の領域のレジスタです。別のクロックへ渡す同期回路は含みません。テストベンチは、値が落ち着いた時刻に読みます。
- `sck`の周波数、デューティ、セットアップ・ホールドといった電気的な時間の規定は確かめていません。シミュレーションは遅延なしです。
- 外部の端子の試験では、`ws`と`sd`は`sck`の立上りの行で動かしません。立上りと同時に変わる入力に対する動作は、対象外です。
- 受信器は、長さの違うスロットを数えるだけで、同期の外れを判定して復帰する機能はありません。
- 実行した構成は、語長16・スロット16と、語長24・スロット32の2つだけです。
- 仕様の元は、Philips Semiconductors（現NXP）のI2Sバス仕様です。この教材は、その文書の本文や図とは照合しておらず、節番号は未照合です。規則は自分の言葉で書いています。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13、Icarus Verilog 14.0開発版で確認しました。Linuxとkirimasimでは実行していません。

- smoke（seed 17・3・5・99）とnightly（`--timeout 60`、seed 17）が合格しました。JUnitはsmoke 20件、nightly 24件です（構成ごとに固定1、ランダム1または3、変異7、要求と目標の判定1）。2構成とも17／17目標で、全目標に固定シナリオだけで届きます。
- セルフテスト18件が合格しました。Icarusがなければ失敗します。
- `--demo-bug 5`は終了コード1になります。
- RTLは、2構成と変異0〜7で、Verilator 5.052の`--lint-only --Wall`の警告が0件です。
- 最初の実行は、テストベンチが非同期リセットの立下りを作っていなかったために止まりました。それを直した後は、モデルと回路は固定シナリオとランダムの全行で一致し、モデルも回路も直していません。

変異とは別に、作業用の写しのRTLへ小さな誤りを16個入れて、smokeにかけました。

- 12個は、固定シナリオが2構成とも不合格にしました。
- 1個（語の後ろを0で埋める向きの誤り）は、埋める部分のない`w16-s16`では回路が変わらず、`w24-s32`の固定シナリオが不合格にしました。
- 3個は合格のまま残りました。どれも動作に差が出ない誤りです：組を渡した後に「左の語あり」の印を消さない（次の左の語で必ず立て直す）、0のビットで該当ビットを明示的に0にする（もともと0）、長さカウンターの止まる値を1つ小さくする（どちらの値も「長さが違う」と判定される）。
- 途中で試験の抜けを1つ見つけました。長さカウンターを止めずに折り返す誤りは、スロット長に、カウンターの1周分を足した長さのスロットでだけ「正しい長さ」に見えます。固定シナリオにその長さのスロットを足し、セルフテストにも残しました。ランダム試験は、この誤りを見つけません。
