# センサーの受信パケット層：レーンの合流、ヘッダーECC、ペイロードCRC、フレームとラインの順序を確かめる

イメージセンサーの受信側には、複数のレーンに分かれて届くバイト列を1本に戻し、パケットのヘッダーを誤り訂正し、画素の行をCRCで確かめ、フレームとラインの順序を見張る層があります。この例は、その層を小さく作った教材です。

**形式はこの教材が独自に決めたものです。** 特定の規格の実装ではなく、どの規格との互換性も主張しません。バイトの同期、物理層、電気的な状態は扱いません。

検証で間違えやすいのは、次の点です。

- **レーンの合流**：レーンごとに届く時刻がずれます。ずれを吸収する範囲と、範囲を超えたときの知らせ方を決めて、境界の両側を試します。
- **ヘッダーの誤り訂正**：1ビットの誤りを「訂正した」と知らせるだけでなく、訂正後の値が使われていることを確かめます。2ビットの誤りを訂正してしまう誤りは、通常の入力では見えません。
- **誤りの後の動作**：長さが信用できないパケットの後ろをどこまで捨てるか、開いているフレームをどう終えるかは、誤りごとの場面を作らないと試されません。
- **順序の規則**：規則が多いので、規則ごとに、その規則だけに反する場面を1つずつ持ちます。

位置付けは[バスプロトコルの検証手順](../../docs/method/bus-protocol-verification.md)と[画像処理の検証手順](../../docs/method/image-processing-verification.md)にあります。フレームの誤り検出を扱うほかの例には、[フレームの受信と返送](../local-network-echo/README.md)と[CRC・ACK・再送リンク](../local-retry-link/README.md)があります。

## 仕様

[`sensor_packet_rx.sv`](rtl/sensor_packet_rx.sv)が対象です。パラメーターは、レーン数`LANES`と、画素の行の最大の語数`MAX_LINE`です。

### レーン

| 信号 | 動作 |
| --- | --- |
| `lane_active[i]` | レーンiがバーストの途中であること。1つのバーストで、レーンごとに1回だけ1の区間を持つ |
| `lane_valid[i]`・`lane_data` | `lane_active`が1のクロックで`lane_valid`が1なら、1バイトを受け取る。`lane_active`が0の間の`lane_valid`は無視する。1つのレーンは、`LANES`クロックに1バイトより速くは送らない |

- 各レーンがバーストで最初に送るバイトは、同期バイト`0xB8`です。
- 送る側は、バイト列のk番目を、レーン k mod `LANES` へ置きます。バイト数が`LANES`の倍数でないときは、後ろのレーンが1バイト少なくなります。
- すべてのレーンが、少なくとも1クロックは同時に`lane_active`を1にします。
- 受信側は、レーンごとに4バイトの待ち行列を持ち、全レーンの同期バイトがそろってから、レーン0から順に1クロックに1バイトずつ取り出します。順番の来たレーンが空で、`lane_active`も0なら、バーストの終わりです。
- バーストの終わりを受信側が見るまで、次のバーストを始めてはいけません。

次の場合は、レーンの誤り（`err[5]`）を知らせ、全レーンが静かになるまで入力を捨てます。

| 場合 | 例 |
| --- | --- |
| 最初のバイトが同期バイトでない | |
| 待ち行列があふれる | レーン間のずれが大きすぎる |
| 同期バイトを送らないレーンがあるまま、全レーンが静かになった | 始まらないレーン |
| 終わったレーンの`lane_active`が、もう一度1になった | 次のバーストが早すぎる |
| バーストの終わりに、ほかのレーンにバイトが残っているか、`lane_active`が1のレーンがある | レーンの長さの不整合 |

### パケット

ヘッダーは4バイトです。

| バイト | 内容 |
| --- | --- |
| 0 | 種類。ビット5が1なら、ペイロードとCRCが続く |
| 1・2 | 16ビットの数（下位が先）。ペイロードつきのパケットではバイト数、それ以外では番号 |
| 3 | 下位6ビットがヘッダーの検査ビット。上位2ビットは0 |

| 種類 | 値 | 数の意味 |
| --- | --- | --- |
| フレーム開始 | `0x00` | フレーム番号 |
| フレーム終了 | `0x01` | フレーム番号 |
| ライン開始 | `0x02` | ライン番号（フレームごとに0から） |
| ライン終了 | `0x03` | ライン番号 |
| 画素の行 | `0x2A` | 画素の数。1以上`MAX_LINE`以下 |
| そのほか | | 長さに従って読み飛ばし、`pkt_ignored`を1クロック出す |

- **検査ビット**は、24ビットに対する1ビット誤り訂正・2ビット誤り検出の符号です。24ビットを符号語の位置1〜29のうち2のべきでない位置へ順に置き、位置1・2・4・8・16にハミング符号のパリティ、6ビット目に全体のパリティを置きます。
- 1ビットの誤り（検査ビット自身の誤りを含む）は訂正して使い、`hdr_fix`を出します。それ以外（2ビットの誤り、存在しない位置を指す誤り、上位2ビットが0でない）は、ヘッダーの誤り（`err[0]`）を知らせ、長さを信用できないので、バーストの残りを捨てます。
- **ペイロードのCRC**は16ビットで、生成多項式 x^16＋x^12＋x^5＋1 を下位ビットから処理し、初期値は`0xFFFF`、最後の反転はありません。下位バイトを先に送ります。対象はペイロードだけです。

### 出力

出力はすべてレジスタで、意味のないクロックでは0です。

| 信号 | 動作 |
| --- | --- |
| `pix_valid`・`pix_data`・`pix_first`・`pix_last` | 受け付けた行の画素を、届いた順に1クロックに1つ出す。CRCを待たずに出す |
| `row_done`・`row_ok` | 行のCRCを受け取った次のクロックに`row_done`を出す。`row_ok`はCRCが一致したこと |
| `frame_start`・`frame_end`・`evt_num` | フレームの開始と終了。`evt_num`はフレーム番号 |
| `frame_clean` | `frame_end`と同時。フレーム開始から終了まで、誤りが1つも知らされなかったこと |
| `hdr_fix`・`pkt_ignored` | ヘッダーを訂正した／扱わない種類を読み飛ばした |
| `err[5:0]` | 上位から、レーン、途中で終わったパケット、語数、順序、CRC、ヘッダー |

画素を出すのは、ライン開始の後の最初の行で、語数が1以上`MAX_LINE`以下、かつ、そのフレームで最初に受け付けた行と同じ語数のときだけです。語数の誤り（`err[3]`）や順序の誤り（`err[2]`）の行は、画素を出さずに読み飛ばします。

順序の誤りは次のとおりです。

| パケット | 誤りになる場合 | その後 |
| --- | --- | --- |
| フレーム開始 | フレームの中で届いた | 新しいフレームを始める（きれいなフレームにはならない） |
| フレーム終了 | フレームの外／ラインの中／番号が開始と違う | フレームの外なら何もしない。それ以外はフレームを終える |
| ライン開始 | フレームの外／ラインの中／番号が続きでない | 前の2つは無視する。番号の誤りだけならラインを始める |
| ライン終了 | ラインの外／行が1つもない／番号が違う | ラインの外なら無視する。それ以外はラインを終える |
| 画素の行 | ラインの外／同じラインで2つ目 | 読み飛ばす |

パケットの途中でバーストが終わると、途中で終わったパケット（`err[4]`）を知らせます。リセットは同期で、状態をすべて捨てます。

## 独立した期待値

[`model.py`](model.py)が期待値を作ります。回路とは、次のように書き方を変えています。

| 部分 | 回路 | モデル |
| --- | --- | --- |
| ヘッダーの検査ビット | パリティのマスク（定数）とのXOR | 符号語の位置を1つずつ調べて作る |
| ヘッダーの復号 | シンドロームと全体のパリティで場合分け | 30ビットのどれか1つを反転して符号語になるものを探す。ちょうど1つなら訂正 |
| CRC | 1ビットずつのシフト | 256項目の表 |
| パケット | 1バイトごとの状態機械 | 1パケット分のバイトをためて、位置で取り出す |
| レーン | 待ち行列とラウンドロビン | **同じ構造**（下の注） |

レーンの層だけは、モデルも同じ構造（レーンごとの待ち行列を順に取り出す）です。どのクロックにどのバイトが取り出されるかが、期待する出力の時刻そのものだからです。この部分の独立な確かめは、セルフテストが行います。許される範囲のずれを全レーン・全クロック数で与え、出てくる画素の列が送ったフレームと一致することを確かめます。

外部の基準は2つです。CRCは、同じパラメーターで公開されている検査値（文字列`123456789`に対して`0x6F91`）と一致します。ヘッダーの符号は、最小距離が4であること（データの重みが1〜3の全2,324語で、符号語の重みが4以上）を全数で確かめます。回路のマスクと位置の表が、位置による定義と同じであることも、セルフテストが回路のソースを読んで照合します。

## 刺激

テストベンチ[`sensor_packet_tb.sv`](tb/sensor_packet_tb.sv)は、1クロックに1行のベクトルを読み、全出力を毎クロック`!==`で比べます。出力が不定なら不合格です。

固定シナリオ（`boundaries`）は、場面の集まりです。場面ごとに「この出力が現れること」「知らせてよい誤りの種類」「現れてはいけない出力」を書いてあり、モデルの結果がそれに合わなければ、計画を作る時点でエラーにします。場面が狙った効果を実際に出していることを、ランナーが毎回確かめる形です。

| 分類 | 場面 |
| --- | --- |
| レーン | ずれなし、ずれあり、吸収できる最大のずれ（待ち行列がちょうど埋まる）、それより1クロック大きいずれ（あふれる）、同期バイトの誤り、長さの不整合、始まらないレーン、`lane_active`なしのストローブ、早すぎる次のバースト、`LANES`の倍数でないバイト数、複数パケットのバースト |
| ヘッダー | 誤りなし、データ24ビットの各1ビット誤り、検査6ビットの各1ビット誤り、2ビット誤り10通り、存在しない位置を指す誤り2通り、上位2ビットの違反、途中で終わったヘッダー |
| 行 | CRC一致、画素・CRC下位・CRC上位の各誤り、語数0、最短（1）、最大、最大＋1、フレーム内の語数の不一致、画素の途中とCRCの途中で終わった行 |
| 順序 | 表の規則ごとに1場面（13場面） |
| フレーム | CRCの誤りで汚れたフレーム、レーン・途中終了・ヘッダーの誤りで汚れたフレーム |
| そのほか | 扱わない種類（ペイロードなし・あり・長さ0）の読み飛ばし、パケットの途中のリセット |

吸収できるずれの上限は、3行のフレームを1バーストで送り、レーン0だけを遅らせて求めます。あふれ始めるのは、`LANES`＝2で8クロック、`LANES`＝4で16クロックの遅れです。固定シナリオは、その1つ手前と、ちょうどその値を使います。

ランダムの場面（`random-seedN`）は、正しいフレームを基に、ビットの反転、パケットの欠落・重複・入替え、同期バイトの誤り、余分なバイト、始まらないレーン、短すぎる間隔、打切り、途中のリセットを混ぜます。

### 画像パイプラインへの接続

固定シナリオの最初の2フレームは、既存の[Sobelフィルター](../local-image-sobel/README.md)（[`sobel_stream.sv`](../local-image-sobel/rtl/sobel_stream.sv)）へ画素を流します。テストベンチが、この層の`pix_valid`・`pix_data`をフィルターの入力へつなぎます。既存の例のファイルは変えていません。

- この層は送り手を止められないので、画素が出るクロックにフィルターが受け取れなければ`SP_PIPE`で不合格です。
- フィルターの出力の個数と、位置で重みを付けた和を、Sobelの例のモデル（フレームの配列から計算する）の結果と照合します。

## 要求と目標

要求は7件、目標は44個です（[`requirements.json`](requirements.json)）。2構成とも、固定シナリオだけで全目標に届きます。

| 要求 | 内容 | 目標 |
| --- | --- | --- |
| SP-LANE | 合流、ずれの吸収、レーンの誤り | 12 |
| SP-HEADER | 訂正と、使えないヘッダー | 6 |
| SP-PACKET | 扱わない種類の読み飛ばし | 2 |
| SP-ROW | 画素の行、語数、CRC、途中終了 | 7 |
| SP-SEQUENCE | フレームとラインの順序、きれいなフレーム | 15 |
| SP-RESET | 途中のリセット | 1 |
| SP-PIPELINE | Sobelパイプラインへの接続 | 1 |

42個は場面の札（計画が場面の効果を確かめた行に付ける）、2個はテストベンチが回路の動きから出します（待ち行列が埋まった、パイプラインがフレームを出し終えた）。

## 意図的な誤実装

| 変異 | 内容 | 検出するラベル |
| --- | --- | --- |
| 1 | 訂正するビットの位置がずれる | `SP_FRAME` |
| 2 | 2ビットの誤りを使えるヘッダーとして扱う | `SP_ERROR` |
| 3 | CRCの初期値が0 | `SP_ROW` |
| 4 | バーストの終わりに、取り出すレーンの順番を戻さない | `SP_ERROR`（2レーン）、`SP_FRAME`（4レーン） |
| 5 | ラインの外の行を受け付ける | `SP_ERROR` |
| 6 | 最大＋1の語数を受け付ける | `SP_ERROR` |
| 7 | 途中で終わったパケットを知らせない | `SP_ERROR` |
| 8 | 待ち行列のあふれを知らせない | `SP_ERROR` |
| 9 | CRCの誤りがあってもきれいなフレームとして終える | `SP_FRAME` |
| 10 | フレーム内の語数の不一致を見ない | `SP_ERROR` |

変異4は、レーン数によって最初に食い違う出力が違うので、予定のラベルを構成ごとに分けています。

## 実行

```sh
python3 examples/local-sensor-packet/run.py --out artifacts/sensor-packet-smoke
python3 examples/local-sensor-packet/run.py --profile nightly --out artifacts/sensor-packet-nightly
python3 -m unittest discover -s examples/local-sensor-packet/tests
```

構成は`lanes2`（2レーン、最大8画素、パイプラインは5×4）と`lanes4`（4レーン、最大6画素、6×3）です。smokeはランダムが1 seedで40操作、nightlyは3 seedで120操作です。JUnitはsmoke 26件／nightly 30件（構成ごとに固定1、ランダム1／3、変異10、判定1）です。`--configuration`、`--seed`、`--iterations`、`--demo-bug 1..10`、`--iverilog`、`--vvp`、`--timeout`は[共通ランナー](../local-common/README.md)と同じです。

ベクトルの1行は、入力・期待する出力・札の3つの16進数に詰めてあります。共通ランナーは全ケースの入力を`manifest.json`へ写すので、列を分けたままでは大きくなりすぎるためです。

セルフテストは21件です。符号とCRCの性質、回路の定数との照合、許されるずれでの画素の一致、ずれの上限の両側、場面の札と目標の対応、効果を出さない場面の拒否、テストベンチが誤った期待値と不定の出力を正しいラベルで知らせること、パイプラインが受け取れないフレームの検出を確かめます。IcarusがないときにskipするテストがあるのはほかのIcarusの例と同じで、全セルフテストはskipを不合格にします。

## 確認範囲と残る制限

- 形式は独自です。規格への適合、物理層、バイトの同期（同期バイトをビット列から探すこと）、レーンの電気的な状態、送り手を止める仕組みは扱いません。
- レーンの層のモデルは、回路と同じ構造です。取り出す時刻まで含めて照合するためで、構造を共有する誤り（たとえば、取り出しを始める条件の考え違い）は、モデルとの比較では見つかりません。許されるずれで画素の列が変わらないことは、セルフテストが別に確かめます。
- 吸収できるずれの上限（8クロックと16クロック）は、この例のバーストの形（1レーンが`LANES`クロックに1バイト）で、レーン0だけを遅らせたときの値です。待ち行列の深さからの一般の式は導いていません。
- 3ビット以上の誤りは、多くが別の正しいヘッダーへ訂正されます。符号の性質で、検出できません。試験したのは、存在しない位置を指す2通りだけです。
- `frame_clean`は、誤りが知らされなかったことを表すだけです。ラインの数や、行の数がフレームごとに同じことは確かめません。ライン開始のないまま終わったフレームも、誤りがなければきれいなフレームです。
- 画素はCRCを待たずに出ます。CRCの誤りは、行の終わりの`row_ok`と`err[1]`で知るので、使う側が行を捨てる必要があります。パイプラインへ接続した2フレームは、誤りのないフレームだけです。
- パイプラインとの接続の照合は、出力の個数と重み付きの和です。画素ごとの照合は、Sobelの例の役目です。
- 場面の札は、モデルの出力に対して付けています。回路が同じ出力を出したことは、毎クロックの比較が確かめます。
- フォーマルは使っていません。Linuxとkirimasimでは実行していません。

## 確認記録

2026-11-21に、macOS arm64、Python 3.13、Icarus Verilog 14.0開発版で確かめました。

- smoke（seed 17・3・99）とnightly（`--timeout 60`、seed 17）が2構成とも合格し、44目標すべてに届きました。変異10種類は、2構成の20件すべてを予定のラベルで検出しました。
- セルフテスト21件が合格しました。
- RTLは、2構成・変異0〜10で、Verilator 5.052の`--lint-only --Wall`の警告が0件です。
- 最初の実行で、モデルと回路は固定シナリオとランダムの全行で一致しました。
- **追加で入れた誤り**：変異とは別に、写しのRTLへ小さな誤りを27個入れてsmokeにかけました。最初の固定シナリオが検出したのは24個で、残った3個は試験の抜けでした。場面を足して、27個すべてを2構成の固定シナリオで検出するようにしています。
  - レーンの誤りがフレームを汚さない誤り → レーン・途中終了・ヘッダーの誤りで汚れるフレームの場面を追加。
  - 終わったレーンの`lane_active`なしのストローブをバイトとして取る誤り → バーストの途中で、終わったレーンにストローブを立てる行を追加。
  - `lane_active`なしのストローブを同期バイトとして数える誤り → バーストの直前の行に、1レーンだけのストローブを追加。
  - ランダムの場面（seed 17、40操作）だけでは、27個のうち両構成で検出するのは14個です。固定シナリオが残りを見つけます。
- 設計の途中で、次のバーストが早すぎる場合の扱いが決まっていないことに気付き、「終わったレーンがもう一度始まったら誤り」という規則を足しました。足す前は、次のバーストの同期バイトがデータとして取り込まれていました。
