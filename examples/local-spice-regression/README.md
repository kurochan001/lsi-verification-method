# SPICEの回帰を自動で判定する

SPICEの結果を、波形の目視ではなく、測定値と期待値の比較で合否にする教材です。RCフィルター、インバーターの遅延、リングオシレーターを、条件を変えながら固定版のngspiceで解き、解析値・記録した範囲・コーナーの順序・モンテカルロの合格数で判定します。収束しない解析、終わらない解析、測定できない波形、有限でない値は、必ず不合格にします。

**トランジスタのモデルは、この教材のために作ったレベル1のモデルカードです。実際のプロセスのデザインキット（PDK）ではありません。** 遅延や周波数の数値は教材のもので、実際のプロセスの特性を表しません。期待する範囲も、このモデルと固定版のngspiceで測った値です。

位置付けは[SPICE協調の手順](../../docs/method/spice-cosimulation.md)にあります。RTLとSPICEを時刻をそろえて交互に進める例は[RC回路とSPICE](../local-spice-cosim/README.md)、SPICEの結果をRTLへ再生する例は[PWMとADC](../local-pwm-spice/README.md)です。この例にRTLはありません。

## 題材

| 題材 | 回路 | 測る量 | 期待値の出どころ |
| --- | --- | --- | --- |
| RCフィルター | 1 Vのステップを抵抗とコンデンサへ入れる | 全解析点の電圧、50%に達する時刻、10%から90%までの立上り時間 | 式（`1-exp(-t/RC)`、`RC·ln2`、`RC·ln9`） |
| インバーターの遅延 | 1段のCMOSインバーターと20 fFの負荷 | 入力の50%から出力の50%までの遅延（立下り`tphl`、立上り`tplh`）、出力の振幅 | 記録した範囲、2通りの測定、粗い手計算 |
| リングオシレーター | 5段のインバーターの輪。各段に10 fFの負荷 | 周期（6周期の平均） | 記録した範囲、2通りの測定、段の遅延との比 |

RCの組は3つ（1 kΩ・100 nF、47 kΩ・10 pF、220 Ω・1 µF）で、時定数は約0.5 µsから220 µsです。

## 条件（コーナー）

| 軸 | 値 |
| --- | --- |
| プロセス | `ff`（しきい値−50 mV、利得×1.15）、`tt`、`ss`（しきい値＋50 mV、利得×0.85） |
| 温度 | −40 ℃、25 ℃、125 ℃ |
| 電源 | 1.32 V、1.2 V、1.08 V |

名前を付けたコーナーは3つです。`fast`は`ff`・−40 ℃・1.32 V、`typ`は`tt`・25 ℃・1.2 V、`slow`は`ss`・125 ℃・1.08 Vです。インバーターとリングオシレーターは、この3つで範囲と順序（`fast`＜`typ`＜`slow`）を判定します。

インバーターは、3軸の全組合せ27通りも実行します。遅いプロセスほど遅い、電源が低いほど遅い、という順序は、27通りのどの温度・どの条件でも成り立つことを確かめます。

温度には、決まった向きがありません。このモデルでは、電源が1.08 Vのとき、立上りの遅延は−40 ℃の方が125 ℃より約7%遅くなります。電源が1.32 Vのときは、立下りの遅延は125 ℃の方が約23%遅くなります。温度が上がると移動度は下がり、しきい値も下がるので、電源が低いとしきい値の効果が勝つためです。27通りの中で立上りが最も遅いのは`ss`・−40 ℃・1.08 Vで、名前を付けた`slow`ではありません。この例は、両方の事実を毎回確かめます。「高温が最も遅い」と決めてコーナーを1つだけ実行すると、最悪の条件を見落とします。

## 判定

| ラベル | 何を見るか |
| --- | --- |
| `RC_TAU` | RCの波形と2つの時刻が、式の値と合う |
| `MEAS_METHOD` | ngspiceの`meas`と、波形から別に求めた値が合う |
| `INV_DELAY`、`RING_FREQ` | 遅延と周期が、記録した値の±2%に入る |
| `INV_SWING` | 出力が電源の範囲いっぱいに振れる |
| `INV_ESTIMATE`、`RING_STAGE` | 手計算の見積りや段の遅延との比が、決めた範囲に入る |
| `CORNER_ORDER`、`CORNER_WORST`、`CORNER_INVERSION` | コーナーの順序、27通りの最悪値、温度の向きの入替り |
| `SETTINGS_SENSITIVE` | 解析の設定を厳しくしても、結果が1%以上動かない |
| `MC_YIELD`、`MC_REPRODUCE` | モンテカルロの合格数が受容域に入る。同じseedで同じ結果になる |
| `SPICE_CONVERGENCE`、`SPICE_TIMEOUT`、`SPICE_MEASURE`、`SPICE_NONFINITE`、`SPICE_NETLIST`、`SPICE_FATAL`、`SPICE_ERROR` | 解析や測定そのものの失敗 |

### 解析値と比べる（RC）

RCの波形は、すべての解析点で`1-exp(-t/RC)`との差を取り、最大が0.1 mV以下であることを求めます。50%の時刻と立上り時間は、式の値との差が0.1%以下です。手元の実測は、波形の差が約3 µV、時刻の差が約0.0004%でした。ここでは期待値がngspiceと無関係に決まるので、ツールの設定や使い方の誤りが、そのまま差として現れます。

### 記録した範囲と比べる（インバーター、リングオシレーター）

トランジスタの回路には、閉じた式の答えがありません。期待値は、固定版のngspiceで測った値を[`expected.json`](expected.json)に記録したものです。これは回帰の判定です。「前と同じ」ことは分かりますが、「正しい」ことは分かりません。そのため、次の3つを組み合わせます。

- **2通りの測定**：同じ波形から、ngspiceの`meas`と、Pythonで交差の時刻を直線補間して求めた値を比べます（差は0.1%以下）。測定の式の書き間違いは、ここで分かります。
- **粗い手計算**：立下りの遅延を「振幅の半分÷飽和電流」で見積もります。入力の傾き・寄生容量・線形領域を無視するので、測定値は見積りの約1.5〜1.7倍になります。判定は1.0〜2.5倍です。単位や桁の誤りを見つけるための検算で、記録した値そのものが誤っていても働きます（セルフテストで、10倍の値を記録した場合に`INV_ESTIMATE`で止まることを確かめています）。
- **段の遅延との比**：リングの周期を、同じコーナーのインバーターの遅延から作った「段数×（`tphl`＋`tplh`）」と比べます。負荷と入力の傾きが違うので、比は約1.0〜1.3で、判定は0.7〜1.7です。

範囲を±2%にした根拠は、次の測定です。解析の設定を変えたときの動きより十分広く、条件や部品の誤りより狭い値を選びました。

| 変えたもの | 測定値の動き |
| --- | --- |
| 最大の刻みを5 psから1 psへ、積分法を台形則へ（厳しい設定） | 遅延で0.6%、周期で0.1% |
| 相対誤差の許容（`reltol`）を10の−4乗から10の−2乗へ | 0.01%未満。この回路では、刻みの上限が精度を決めています |
| `slow`の温度を125 ℃から85 ℃へ | 立上りの遅延で3.1% |
| 遅いプロセスの利得を0.85倍から0.88倍へ | 3.0% |
| リングの各段の負荷を10%増やす | 周期で5.0% |
| インバーターの負荷を15%増やす | 8.7% |

最初は範囲を±5%にしていましたが、上の表の3〜5行目の誤りが合格しました。±2%へ狭めて、どれも不合格になることを確かめています（後の「追加で入れた誤り」）。

出力の振幅は、入力の振幅の0.99〜1.15倍を求めます。1を少し超えるのは、ゲートとドレインの間の容量を通って、入力の変化が出力へ飛び込むためです（実測は1.06〜1.09倍）。

### 解析の設定

通常の設定は、`reltol`が10の−4乗、積分法がGear、最大の刻みが5 psです。RC・インバーター・リングのそれぞれで、厳しい設定（`reltol`が10の−6乗、台形則、刻み1 ps）でも実行し、測定値の差が1%以下であることを確かめます。設定に結果が左右されているなら、範囲と比べる前にここで止まります。

## 失敗を合格にしない

ngspiceは、打ち切った過渡解析からも0を返します。この例の`diagnose-return-code`は、収束しない回路で、解析の命令の戻り値が0、メッセージに打切りの記録があり、最後の時刻が予定の終了時刻に届いていないことを、毎回確かめます。戻り値だけを見る判定は、打ち切られた波形の前半から測定して、合格にしてしまいます。

作業者（[`solve.py`](solve.py)）は、ジョブごとに次の順で調べ、最初に当てはまったものを結果にします。

| 状況 | 結果 | 確かめる負例 |
| --- | --- | --- |
| ネットリストを読めない | `SPICE_NETLIST` | 定義のないモデル名を使う |
| メッセージに打切りがある、または最後の時刻が終了時刻に届かない | `SPICE_CONVERGENCE` | 反復の上限と許容誤差を極端に絞る |
| 波形に有限でない値がある、測定値が有限でない | `SPICE_NONFINITE` | 入力が動かない回路で、振幅の比（0÷0）を測る |
| 交差がない、`meas`が成立しない、ベクトルがない | `SPICE_MEASURE` | 入力を止めて遅延を測る |
| 作業者が時間内に終わらない | `SPICE_TIMEOUT` | 1ステップを10の−18乗秒に制限して、終わらない解析にする |
| 作業者が結果を残さずに終わる | `SPICE_FATAL` | セルフテスト（偽の作業者） |

終わらない解析の負例は、3秒で打ち切ります。振幅の比のように定義できない測定は、適当な値で埋めず、NaNを返して判定側で不合格にします。

モンテカルロでは、1回でも解析や測定に失敗した試行があれば、その実行は失敗のラベルで不合格です。失敗した試行を「不合格の1回」や「合格の1回」に数えません。

## モンテカルロの判定：試行数・区間・誤って不合格にする確率

### 何を1回の試行とするか

1回の試行は、ばらつきを1組引いたインバーター1個です。ばらつきは、n型とp型のしきい値（標準偏差15 mV）、それぞれの利得（対数で4%）、負荷（対数で3%）の5つで、互いに独立です。乱数はすべてPython側で引き、値をネットリストへ書き込みます。ngspiceの乱数は使いません。同じseedなら、引く値も解析の結果も同じです（`monte-carlo/reproducible`が、引いた値と、同じ20試行を2回解いた結果の一致を確かめます）。引いた値は、試行ごとに`draws.json`へ残します。

1回の試行は、`tphl`と`tplh`の平均が64.5 ps以下なら合格です。試行は互いに独立で、結果は合格か不合格の2つなので、合格数は二項分布に従います。

### 基準の合格率

基準は、別の乱数の系列で20,000回試行した結果です。18,174回が合格で、合格率は0.9087です。この値にも誤差があるので、99.9%の区間（0.9018〜0.9153、クロッパー・ピアソンの方法）を取り、区間の下端と上端を使って受容域を作ります。基準の標準誤差は0.0020で、300回の標本の標準誤差0.0166の8分の1です。

閉じた式の基準値はありません。基準そのものがこのモデルとこのngspiceの結果なので、モデルの値を変えれば基準も取り直します。

### 受容域

正しい回路を誤って不合格にする確率を、片側0.001以下にします。合格数が次の範囲なら合格です。

| プロファイル | 試行数 | 合格数の受容域 | 基準の合格率での、誤って不合格にする確率 | 99%以上の確率で不合格にできる合格率 |
| --- | --- | --- | --- | --- |
| smoke | 300 | 254〜288 | 0.0004 | 0.792以下、または0.982以上 |
| nightly | 1,000 | 872〜941 | 0.0001 | 0.845以下、または0.958以上 |

受容域は二項分布の厳密な計算です（正規近似は使いません）。上側も判定します。合格数が多すぎる場合も、モデルや仕様の値が変わったことの現れだからです。

報告には、観測した合格率の99%の区間（クロッパー・ピアソン）も載せます。seed 17のsmokeでは、300回中274回が合格で、区間は0.863〜0.950です。

### 試行数の決め方

- 300回では、合格率が0.79まで下がる変化（しきい値の平均が約10 mVずれる程度）を見つけられます。0.85程度までの小さな劣化は見逃します。
- 1,000回にすると、0.845以下を見つけられます。しきい値の標準偏差が15 mVから22 mVへ増える誤りは、300回では合格し、1,000回では不合格になります（後の「追加で入れた誤り」）。
- 見つけたい変化が小さいほど、試行数は差の2乗に反比例して増えます。この例の解析は1回数ミリ秒なので、試行数を増やせます。重い回路では、ここが実行時間を決めます。

### seedを変えたとき

既定のseedは17で、結果は毎回同じです。seedを変えると、正しい回路でも、上の表の確率で不合格になります。受容域を作った後に、別の400個のseedでsmokeと同じ300回の試行を行ったところ、合格数は257〜286で、受容域を外れたものはありませんでした。nightlyと同じ1,000回の試行を100個のseedで行った結果は、「確認記録」にあります。

## 実行

固定版のngspiceの共有ライブラリーを使います。準備は[実行環境のngspiceの節](../../tools/ENVIRONMENT.md#ngspiceとspice協調例)にあります。`lsi-ngspice-config`の場所を`PATH`に入れるか、`--ngspice-config`で渡します。

```sh
python3 examples/local-spice-regression/run.py --out artifacts/spice-regression-smoke
python3 examples/local-spice-regression/run.py --profile nightly --out artifacts/spice-regression-nightly
python3 -m unittest discover -s examples/local-spice-regression/tests
```

`--seed`はモンテカルロのseedです（既定17）。nightlyは、seed・seed＋1・seed＋2の3つで、各1,000回の試行を行います。`--timeout`は作業者1回の上限です（既定30秒）。`--out`には新しいディレクトリを指定します。

ngspiceは、[`solve.py`](solve.py)が別のプロセスで読み込みます。1回の起動で複数のネットリストを順に解き、ジョブごとに結果か失敗のラベルを返します。回復できない誤りの後は、同じプロセスの残りのジョブをすべて失敗にします。

出力は、`manifest.json`（計画、条件、受容域、入力のハッシュ）、`summary.json`、`junit.xml`、ケースごとのディレクトリ（`jobs.json`、`results.json`、`solver.log`）、代表の波形（`inv-typ/waveform.csv`など）、モンテカルロの`draws.json`です。

JUnitは、smokeが32件、nightlyが34件です。内訳は、ngspiceの導入の確認1、RC 3、インバーター3、リング3、コーナー2、設定3、モンテカルロ1（nightlyは3）と再現性1、負例12、戻り値の診断1、要求と目標の判定1、入力の変更の確認1です。実行時間は、手元でsmokeが約10秒（うち3秒は終わらない解析の打切り）、nightlyが約25秒です。

セルフテストは30件です。測定（交差・遅延・周期・未定義の比・RCの式・範囲の境界・手計算）、統計（二項分布、受容域の両端、クロッパー・ピアソン、乱数の再現）、ネットリスト、判定（規則ごとに1つずつの違反、受容域の両端と1つ外、失敗した試行の扱い）、作業者の異常終了、計画と目標の対応、実際のngspiceでの実行（smoke、同じseedでの一致、別のseed、ツールの欠落、記録した範囲を3%ずらすと不合格になること、作業者が返す失敗の種類）を確かめます。

## 要求と目標

| 要求 | 内容 | 目標 |
| --- | --- | --- |
| `SPICE-RC` | RCのステップを、全解析点と2つの時刻で式と照合する | 4 |
| `SPICE-MEAS` | 2通りの測定と、粗い見積りとの整合 | 4 |
| `SPICE-RANGE` | 遅延と周期が記録した範囲に入る | 2 |
| `SPICE-CORNER` | 名前を付けた3コーナー、順序、27通りの単調性、温度の向きの入替り | 6 |
| `SPICE-SETTINGS` | 解析の設定を厳しくしても結果が動かない | 3 |
| `SPICE-MC` | seedを固定したモンテカルロを、厳密な受容域で判定し、区間を報告する | 3 |
| `SPICE-FAIL` | 収束の失敗・時間切れ・測定の欠落・有限でない値・読めないネットリストを合格にしない。戻り値だけでは足りないことを示す | 6 |
| `SPICE-DETECT` | 部品・条件・プロセスの誤りを、予定のラベルで検出する | 6 |

8要求・34目標です。目標は、通常のケースが合格したとき、または負例が予定のラベルで不合格になったときに達成とします。

## 負例

| ケース | 入れる誤り | 予定のラベル |
| --- | --- | --- |
| `detect-rc-resistance` | 抵抗が2倍 | `RC_TAU` |
| `detect-inverter-load` | 負荷が15%多い | `INV_DELAY` |
| `detect-ring-stage` | リングの1段だけ負荷が4倍 | `RING_FREQ` |
| `detect-corner-supply` | `slow`の電源を1.08 Vにし忘れる（1.2 Vのまま） | `INV_DELAY` |
| `detect-corner-temperature` | `fast`の温度を−40 ℃にし忘れる（25 ℃のまま） | `INV_DELAY` |
| `detect-yield-shift` | しきい値の平均が20 mV高い | `MC_YIELD` |
| `detect-yield-too-good` | しきい値の平均が20 mV低い（合格数が多すぎる） | `MC_YIELD` |
| `detect-no-convergence` | 収束しない設定 | `SPICE_CONVERGENCE` |
| `detect-endless-analysis` | 終わらない解析 | `SPICE_TIMEOUT` |
| `detect-no-crossing` | 入力が動かず、遅延を測れない | `SPICE_MEASURE` |
| `detect-not-finite` | 定義できない比を測る | `SPICE_NONFINITE` |
| `detect-bad-netlist` | 定義のないモデル名 | `SPICE_NETLIST` |

負例は、別のラベルで不合格になった場合も、合格した場合も、その実行を不合格にします。範囲の許容を±50%にゆるめると、4つの負例が検出されなくなり、実行が不合格になります。負例は、判定そのものがゆるんでいないことの確認も兼ねています。

## 確認範囲と残る制限

- モデルカードは自作のレベル1です。短チャネルの効果、実際の容量、ばらつきの相関はありません。数値を実際のプロセスに当てはめることはできません。
- インバーターとリングの期待値は、同じツールで測った記録です。ツールとモデルに共通する誤りは、粗い手計算（2.5倍までの幅）でしか見えません。RCだけが、ツールと無関係な式で判定されます。
- 範囲の±2%は、手元（macOS、Apple Silicon）の値に対するものです。Linuxでは実行していません。同じ固定版のngspiceでも、浮動小数点の最後の桁は違いうるので、実測の記録は6桁に丸めています。設定を変えたときの動き（0.6%）より大きな差がOSで出るとは考えていませんが、確かめていません。
- 解析は過渡解析だけです。直流の動作点、交流、雑音、`.step`や`.alter`による掃引は使っていません。条件ごとにネットリストを作り直します。
- 温度の依存は、ngspiceのレベル1のモデルが持つものです。温度の向きの入替りがどの電源で起きるかは、このモデルの値によります。
- モンテカルロの基準は20,000回の試行です。局所のばらつき（素子ごと）と全体のばらつき（チップごと）は分けていません。裾の確率（100万分の1など）を求める方法は扱いません。
- 終わらない解析の負例は、作業者のプロセスを外から止めます。ngspiceの中の時間上限は使っていません。
- ngspiceが返すメッセージの文面（「Timestep too small」「aborted」）に頼って、打切りを見分けています。版が変わって文面が変わっても、最後の時刻の確認が残ります。
- ngspiceの利用者向けの資料の節番号とは照合していません（未照合）。
