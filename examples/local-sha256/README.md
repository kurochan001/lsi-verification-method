# SHA-256のパディング・ブロック連鎖・反復演算を検証する

SHA-256を、0〜119バイトのメッセージを受け取る小さな回路として実装した例です。[RFC 6234の4.1・5.1・6.1・6.2節](https://www.rfc-editor.org/rfc/rfc6234.html#section-4.1)のアルゴリズムを参照し、期待する256ビットのダイジェストはPython標準ライブラリの`hashlib.sha256`で求めます。RFCの参照実装コードは取り込んでいません。

## 回路とインターフェース

```mermaid
flowchart LR
  accTitle: SHA-256の入力からダイジェストまで
  accDescr: 長さを受理し、宣言したバイト数を収集してパディングする。1または2ブロックを圧縮し、ダイジェストを受理されるまで保持する。
  C["長さを受理"] --> L["バイトを収集"] --> P["パディング"]
  C -- "空メッセージ" --> P
  P --> B["512ビットブロックを圧縮"]
  B -- "第2ブロックへ連鎖" --> B
  B --> D["ダイジェストを保持"]
```

`cmd_valid && cmd_ready`で7ビットの`length`を取り込み、その後`byte_valid && byte_ready`で正確にそのバイト数を受け取ります。バイトはメッセージの先頭から入力します。長さは要求受理時に固定し、処理中のコマンド入力は参照しません。入力に終端信号はなく、宣言した長さで終わります。

長さ0ではバイト入力を待たず、長さ120〜127では入力を受け取らず`error=1, digest=0`を返します。有効な要求では`error=0`です。結果は`digest_valid && digest_ready`まで保持し、結果を保持している間は次の要求を受け付けません。リセットは同期・Low有効で、入力途中・演算途中・結果保持中の処理を取り消します。

0〜55バイトは1ブロック、56〜119バイトは2ブロックになります。`0x80`、ゼロ、64ビットのビット長を付加し、長さとワードの並びはビッグエンディアンです。第2ブロックは第1ブロックの圧縮結果を初期値に使います。

`round1`は1サイクル1ラウンド、`round2`は2ラウンドです。どちらもブロック当たり64ラウンドを処理します。制御は入力収集・パディング・ブロック開始・反復演算に分かれ、メッセージスケジュールは組合せ回路で展開します。面積や動作周波数の最適化を目的とした構成ではありません。対応する`ROUNDS`は1と2です。

## 実行と判定

Python 3.10以上とIcarus Verilogを用い、リポジトリのルートで実行します。

```sh
python3 examples/local-sha256/run.py
python3 examples/local-sha256/run.py --profile nightly
python3 -m unittest discover -s examples/local-sha256/tests -v
```

固定シナリオは空メッセージ・`abc`・55／56・63／64／65・119バイト、長さ超過、入力の間欠供給、演算中の入力変更、結果の保持、途中リセットを含み、各構成で15目標に到達します。ランダムケースでは長さ・内容・入力間隔・結果の待ちを変えます。RTLを実行し、受理信号と結果が有効になる時刻を制御モデルと、ダイジェストを`hashlib`と比較します。

| 変異 | 誤り | 検出ラベル |
| --- | --- | --- |
| 1 | 先頭ラウンドの加算結果を1ずらす | `SHA_DIGEST` |
| 2 | ビット長の格納位置を逆のバイト順にする | `SHA_DIGEST` |
| 3 | 第2ブロックで初期ハッシュ値へ戻る | `SHA_DIGEST` |
| 4 | 結果が受理される前にダイジェストを変える | `SHA_DIGEST` |

セルフテスト7件には、空メッセージと`abc`の既知のダイジェスト、ブロック境界の前後、長さ超過からの復帰、入力・演算途中のリセットを含みます。通常ケースへの`--demo-bug 1..4`が失敗することも確認します。JUnitはsmoke 14件／nightly 18件です。証跡と合格条件は[共通手順](../local-common/README.md)を参照してください。

2026-10-31に両構成のsmoke／nightly、7セルフテスト、全構成・変異0〜4のVerilator lint、両構成のYosysによる読込み・`proc; opt; check -assert`を確認しました。

## 確認範囲

バイト境界のメッセージを最大2ブロックに限定します。任意長のストリーミング、ビット単位の入力、HMAC、鍵管理、セキュアブートへの統合、暗号モジュールの認証は扱いません。データパスの機能検証であり、電力・電磁放射等のサイドチャネル耐性を示すものではありません。[定時間比較のフォーマル例](../local-constant-time/README.md)とは検証する性質が異なります。
